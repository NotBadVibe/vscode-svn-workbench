## 1. 当前结论

v3 功能矩阵和本轮中文体验矩阵均已进入生产实现。当前 macOS ARM64 开发验收环境中，静态检查、覆盖率、Webview、真实 Extension Host、隔离 SVN、性能预算、制品审计以及 VSIX 安装/卸载/重装均通过；Windows、macOS、Linux 远端候选门禁也已全部通过。

中文术语一致性、右键直达仓库子任务、局部滚动可见性、小高度与缩放适配以及真实视口测试，已按 [`中文用户体验与页面滚动优化及验收方案.md`](./中文用户体验与页面滚动优化及验收方案.md) 落地：ZH-01～ZH-10、SCR-01～SCR-15 均有自动化证据，完整内容截图与真实滚动证据已明确分层。

状态定义：

- **完成**：具备正式实现、失败/恢复表达及自动化或真实 SVN 证据。
- **平台边界**：VS Code 公共 API 不允许 Explorer 菜单按任意资源异步查询 SVN 状态；精确菜单由原生 SCM 与 Svelte 文件树承担，Explorer 入口仍由 Host 复验。
- **外部环境验证**：真实企业 AI Provider、代理和私有 CA 需要目标环境凭据，不构成核心 SVN 功能依赖；对应失败、隐私和本地降级契约已自动化覆盖。

## 5. 每次交付必须执行的顺序

1. `npm ci`，然后执行 `npm audit --audit-level=high`。
2. `npm run verify`；任一子任务失败即停止，不允许用后续步骤覆盖失败。
3. 检查 `docs/releases/artifacts/<日期>/pages/` 中每个页面/关键状态截图，并抽查三主题尺寸截图。
4. `npm run package:vsix`，审计压缩包不得包含 `src/`、`tests/`、`docs/`、`coverage/`、source map 或本机环境文件。
5. `npm run validate:vsix-install`，确认干净 profile 的安装、列表、卸载和重装全部成功。
6. 写入版本报告中的文件数、大小、SHA256、机器环境和证据链接；源码、README 或依赖变化后必须重新打包并复验。
7. 推送后要求 Windows/macOS/Linux CI 矩阵全部为绿色；企业 Provider、代理或 CA 场景在目标环境补充连接性签字。

## 6. 发布判断规则

- 当前代码与本机候选制品的开发验收结论为“通过”。
- 三平台 CI 已通过；真实 VS Code 现场 UI、目标 `zh-CN` Windows 中文文件名提交、企业网络或真实模型连接仍属于外部环境证据，未执行时不得伪造通过链接；失败时必须撤回候选并从受影响层重新验收。
- VS Code Explorer 菜单的平台限制不得通过未公开 API 绕过；精确状态操作以原生 SCM 和 Svelte 文件树为准，Host 始终进行最终边界校验。
