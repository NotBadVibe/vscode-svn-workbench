## 3. 当前设计原则

- VS Code Explorer、编辑器和命令面板负责发起当前任务，命令直接进入对应 Svelte 功能模块，不强制经过工作台首页。
- 所有 SVN 可见业务界面统一使用 Svelte 5；状态、选择、Changelist、提交、Diff、冲突、设置、进度和 AI 交互使用同一套设计系统。
- VS Code 原生 API 只承担右键入口、Webview 宿主、文件打开、SecretStorage 等平台能力，不形成第二套重复业务流程。
- 操作范围由用户入口决定；筛选、模板和 AI 都只能缩小范围，不能扩大范围。
- AI 提供建议、证据和受控计划，不静默执行提交、更新、还原、删除、切换或合并。
- 核心 SVN 功能不依赖 AI；AI 未配置或失败时必须保留本地规则和手动流程。

## 4. 文档维护规则

1. 产品范围变化时，先更新 v3 的功能矩阵，再更新原型和开发映射。
2. 中文术语、页面滚动或真实视口验收变化时，同步更新 `中文用户体验与页面滚动优化及验收方案.md`。
3. 技术契约变化时，更新 `implementation-reference`，不要新增同主题的日期快照。
4. 测试结果由命令和 CI 产生；只有里程碑基线才写入文档，不再为每次 PASS 数新增文件。
5. 发布包大小、SHA256 和安装结果只在实际发布记录中生成，不写入长期技术基线。
6. 被替代的文档移动到 `archive` 并在归档索引中说明，不直接删除设计历史。
