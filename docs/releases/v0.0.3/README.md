# SVN Workbench v0.0.3 版本规划

> 状态：规划中。本文定义 `v0.0.3` 的目标范围、实现方案和验收门槛，不代表相关功能已经完成或通过测试。
>
> 基线版本：`v0.0.2`。

> 当前代码审查已记录 4 个待修复 P1 问题，详见[《代码审查问题》](./代码审查问题.md)。问题关闭前不得将本版本提升为候选或发布状态。

## 1. 版本主题

`v0.0.3` 聚焦提交文件选择体验，将当前硬编码的本地选择规则升级为可解释、可配置、可预览的正式能力，并在产品界面上明确区分“应用本地规则”和“获取 AI 建议”。

本版本需要解决以下问题：

- 未配置 AI 时，“AI 建议选择”实际执行本地规则，名称与结果来源不一致。
- 生成物目录、扩展名和 SVN 状态决策硬编码在源码中，用户和团队无法调整。
- 现有 `commitCandidateFilterPresets` 只控制列表显示，容易被误解为提交推荐规则。
- 设置页没有用于查看规则来源、命中结果和最终决策的专门页面。
- 仅 SVN 属性变化可能表现为 `status=normal`、`propStatus=modified`，需要独立判断，不能作为普通 `normal` 状态直接排除。

## 2. 版本目标

### 2.1 用户目标

- 设置页新增“提交选择规则”，与 AI 模型、团队提交规范和 SVN 安全并列。
- 用户可以配置常见 SVN 状态的默认选择策略。
- 用户可以通过 Glob 路径规则配置推荐、待确认和排除项。
- 页面可以使用当前仓库变更实时预览规则命中结果。
- 提交页始终提供“应用本地规则”，AI 已配置时另行提供“获取 AI 建议”。
- 所有结果明确显示来源，不把本地规则描述成模型分析。

### 2.2 工程目标

- 将本地规则从 `commitCandidateCollector.ts` 和 `generatedFilePolicy.ts` 的硬编码中抽离为可测试的领域模型。
- 用户、工作区和仓库配置使用同一套解析、校验、合并和评估逻辑。
- 所有提交候选入口使用同一份有效规则，避免提交页、SCM 和仓库动作产生不同分类。
- AI 只能在本地安全边界内补充建议，不能绕过阻止项、范围保护和明确排除规则。
- 没有新增配置时保持 `v0.0.2` 的现有选择结果，完成无损兼容。

## 3. 不在本版本范围内

- 不引入远程规则中心或云端同步服务。
- 不允许 AI 自动提交、自动加入 SVN 或自动修改 `svn:ignore`。
- 不把列表显示筛选预设改造成选择决策规则。
- 不以本次改造为由重写整个提交模块或设置模块。
- 不改变右键确定的仓库与操作范围。
- 不在本版本处理与该功能无关的历史归档、发布证据或全仓库格式化。

## 4. 产品与交互方案

### 4.1 设置页结构

设置页调整为四个标签：

1. AI 模型
2. 提交选择规则
3. 团队提交规范
4. SVN 安全

“提交选择规则”页面包含以下区域。

#### 配置作用域

- 用户默认：适用于所有仓库，使用 VS Code `contributes.configuration` 承载，复用原生设置 UI、schema 校验和 Settings Sync。
- 当前工作区：覆盖用户默认，同样使用 VS Code 配置承载。
- 当前仓库：写入 `.svn-workbench.json`，可以随仓库共享。
- 页面显示当前有效配置来源和各层覆盖关系。
- 设置页表单只编辑仓库级规则；用户和工作区级提供“在 VS Code 设置中编辑”入口并展示只读合并结果，不允许三个表单各自实现一套规则逻辑。

配置优先级为：

```text
不可修改的安全规则
  > 当前仓库规则
  > 当前工作区规则
  > 用户默认规则
  > 内置默认规则
```

#### SVN 状态策略

| SVN 状态                   | 内置默认决策 | 是否允许配置             |
| -------------------------- | ------------ | ------------------------ |
| `modified`                 | 推荐提交     | 是                       |
| `added`                    | 推荐提交     | 是                       |
| `deleted`                  | 推荐提交     | 是                       |
| `replaced`                 | 推荐提交     | 是                       |
| 仅 SVN 属性变更            | 推荐提交     | 是                       |
| `missing`                  | 需要确认     | 是                       |
| `unversioned`              | 需要确认     | 是                       |
| `unknown`                  | 需要确认     | 是                       |
| `normal`                   | 排除         | 是，但不能覆盖仅属性变化 |
| `ignored`                  | 强制排除     | 否                       |
| `external`                 | 强制排除     | 否                       |
| `conflicted`               | 阻止提交     | 否                       |
| `obstructed`、`incomplete` | 阻止提交     | 否                       |

设置项使用“推荐提交”“需要确认”“排除”三种中文决策，不直接暴露内部枚举值。

#### 路径规则

路径规则使用可排序表格编辑，每条规则包含：

- 是否启用。
- 稳定的规则 ID。
- Glob 路径表达式。
- 决策：推荐提交、需要确认、排除。
- 中文原因说明。
- 配置来源。

内置的 `node_modules`、`dist`、`build`、`target`、`.next`、`.nuxt`、`__pycache__`、`obj`、`bin/Debug`、`bin/Release`、`*.log`、`*.tmp` 和 `*.pyc` 等规则迁移为内置默认规则。

用户可以按稳定 ID 覆盖内置规则，也可以新增更具体的团队规则。自定义规则按页面顺序匹配，第一条命中规则生效。

被前面更宽规则永久遮蔽的规则在编辑和保存时给出警告（至少检测重复 pattern 和明显包含关系），帮助团队发现永不生效的规则；警告不阻止保存。

#### 实时预览

页面使用当前仓库的实际候选文件展示：

| 文件 | SVN 状态 | 命中规则 | 规则来源 | 最终决策 |
| ---- | -------- | -------- | -------- | -------- |

预览只进行本地计算，不调用 AI，也不修改当前提交篮。无工作副本或无候选文件时显示可恢复的空状态。

规则评估器为纯函数并随设置快照下发到 Webview，预览评估在 Webview 端本地执行（编辑输入做 debounce），不因为每次击键向 Host 请求完整快照；只有保存、恢复默认和重新采集候选文件需要与 Host 往返。

#### 页面操作

- 保存当前作用域。
- 恢复当前作用域默认值。
- 打开当前仓库 `.svn-workbench.json`。
- 重新采集候选文件并刷新预览。

保存规则不会自动覆盖用户当前已经勾选的提交篮。规则发生变化后，提交页提示用户主动点击“应用本地规则”。

### 4.2 提交页行为

当前单一“AI 建议选择”拆分为：

- “应用本地规则”：始终可用，使用当前有效规则重新计算推荐选择。
- “获取 AI 建议”：仅在提交文件选择场景配置了有效模型时可用；未配置时显示“配置 AI”入口。

提交页首次打开时仍使用本地规则建立默认选择。用户手动修改选择后，刷新页面不应无条件覆盖手动结果。

AI 调用失败时保留当前选择，显示失败原因和“应用本地规则”恢复动作；不再通过相同按钮静默替换成另一种来源的结果。

### 4.3 决策展示

每个候选文件至少展示：

- 最终决策。
- 决策原因。
- 命中规则及来源。
- 是否属于不可覆盖的安全结果。

摘要分别统计推荐、待确认、排除和阻止数量。状态不能只通过颜色表达。

## 5. 领域规则

### 5.1 评估顺序

```text
OperationScope 与仓库边界
  -> SVN 原始文本状态、属性状态和仓库归属
  -> 不可覆盖的安全规则
  -> 合并后的路径规则（按顺序第一条命中）
  -> 状态默认策略
  -> 本地最终决策与解释
  -> 可选 AI 建议
  -> 结构化结果与范围复验
  -> 用户最终确认
```

### 5.2 不可配置的安全规则

- `conflicted`、`obstructed`、`incomplete` 始终为阻止项。
- `external` 不得进入当前仓库提交。
- `ignored` 不得通过建议选择隐式加入 SVN。
- 范围外路径、虚构路径和不属于候选集合的路径始终拒绝。
- AI 不得把本地阻止项或强制排除项改为推荐。

### 5.3 路径规则合并

- 内置规则拥有稳定 ID。
- 用户、工作区和仓库可以用相同 ID 覆盖低优先级定义。
- 新增的高优先级自定义规则在内置规则之前评估。
- 禁用覆盖只影响同 ID 规则，不删除低层配置文件中的数据。
- 配置解析失败时保留上一次有效状态或内置默认规则，并展示具体错误；不得将损坏配置静默保存为空配置。
- 保存前检测遮蔽规则：被更宽前置规则覆盖而永不命中的规则给出警告，但不阻止保存。

### 5.4 评估输入与解释模型

- 评估器输入必须是 `(status, propStatus)` 二元组：仅属性变化（`status=normal`、`propStatus=modified`）独立于普通 `normal` 判断。`propStatus` 目前已在 SVN 状态解析层产出并透传到 Webview，本版本把它纳入决策输入；引用 `CommitCandidate` 的 AI 模块需同步兼容该模型。
- 设置预览表、提交页决策原因和 AI 请求中的“本地规则结论”共用同一个决策解释模型（最终决策、命中规则、规则来源、是否不可覆盖的安全结果）；中文文案统一收口到 `src/webview/i18n/terminology.ts`，不允许在各模块拼字符串。

### 5.5 AI 边界

- AI 请求继续只发送当前范围候选文件的相对路径、SVN 状态、文件类型和本地规则结论，不发送本地绝对路径。
- AI 可以在“推荐”和“需要确认”之间提出调整。
- AI 不能覆盖本地阻止、强制排除或用户明确配置的排除结果。
- AI 结果必须绑定仓库 UUID、范围哈希、候选状态哈希、生成时间和模型；关键状态变化后结果失效。

## 6. 配置格式

仓库级配置在 `.svn-workbench.json` 中新增 `commitSelection`：

```json
{
  "commitSelection": {
    "version": 1,
    "statusRules": {
      "modified": "recommended",
      "added": "recommended",
      "deleted": "recommended",
      "replaced": "recommended",
      "propertyModified": "recommended",
      "missing": "needsReview",
      "unversioned": "needsReview",
      "unknown": "needsReview",
      "normal": "excluded"
    },
    "pathRules": [
      {
        "id": "generated-dist",
        "enabled": true,
        "pattern": "**/dist/**",
        "decision": "excluded",
        "reason": "构建输出目录"
      }
    ]
  }
}
```

约束：

- `version` 用于后续配置迁移。
- `blocked` 不作为可写配置值。
- 未识别字段应保留，避免保存一个设置区域时破坏其他团队配置。
- 保存前校验规则 ID、Glob、决策值和重复项。
- `commitCandidateFilterPresets` 保持原含义，只负责列表显示筛选。
- Glob 方言固定为：相对仓库根、统一使用 `/` 分隔、支持 `**`；实现引入 `picomatch` 作为本版本唯一新增运行时依赖，规则数量和单条 pattern 长度设上限（建议分别不超过 200 条和 200 字符），防止病态 pattern 拖垮实时预览。
- 为 `.svn-workbench.json` 发布 JSON Schema（通过 `jsonValidation` contribution 和 `$schema` 提示生效），团队手工编辑时获得补全与校验。

## 7. 技术实现规划

### 7.1 新增领域模块

计划在 `src/commit/` 增加：

- `commitSelectionRules.ts`：配置类型、内置默认值、编辑输入和校验结果。
- `commitSelectionRuleResolver.ts`：用户、工作区、仓库配置读取与优先级合并。
- `commitSelectionRuleEvaluator.ts`：根据候选状态和路径计算纯本地决策及解释。

同时增加两个前置模块：

- 统一 `.svn-workbench.json` 读写层：收敛现有 `commitConvention.ts`、`commitCandidateFiltering.ts` 各自解析和写回同一文件的重复逻辑，再由它承载新增 `commitSelection` 键，保证单次解析、合并未知键和统一校验警告。
- 决策解释模型（可并入 `commitSelectionRules.ts`）：预览、提交页和 AI 请求共用的结构化解释类型。

规则解析和评估保持为可独立测试的纯领域逻辑，不继续扩大 `WorkbenchController.ts`。

### 7.2 调整现有模块

| 位置                                                                       | 计划改动                                                                             |
| -------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |

### 7.3 统一候选采集

当前候选采集被多个 Controller、SCM 和仓库动作调用。本版本必须建立统一入口，保证所有调用在同一仓库中解析出相同的有效规则。

不能只修改提交页面调用，否则 SCM 摘要、提交预览、Changelist 和实际执行前复验可能得到不同分类。

### 7.4 协议与状态

设置快照至少包含：

- 当前编辑作用域。
- 每层原始配置与有效合并结果。
- 状态策略。
- 有序路径规则。
- 校验错误和警告。
- 当前候选文件的规则预览。

保存、恢复和刷新必须有明确反馈。任何会改变候选状态的动作都要清除旧提交预览和旧 AI 结果，但不能静默重置用户已手动确认的提交篮。

实时预览所需的规则合并结果和候选清单随设置快照一次性下发；规则评估在 Webview 端本地执行并做编辑 debounce，协议不承担高频预览往返。新增 `settings/selection` 相关 action 时，注意 `workbenchProtocol.ts` 中字面量联合与运行时集合需双处同步，并有对应一致性测试（见第 9.2 节）。

## 8. 兼容与迁移

- 未配置 `commitSelection` 时，选择结果必须与 `v0.0.2` 保持一致。
- 现有 `.svn-workbench.json` 中的 `commitConvention`、`commitCandidateFilterPresets` 和未知字段必须保留。
- 不在读取旧配置时自动写文件；只有用户明确保存时才持久化。
- 内置规则调整需要版本化，并在界面中说明变化来源。
- 无效配置不得阻断手动 SVN 流程；页面显示警告并使用最后有效配置或内置默认规则。
- 配置保存后不立即改写当前勾选，避免用户正在准备的提交篮被意外覆盖。

## 9. 测试计划

### 9.1 单元测试

- v0.0.2 行为金样：以 fixture 快照固化现有 `collectCommitCandidates`/`classifyGeneratedFile` 的分类结果（含仅属性变化和各安全状态），作为阶段 1–2 的兼容红线；Extension Host 套件中现有相关断言保持不变作为补充。
- 默认状态映射与仅属性变化。
- 内置生成物路径和扩展名规则。
- Glob 校验、路径规范化、规则排序和第一条命中；方言边界（`/` 归一、`**` 语义）与数量、长度上限。
- 规则遮蔽检测：重复 pattern 和明显包含关系产生警告。
- 用户、工作区、仓库覆盖优先级。
- 稳定 ID 覆盖、禁用和未知字段保留。
- 无效 JSON、无效决策、重复 ID、非法 Glob 的降级。
- 安全状态不能被配置或 AI 覆盖。
- 无配置时与 `v0.0.2` 结果兼容。

### 9.2 组件与协议测试

- 设置页四个标签及深链接 `settings/selection`。
- 作用域切换、状态策略编辑、路径规则增删、排序和保存动作。
- 规则预览的命中结果、来源、空状态和错误状态。
- 提交页“应用本地规则”和“获取 AI 建议”的可用条件。
- 未配置 AI、AI 失败、AI 成功和结果过期状态。
- 协议动作白名单、快照结构和 Mock 行为同步。
- `workbenchProtocol.ts` 中 action 字面量联合与运行时集合双处定义的一致性测试，新增 `settings/selection` action 必须两处同步。

### 9.3 Webview E2E 与视觉验收

- 720×480、1024×600、1440×900 和 200% 缩放下设置表单、规则表和底部操作可达。
- 规则列表和预览列表使用明确的 `ScrollArea`，键盘可以到达最后一项。
- Light、Dark、High Contrast 下来源、警告、禁用和危险状态可辨识。
- 中文长路径、长原因、中文 IME 和错误恢复文案可用。
- 不通过覆盖 `overflow` 证明设置页面可用。

### 9.4 Extension Host 与真实 SVN

- 覆盖 modified、added、deleted、replaced、missing、unversioned、ignored、external、conflicted、obstructed、incomplete 和仅属性变化。
- 仓库配置保存后重新采集得到一致结果。
- 文件、目录、多选、嵌套工作副本和 external 范围不被扩大。
- 提交预览和执行前复验使用相同有效规则。
- 无效配置和 AI 不可用时核心提交预览仍可使用。

## 11. 版本验收标准

- 设置页存在可深链接的“提交选择规则”标签。
- 用户可以配置状态策略和有序路径规则，并预览当前仓库命中结果。
- 用户、工作区、仓库配置按约定优先级合并，页面能解释最终来源。
- 无配置时行为与 `v0.0.2` 兼容，且 v0.0.2 金样测试全量通过。
- `conflicted`、`obstructed`、`incomplete`、`external` 和范围外路径不能被配置或 AI 放行。
- 仅 SVN 属性变化不会作为普通 `normal` 状态被错误排除。
- 提交页明确区分“应用本地规则”和“获取 AI 建议”。

- 保存 `.svn-workbench.json` 时保留其他配置和未知字段。

- 配置保存校验包含重复与遮蔽规则警告；`.svn-workbench.json` 的 JSON Schema 生效。
- 实时预览在 Webview 端本地计算，编辑输入不产生高频 Host 往返。
- 设置页在小高度、200% 缩放、键盘和三种主题下可用。
- 所有新增行为具备对应自动化测试，且没有通过降低安全检查或批量更新视觉基线规避失败。
- `npm run docs:verify`、`npm run check`、相关测试和最终 `npm run verify` 通过。
- 候选 VSIX 在隔离工作副本和干净 VS Code profile 中完成验收后，才能把版本状态从 `draft` 提升为 `candidate` 或 `released`。

## 12. 风险与待决策

### 配置作用域复杂度

同时支持用户、工作区和仓库会增加合并与编辑复杂度。本版本决策：用户和工作区级使用 VS Code 原生配置承载，设置页表单只编辑仓库级并展示合并结果，以此削减三作用域表单风险；合并与解释逻辑仍必须在统一领域模型中只实现一次，再开放多个作用域。

### 规则覆盖语义

同 ID 覆盖、禁用继承和自定义排序必须有稳定定义，否则团队配置升级后可能改变结果。相关行为应在 schema、UI 帮助和单元测试中同时固定。

### 当前提交篮保护

规则保存或刷新不能静默丢失人工选择。需要明确区分“候选重新分类”“应用推荐选择”和“用户最终选择”三个状态。

### 大候选集性能

实时预览需要复用现有窗口化和本地计算能力，不能因每次输入都重新执行 SVN 命令或向 Host 发送高频完整快照。规则评估器保持无 I/O 纯函数并随快照下发，预览在 Webview 端本地执行且编辑输入做 debounce；仅保存、恢复和重新采集允许 Host 往返。

### glob 运行时依赖

项目此前没有运行时依赖。本版本已按阶段 1 评审结论引入 `picomatch` 作为首个运行时依赖，未启用限定方言的自实现匹配器备选方案；该依赖持续受高危依赖审计与 dependabot 兼容性守卫约束。

### 版本工具链一致性

仓库 `.nvmrc` 原声明 Node.js 22，与 `package.json`、README 和测试基线要求的 Node.js 26 不一致；该不一致已在阶段 0 以独立提交修正为 Node.js 26，验收结果以实际运行环境记录为准。
