# SVN Workbench v0.1.2：可编辑合并结果与可撤销取舍

> 文档身份：`planned-version-record`
>
> 状态：规划中（`draft/planned`）。依赖 [`v0.1.1`](../v0.1.1/) 的统一冲突视图通过退出门禁。
>
> 基线版本：[`v0.1.1`](../v0.1.1/)。
>
> 路线来源：[融合审查报告](../../archive/product-reviews/2026-08-23/以人为本易用性审查与优化报告.md)第 6.3～6.5、6.7～6.9 节。
>
> 优先级：P0。
>
> 用户可独立体验的主路径：在冲突块旁选择任一侧或两种保留顺序，立即在可编辑合并结果中手工微调；每次自动取舍与手工输入进入同一撤销/重做时间线，保存检查点后关闭或切换文件再返回，草稿仍可恢复。
>
> 不包含：自动执行验证命令、自动 Resolve、同步四窗格、批量 Resolve、持久化到项目文件之外的长期草稿。

## 1. 版本目标

`v0.1.1` 解决“看清并就地选择”，本版本解决“选择后继续人工编辑”。块级动作不能成为不可逆的魔法按钮；它们必须与键盘输入一样是普通、可撤销、可恢复的编辑。

成功标准：

- Pierre `Editor` 稳定附加到合并结果，只有结果侧可编辑，Mine/Theirs/BASE 只读。
- 提供“先我的后对方”“先对方后我的”，顺序与最终文本可预览、可撤销。
- “采用我的/对方/双方”、程序化 `applyEdits` 和手工输入进入同一 undo/redo 栈。
- 查找能力可用；替换仅在能够保持 IME、撤销和范围安全时启用，否则明确延期。
- 关闭、刷新、切换文件、切换项目时继续使用 Host 内存检查点和三选一守卫。
- 外部磁盘变化、revision/scope/hash 变化后旧编辑 token 和旧草稿采用动作失效。

### 3.1 V012-A · 合并文档模型

建立明确状态：

- `authoritativeContents`：Host 最近一次确认的工作副本内容。
- `draftContents`：当前编辑结果。
- `draftRevision`：每次编辑/动作单调递增。
- `baseContentHash`、`workingContentHash`、`scopeHash`、`workingCopyRevision`。
- `conflictRegions`：绑定内容 hash 的稳定 region，不跨文本变化盲用旧行号。
- `editorState`：selection、视口和当前冲突块，只作为界面状态，不参与 SVN 写入身份。

规则：

- Webview 不能自行宣布草稿已保存。
- Host 回执只接管匹配的 draft revision；旧回执不得覆盖后续输入。
- 程序化动作先解析 region，再生成最小 `TextEdit[]`；应用前复核预期旧文本。
- region 因前序编辑移动时重新映射或明确失效，不按旧行号写入其他内容。
- 所有文本操作保留 BOM/EOL/末尾换行语义。

### 3.2 V012-B · 可编辑结果

实现要求：

- 将 `Editor` 附加到合并结果实例；Mine/Theirs/BASE 和历史来源保持只读。
- 暴露 `getText`、`focusLine`、`applyRegionEdit`、`canUndo`、`canRedo`、`undo`、`redo`、`getState/setState`。
- 编辑器变更只更新草稿和脏状态，通过 debounce 写 Host 内存检查点，不直接写盘。
- 编辑态 Host 快照刷新保持实例；目标/容器/角色映射变化才重建。
- 附加/清理失败时保留文本并进入简化编辑器；不得同时留下两个可编辑实例。
- 文本 composition 期间 Enter/Escape 不触发保存、切换或冲突动作。

### 3.3 V012-C · 可撤销的取舍动作

必须提供：

- 采用我的修改；
- 采用对方修改；
- 先我的后对方；
- 先对方后我的；
- 恢复当前冲突块到打开时状态；
- 删除当前冲突块双方内容（放入“更多”，需清楚预览，不是默认动作）。

要求：

- 每个动作显示将插入/删除的行数和顺序。
- `both` 两种顺序由受控 `applyEdits` 实现，不假设 Pierre 内置反向顺序。
- 程序化动作进入 Editor undo 栈，撤销后 selection 恢复到可理解位置。
- region 已被手工改写时，不盲目再次采用；提示“当前块已手工修改”，允许先预览或恢复。
- 快速连续点击、重复消息和乱序回执幂等或 fail-closed。
- 动作完成后播报结果，不只闪色。

### 3.4 V012-D · 检查点与恢复

复用既有 Host 内存草稿：

- 自动检查点采用短 debounce，显式“保存检查点”立即执行；两者不写工作副本。
- 切换冲突文件、项目、刷新或关闭任务触发“保存检查点并继续 / 留在当前文件 / 放弃草稿”。
- 超时默认保存检查点并继续，保持既有不丢稿策略。
- 返回文件时先重采 SVN 状态；scope/hash/revision 仍匹配才恢复为可编辑，否则只读展示并要求用户复制/导出或重新建立。
- Host 容量上限和淘汰必须给出可预期反馈；不得无提示丢弃最新草稿。
- “复制草稿”“导出草稿”“放弃草稿”在 Editor 失败时仍可用。

### 3.5 V012-E · 查找、快捷键与状态

用户可见控制：

- `Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z` 或平台 redo；
- `Ctrl/Cmd+F` 查找，焦点关闭后返回编辑位置；
- `Ctrl/Cmd+S` 在本版本执行“保存检查点”，文案明确“不写入工作副本”；
- 与 Diff 一致的上/下冲突快捷键；
- 工具栏持续显示未保存/检查点已保存/保存失败、undo/redo 可用状态；
- `?` 或 Tooltip 显示真实快捷键，内容由单一绑定来源维护。

替换能力必须先验证 Pierre 当前公开 API、中文 IME 和 undo 等价性；任一不满足则只交付查找，并把替换延期写入版本结论。

### 3.6 V012-F · 测试矩阵

最低覆盖：

- 单元：两种 both 顺序、region 漂移、预期文本不匹配、BOM/EOL、恢复原块。
- Editor 适配：attach/cleanup、undo/redo、selection/state、程序化编辑进入历史。
- 组件：按钮禁用、行数预览、手工改写后拒绝、查找焦点、IME。
- Host 草稿：revision 乱序、容量、scope/revision/hash 变化、项目切换恢复。
- E2E：连续“动作→输入→undo→redo→检查点→关闭→重开”，`repeat-each≥15`。
- CSP/主题/小视口：无违规、无双编辑器、主状态可达。
- 性能：100 冲突块下输入 P95 候选目标 ≤50ms，块动作反馈 ≤100ms；未达标时不得进入保存闭环。

### 3.7 完成结论（v0.1.2 实测）

- 测试：单测+组件 1449 通过（133 文件）、E2E `conflict-v012.spec.ts` 5 用例、`repeat-each=15` 全 75 绿。
- **性能实测（100 冲突块，候选目标 50ms/100ms 未达）**：输入 P95≈70-90ms、块动作反馈 P95≈400-700ms；作为已知性能差距列入后续优化，不得表述为达标。
- **性能优化后复测（2026-08-30，增量编辑 + 索引 + 缓存，repeat-each=15）**：模型层 `applyMergeEdit` P95 从 1.97ms（全量）降至 0.05ms（增量，60×），链式 30 次全量从 9.14ms/次降至 0.13ms/次；端到端 `conflict-v012` 100 块输入 P95≈95-140ms（5 次取样：95/110/122/136/140）、块动作 P95≈550-818ms（取样 605/632/658/672/712）；候选目标仍未达成。主因：Pierre `applyEdits` 对 100 块（~11k 字符）全量 DOM 重渲染/重分词为物理下限，模型层已非瓶颈；工具栏预览已缓存、轮询降频，对端到端影响有限。
- **替换（replace）能力延期**：查找输入框无 IME 保护、面板英文硬编码、仅能 keymap 间接打开；查找（Ctrl/Cmd+F）已交付，替换延期至后续版本。
- 修复 bug：`mergeDocumentModel` `restore-original` 的 `manuallyModified` 引用比较未清除 + `onChange` 时序误标记。

## 5. 人工验收任务

1. 对同一块依次执行四种取舍并撤销，最终文本均正确。
2. 采用一侧后手工调整变量名，undo/redo 顺序符合操作时间线。
3. 保存检查点、关闭、重开，文本与当前块附近视口恢复。
4. 在输入中触发 Host 刷新，后续输入不被旧快照覆盖。
5. 编辑期间外部改文件，旧草稿不静默写回；复制/导出仍可用。
6. 中文 IME 候选期间按 Enter/Escape，不触发检查点、切换或动作。
7. 100 个冲突块下连续输入和动作满足候选延迟预算。
