> 文档身份：`released-version-record`

>

## 1. 版本结论

在扩展 AI 能力前，先纠正现有产品承诺：纯本地规则不能叫“AI 已审查”，固定步骤不能包装成智能 Agent，生成或降级结果不能直接覆盖用户已经填写的提交说明。

本版本目标是：**页面说清楚自己实际上做了什么，任何建议都不损害用户已有输入，模型不可用时人工流程仍完整可用。**

本版本已落地：

- 纯本地页面与结果名称收敛为“本地检查 / 影响与测试建议 / 本地检查流水线 / 变更集管理”，
  固定分组、正则与模板不再包装成智能分析；
- 结果来源统一文案（本地检查 / 模型建议 / 模型不可用，已保留本地结果），每条结果标记来源；
- 提交说明生成改为“生成建议草稿”：生成、失败、超时、取消、降级、过期均不覆盖用户草稿，
  采用必须显式（插入空白字段 / 替换草稿），替换前可比较差异与字符数并可撤销，
  范围或候选变化后建议只读；
- AI 设置只列出有真实调用链的场景（`conflictMerge` 不展示）；
- 终审修复：adopt replace 被拒后补发快照回滚界面草稿、设置页模型场景列表读屏标签收敛、
  冲突建议按钮未配置外部模型时如实显示“本地建议”、Mock 建议草稿状态跨 action 保真。

发布证据：`npm run verify` 端到端 exit 0（覆盖率 93.87%、webview 69/69、Extension Host
110 PASS 含真实 SVN），多模态视觉核验 6/6 关键页面截图通过。

> 非阻断观察项（未虚构为已验收）：§9.3 真人 UI 主路径（真实读屏、200% 目视、真实 SVN
> 完整流程）与 Linux/macOS/Windows 三平台 GitHub Actions 未在发布时点完成，按 v0.0.8
> 处理方式保留为发布事实的观察项，见 §12。

## 2. 当前需要修正的事实

- “AI 变更审查”实际只运行本地敏感信息、调试代码、生成物和缺少测试文件规则；
- “影响与测试”主要按目录、文件数量和路径正则生成固定建议；
- “受控 AI 任务代理”始终执行固定三步，用户目标不会改变计划；
- Commit 生成说明只收到路径、状态与差异统计，没有差异正文，却可能生成具体口吻的说明；
- 生成、模型失败或本地降级结果可能直接替换当前提交草稿；
- AI 设置暴露了没有真实模型调用链的场景。

这些问题损害信任，优先级高于新增模型能力。

## 3. 产品命名与入口修正

### 3.1 真实来源

统一来源文案：

- **本地检查**：未外发、可重复验证的规则；
- **模型建议**：基于明确回执中的数据生成；
- **用户确认**：用户补充或明确采用；
- **模型不可用，已保留本地结果**：不能简称 AI 分析。

每条结果标记来源；页面级总来源不能掩盖混合结果。

### 3.2 入口收敛的第一步

- “AI 变更审查”在尚无模型调用时改为“本地变更检查”；
- “影响与测试建议”说明其依据是路径与本地规则，避免表达成依赖关系分析；
- 隐藏或降级独立 Agent 一级入口；固定只读流水线不再要求逐步批准；
- Changelist 路径分组称为“按目录和文件类型分组”，不能称语义拆分；
- 冲突存在真实模型调用时保留“模型建议”，本地回退明确标记；
- AI 设置只列出真实存在的调用场景。

本版本可以保留旧模块以降低迁移风险，但所有用户可见名称必须与真实能力一致。完整 Review / Impact 合并在 v0.0.12。

## 4. 提交说明草稿保护

“生成提交说明”改为“生成建议草稿”，无论模型结果还是本地回退都不得直接替换用户输入。

流程：

1. 保留当前草稿、选择区和光标；
2. 在旁侧或 Dialog 展示建议；
3. 标明输入仅是文件信息和差异统计，不能证明具体行为；
4. 展示与当前草稿的差异；
5. 提供“插入空白字段”“替换草稿”“复制建议”“放弃”；
6. 替换前写明字符数并允许撤销；
7. 失败、超时、取消、降级或过期时原草稿不变。

用户填写的工单号、业务原因和风险优先于模型建议，不能静默删除、改写或编造。没有足够输入时只生成结构化占位草稿，并明确标记“基于文件信息”。

## 5. 页面用途与状态

每个相关页面首屏说明：

- 这个页面能帮助完成什么任务；
- 当前项目与范围；
- 运行本地规则还是外部模型；
- 使用了哪些数据类型；
- 得到结果后下一步是什么；
- 不会修改文件或直接执行 SVN 写操作。

状态必须覆盖初始、运行、空、部分、未配置、离线、结构错误、取消和过期。错误说明“发生了什么 → 可能原因 → 可以怎么做”，不直接展示 Provider 原始异常。

“没有发现”只能表示规则未命中，不能宣称代码没有问题。过期状态说明哪些文件、范围或 revision 变化；旧结果只读，用户草稿继续保留。

## 6. 设置页真实性

设置首屏按任务显示：

- 文件选择、冲突建议、提交说明、拆分和团队规则的真实可用性；
- 当前使用模型或仅本地模式；
- 哪些数据可能外发；
- 最近一次连接状态；
- 历史摘要是否允许使用。

Provider、Base URL、默认模型和逐场景模型进入“连接与高级设置”。删除没有调用链的伪场景，或在完成实现前保持隐藏。

## 7. 安全与恢复

- 来源修正不得降低现有本地阻止规则；
- 模型结果仍不能扩大 `operationScope`、修改工作副本或执行写操作；
- Commit、Changelist 与 Conflict 继续经过预览、确认 token 和 Host 复验；
- 切换项目或范围时复用 v0.0.7 的草稿隔离与失效机制；
- AI 未配置或失败时，Changes、Commit、Changelist、Conflict 的人工流程完整可用。

## 8. 实施顺序

1. 建立命令、页面、标签、模型场景与真实调用链清单；
2. 修正纯本地页面和结果名称；
3. 隐藏 / 降级固定 Agent 入口；
4. 实现建议草稿对比、采用、撤销和不覆盖回归保护（归复杂开发会话）；
5. 清理 AI 设置中的伪场景；
6. 完善初始、空、失败、部分、取消和过期状态（页面用途与状态文案）；
7. 运行候选验证并同步 `docs/current/`。

## 8.3 已落地状态（复杂开发会话）

§4 提交说明草稿保护已实现（数据流、协议与 Host 校验、过期隔离）：

- `commit/generate-message` 只生成建议草稿（`CommitSnapshot.messageSuggestion`），
  不覆盖用户已填草稿；失败、超时、取消、降级、过期均不覆盖；
- 建议区旁侧展示来源/模型/“仅文件信息”声明、与当前草稿的行级差异；
  提供“插入空白字段 / 替换草稿 / 复制建议 / 放弃”，替换前写明字符数并二次确认，替换后可撤销；
- 范围/候选变化使建议 stale（只读），采用前 Host 重新校验候选；项目切换守卫识别未处理建议草稿；
- 协议新增 `CommitMessageSuggestion` 与 `commit/adopt-suggestion`/`commit/undo-suggestion-replace`/`commit/discard-suggestion`；
  同步检查 Host、Webview、Mock、消息守卫与相关测试。
- 若来源标识需要新增协议字段（当前建议区直接复用 `source` 字段，未新增），
  由任务管理协调复杂开发实现协议后再接入。

## 9. 候选验收

### 9.1 真实性

- `AI09-TRUTH-01`：每个“AI / 模型”标签都有真实模型调用；
- `AI09-TRUTH-02`：纯本地规则统一标为本地检查；

- `AI09-TRUTH-05`：每条结果来源可见且读屏可辨识。

### 9.2 草稿与恢复

- `AI09-DRAFT-01`：生成、失败、超时、取消、降级、过期均不直接覆盖草稿；

- `AI09-RECOVER-01`：模型不可用时本地检查和人工提交流程可用；
- `AI09-RECOVER-02`：切换项目 / scope 时建议和草稿正确隔离、失效或恢复。
