## 1. 版本目标

这是 `v0.1.x` 路线的证据驱动收口版本。它不预设所有高级能力都必须打开，而是以测量决定：

- 普通大 Diff 是否切换 `VirtualizedFileDiff`；
- 语法高亮是否使用 `@pierre/diffs/worker`；
- 冲突 `UnresolvedFile` 在多大规模下仍可用；
- 是否启用 Mine vs BASE、Theirs vs BASE 同步只读窗格；
- overview/locator 是否值得其 DOM、滚动和键盘复杂度；
- 何时提示“使用简化视图/在 TortoiseMerge 中打开”。

成功标准：

- 首个可见内容不等待完整语法高亮。
- 输入、块动作、导航、切换文件满足候选延迟预算。
- 连续切换文件后实例/observer/Worker/内存无持续增长。
- 大文件降级阈值可解释、可测试、可配置但不过度暴露。
- Tortoise 式角色、双顺序、空白、locator 和外部工具融入 VS Code 交互，不照搬 Windows 外观。
- 高级布局若未通过预算，版本仍以“可靠大文件处理与明确降级”作为可独立交付主路径。

## 3. 性能预算

以下为初始候选门槛，先测 baseline 后允许基于证据调整；调整必须说明原因，不可只为测试通过而放宽。

| 场景      | 数据档位                          | 候选门槛                                           |
| --------- | --------------------------------- | -------------------------------------------------- |
| 普通 Diff | 100/1000/5000/10000 行            | 5000 行首个可见内容 P95 ≤800ms；首屏不等待完整高亮 |
| 冲突      | 10/100/500 块，1000/5000/10000 行 | 100 块首个可操作冲突 P95 ≤1000ms                   |
| 块动作    | 单次采用/双顺序/恢复              | 视觉反馈 P95 ≤100ms                                |
| 编辑      | 连续输入、粘贴 1000 行、undo/redo | 普通输入处理 P95 ≤50ms；无 Host 回执覆盖           |
| 导航      | 上/下块、locator 跳转             | P95 ≤100ms，目标进入正确滚动区                     |
| 高亮      | TS/JSON/XML/text/超长行           | 输入期间无 >50ms 高亮长任务                        |
| 生命周期  | 连续切换 100 个文件/主题          | 无持续内存增长，实例与 observer 回收               |
| 小视口    | 720×480、200%                     | 高级面板可折叠，主编辑/降级出口可达                |

### 4.1 V018-A · 基准与追踪

- 基准固定 seed、文件内容、变更比例、冲突块、语言、EOL、长行和运行次数。
- 采集首个 plain render、highlight ready、first interactive、输入、动作、导航、内存和 main-thread long task。
- 每组至少 warm/cold 分开，输出 P50/P95，不只平均值。
- 记录设备、OS、VS Code、Node、缩放、主题和扩展调试/生产构建。
- 普通 evidence 写 `.validation/evidence/v0.1.8/<run>`。
- 自动门禁只使用稳定指标；易抖指标先作为趋势观察，不直接形成 flaky 阻断。
- 性能失败不得通过缩小 fixture、跳过平台或关闭断言隐藏。

### 4.2 V018-B · 普通 Diff

评估 `VirtualizedFileDiff` 和 Worker：

- 先验证与当前 `FileDiff` 输入、Editor、split/unified、上下文折叠、CSP、主题和生命周期兼容性。
- 只在测得阈值以上切换，避免小文件承担不必要复杂度。
- Worker 只处理可安全离线的高亮/解析；消息不得携带范围外文件或凭据。
- 首屏先纯文本/基础 token，再渐进应用高亮；高亮失败不阻塞阅读/编辑。
- 编辑器 selection、undo 和滚动锚点在窗口化重新渲染时保持。
- 如果虚拟化与编辑模式不兼容，普通编辑文件使用分级阈值或简化高亮，不强行启用。
- 将阈值和原因集中在性能策略模块，不散落魔法数字。

### 4.3 V018-C · 冲突大文件

由于当前包没有 `VirtualizedUnresolvedFile`：

- 先实测 `UnresolvedFile` 的 10/100/500 块行为。
- 可使用 `maxContextLines`、按需来源窗格、延后高亮和单一 Editor 降低成本。
- 不把冲突文件切成会破坏 marker/region/hash 的独立伪文件。
- 低于阈值：完整统一视图。
- 接近阈值：关闭非必要高亮、减少上下文、隐藏未激活只读来源。
- 超过阈值：保留草稿，提供简化编辑器或外部合并工具。
- 任一降级显示原因、当前模式、可恢复动作；不静默改变内容。
- 大文件保存仍受 5 MB 与安全写入当前基线限制；若要改变上限必须另做安全评审，本版本默认不改。

### 4.4 V018-D · 空白与 locator

#### 空白

- 提供“显示空白字符”和经验证的比较呈现选项。
- “忽略空白”只改变比较时明确标注，不静默删除/重写最终文本。
- 切换后当前冲突 identity、草稿和 undo 不丢失；做不到则只允许只读视图切换。

#### Overview/locator

- 显示变更/冲突分布、当前视口和未处理块。
- 状态有图形+文字/aria，不只红绿。
- 点击/键盘选择滚动到正确块；滚动不带走固定文件/范围状态。
- 100/500 块下仍满足导航和滚动预算。
- 720×480/200% 可折叠，不占用主编辑区不可恢复空间。

### 4.5 V018-E · 可选同步比较窗格

go 条件全部满足才启用：

- Mine vs BASE、Theirs vs BASE 两个只读 `FileDiff` 与一个可编辑结果的角色清楚。
- 使用公开 `ScrollSyncManager`/`CodeViewCoordinator` 或可维护适配，不调用私有 API。
- 同步滚动可关闭，不制造滚动震荡。
- 只挂载当前需要的只读实例；文件切换完整清理。
- 1024px 以上才考虑多栏；小屏自动回到 Tabs/单视口。
- 键盘焦点和读屏顺序可理解。
- 性能和内存仍在预算内。

任一条件不满足，no-go 并保留 `v0.1.3` 单视口工作区，不视为版本失败。

### 4.6 V018-F · 外部合并工具

提供通用“在配置的外部合并工具中打开”，Windows 可识别 TortoiseMerge，但不能硬编码唯一产品：

- 命令路径来自用户显式配置或安全探测，参数使用数组。
- 打开前显示文件角色、将传递的路径和“外部工具可能修改工作副本”。
- 不传递凭据、token、范围外文件或 AI 上下文。
- 外部工具退出/文件变化后重新采集状态，旧 token/草稿动作失效。
- 工作副本被修改时提示重新打开/比较，不自动 Resolve。
- 未安装或配置无效时给出选择可执行文件/打开设置/继续内置编辑。
- macOS/Linux 保持通用外部工具配置，不显示 Windows 专属承诺。

### 4.7 V018-G · 收口验证

- 性能自动化和中低配实测。
- 连续 100 文件切换、主题切换、编辑/保存、降级/恢复。
- Worker 创建/终止、CSP、异常和主线程回退。
- 大冲突真实 SVN fixture 和外部修改。
- locator/同步窗格的键盘、读屏语义、小视口。
- 外部工具参数与路径白名单、失败、退出后刷新。
- 全 `npm run verify`，必要时构建候选 VSIX；没有用户明确发布要求不得运行 `evidence:release`。
- 回顾 `v0.1.0～v0.1.8` 所有验收指标，形成路线收口摘要；该摘要属于当前版本 README 的实施状态更新，不新增临时 PASS 文档。

### 9.1 本版本交付摘要（按 §7 格式）

1. **性能矩阵 P50/P95 与设备**：设备均为 Apple M4 / 24 GB / Node 26.7.0（darwin arm64）。

   - V018-A 模型解析层 baseline（seed `20260823`、rounds 11；runs `2026-09-04T12-11-31-769Z-d0106d68` / `2026-09-04T12-11-44-156Z-b0e468d6` 的 `v018-baseline.json`，warm P50/P95）：`diff-ts-5000-mid` ≈0.52–0.55/0.75–0.89ms；`diff-ts-10000-mid` ≈1.14/2.42–2.43ms；`diff-json-5000-mid` ≈0.62–0.63/0.76–1.17ms。结论：模型解析层非瓶颈（毫秒级），瓶颈在浏览器首次渲染。
   - V018-B 浏览器首屏（`FileDiff` 现状只读，生产构建 preview，runs=5；run `v018b-2026-09-04T12-21-14-browser/v018-browser.json`）：`ts-1000-mid` 首可见 P50 520.83/P95 529.81ms；`ts-5000-mid` 首可见 P50 2055.97/P95 2060.43ms（候选预算 ≤800ms，未达标）、高亮就绪 P50 313/P95 314.49ms、GC 后堆 50.4MB；`ts-10000-mid` 首可见 P50 4727.72/P95 4754.22ms、堆 86.4MB；长行+CRLF 档首可见 P50 4416.8/P95 4451.01ms。与 [`v0.1.0`](../v0.1.0/) §9（1923/4496ms）同量级、无回归。
   - V018-B 虚拟化 spike（同 run 下 `v018-spike-dom.json`，`ts-5000-mid`）：`FileDiff` Shadow 节点 117373/样式 token 92103，首可见 1769.7ms；虚拟化窗口化后节点 3366/token 2560、滚动 22.5ms（优于 319.7ms），但首可见 2857.4ms 明显倒退（vite-dev 相对对比）。首屏矛盾未解决是 no-go 的直接证据。
   - V018-C 冲突三档（渲染器恒为 `UnresolvedFile`；run `v018c-conflict-browser/v018c-conflict.json`；预算：100 块首个可操作 ≤1000ms、块动作 ≤100ms、输入 ≤50ms）：10 块首个可操作 P50 5/P95 455ms、块动作 P50 257/P95 259ms（超预算）、输入 P50 8/P95 13ms ✓；120 块首个可操作 P50/P95 287ms ✓、输入 P50 8/P95 14ms ✓；500 块首可见 P50 2941/P95 2971ms、块动作 P50 2970/P95 3007ms、输入 P50 8/P95 34ms ✓（输入全程达标，块动作超预算即进简化档）。

2. **每项 go/no-go 及理由**（实测结论，证据见第 1 项各 run 与对应单测）：

   | 项                               | 结论                 | 理由                                                                                                                                                                                                                                                                                        |
   | -------------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | `VirtualizedFileDiff`            | no-go                | spike-dom 实测：虚拟化首可见 2857.4ms，反而倒退于 `FileDiff` 的 1769.7ms——只减滚动/DOM 成本，不解决首屏矛盾；小文件不得承担窗口化复杂度（commit `43795fc`）                                                                                                                                 |
   | Worker（`@pierre/diffs/worker`） | no-go                | 同样不解决首屏矛盾（高亮就绪 314ms vs 首可见 2060ms，瓶颈在首次渲染）；且 `WorkerPoolManager` 未从包根导出（[`v0.1.0`](../v0.1.0/) §8），生产计划不得依赖，CSP 保持不动（commit `43795fc`）                                                                                                 |
   | 冲突分级降级                     | go                   | 120 块首个可操作 287ms ≤1000ms 完整视图可用；500 块块动作 ~3000ms 即进简化档，但输入 P95 34ms 仍达标、草稿保留。`VirtualizedUnresolvedFile` 在 1.3.4 不存在，渲染器恒为 `UnresolvedFile`，不强行虚拟化（commit `b92026c`）                                                                  |
   | 空白选项                         | go                   | “显示空白”与经验证的比较呈现只改变比较标注，不静默改写最终文本；切换不得丢失 identity/草稿/undo，否则仅允许只读视图切换（commit `e826c54`，含回归修复）                                                                                                                                     |
   | 门控 locator                     | go（≤100 块）        | 门控阈值 `V018D_OVERVIEW_BLOCK_THRESHOLD=100`（`tests/unit/diffOverviewGate.test.ts`：100 块边界默认展开，101 块默认折叠+中文原因）；超预算即折叠，不挤占主编辑区（commit `e826c54`）                                                                                                       |
   | 同步只读窗格                     | no-go                | §4.5 七条件逐条评估：条件 2 不满足（`ScrollSyncManager` 公开面仅同实例横向同步，跨窗格纵向须触 protected 节点=私有 API）；条件 7 不满足（单只读 `FileDiff` 5000 行首屏已超预算 2.6x，三实例远超）。`decideV018ESyncPanes` 恒关闭，保留 `v0.1.3` 单视口 Tabs，不视为失败（commit `6f2669e`） |
