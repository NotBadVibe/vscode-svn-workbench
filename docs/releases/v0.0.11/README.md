## 1. 版本结论

当前 Commit 模型只收到文件元数据和差异统计，无法可靠说明具体行为。v0.0.11 选择一个边界清晰、用户价值高、可独立验收的 AI 场景：**用户明确同意发送受限差异后，生成每条结论可追溯到证据的提交说明建议，且绝不直接覆盖原草稿。**

如果差异不足、被截断或只有二进制内容，产品必须直说“无法判断具体改动”，不能生成貌似完整的说明。

## 2. 两种输入模式

### 2.1 仅文件信息

发送或使用：项目内路径、状态、文件类型、模块分组、增删行和差异块数量。

允许输出：范围、状态与结构归类，以及“基于文件信息的占位草稿”。

禁止表达：具体业务行为、接口语义或“原来 / 现在”的确定性变化。

### 2.2 受限差异内容

在用户确认后，按当前 `operationScope` 采集、脱敏和裁剪差异片段，才允许生成具体改动说明。必须显示覆盖率、截断、二进制、读取失败和未分析项。

模型不能看到本地绝对路径、范围外文件、API Key、SVN 凭据或未授权历史。

## 3. 动作级外发回执

每次模型调用前展示：

- 任务：提交说明；
- 模型服务商、接口地址主机和模型；
- 数据类型：路径、状态、差异片段、用户草稿、团队规则、历史摘要；
- 文件数、字符总预算、单文件预算和预计排除数；
- 是否包含历史及条数；
- 明确不会发送的数据；
- 无法由插件证明的服务商保留策略标为“由模型服务商策略决定”。

用户可展开查看包含 / 排除文件，选择“开始模型生成”或“继续仅文件信息”。数据范围扩大、启用历史或更换任务时重新确认；取消后说明是否已经完成外发。

## 4. 差异采集与证据绑定

- Host 按 v0.0.7 的 project identity、working copy、repository identity 和 scope 采集；
- 新增、删除、重命名、属性变化、二进制和截断有明确表示；
- 发送 `projectRelativePath`，内部以不透明 `candidateId`、仓库内路径和逐文件差异 hash 绑定；
- 本地敏感信息规则先于模型调用运行；
- 模型引用必须落在回执允许的文件与差异块集合；
- 虚构、范围外、移动、过期或无法定位的引用丢弃并计入 coverage；
- 模型返回路径不能拼接到工作副本根执行任何文件写入。

结果至少绑定 repository UUID、working-copy identity、project ID、scope hash、候选 hash、逐文件差异 hash、工作副本 revision、模型、生成时间和回执版本。

## 5. 建议草稿结构与交互

可采用建议至少包含：

- 一句说明修改对象与结果的具体标题；
- 1～4 条行为、接口、配置或文档变化；
- 必要影响、兼容性或迁移说明；
- 每条具体陈述至少关联一个 Host 校验过的证据；
- 无法证明的内容标记为推断或待确认；
- 团队规则要求的真实工单号留给用户填写，不得编造。

交互复用 v0.0.9：

- 原草稿和光标始终保留；
- 建议与原文差异可查看；
- 支持插入、替换、复制、放弃和撤销；
- 模型失败、超时、取消、结构错误、部分完成或过期不改变原草稿；
- 用户确认过的事实可进入建议，但工作副本变化后需复核。

“优化相关逻辑”“整理当前范围”“涉及 3 个文件”只能作为降级提示，不能作为高质量完成结果。

## 6. 覆盖率、部分结果与过期

页面显示：

- 总候选、已分析、未分析、截断、二进制、读取失败和预算外数量；
- 每条建议的来源、证据、限制与置信理由；
- 哪些内容只是元数据推断；
- 哪些用户确认仍有效。

部分完成允许只重试失败项。过期时说明新增、删除、内容改变或 revision 变化；旧结果只读，不能继续采用到提交草稿。重新生成保留原草稿及仍有效的用户输入。

## 7. 本地降级

未配置、离线、超时或结构错误时：

- 保留 v0.0.9 的本地检查和文件信息占位建议；
- 不把本地结果标成模型分析；
- 不覆盖用户草稿；
- 用户仍可人工编辑并进入 Commit 预览；
- 错误说明恢复动作，不暴露凭据或完整 Prompt。

## 8. 协议与实现边界

建议建立可供 v0.0.12 复用的基础类型：

```ts
interface AnalysisReceipt {
  task: "commit-draft";
  projectId: string;
  model: string;
  dataTypes: string[];
  files: number;
  totalBudget: number;
  perFileBudget: number;
  historyIncluded: boolean;
}

interface EvidenceReference {
  candidateId: string;
  hunkId?: string;
  projectRelativePath: string;
}
```

具体字段可调整，但必须保证：Webview 不持有可写绝对路径；每条建议来源与证据独立；Host 校验引用和时效；差异采集、脱敏、预算与校验进入可单测领域服务，不继续扩大 Controller。

## 9. 实施顺序

1. 定义 action-bound receipt、coverage、candidate / hunk identity；
2. 实现受限差异采集、敏感信息扫描、预算和脱敏；
3. 扩展提交说明请求与严格结构校验；
4. 实现证据打开、范围拒绝和过期绑定；
5. 接入 v0.0.9 的建议草稿对比与恢复；
6. 完成部分、取消、离线和结构错误状态；
7. 运行安全、组件、E2E、真实 SVN 和候选验证，并同步 `docs/current/`。

## 10. 候选验收

### 10.1 隐私与安全

- `AI11-PRIVACY-01`：外发前显示任务、模型、数据类型、范围、预算、历史和排除项；
- `AI11-PRIVACY-02`：范围扩大或历史启用时重新确认，取消说明是否已外发；
- `AI11-PRIVACY-03`：凭据、本地绝对路径、范围外内容和未授权历史不进入请求、日志、快照或夹具；
- `AI11-SAFE-01`：模型结果不能扩大 scope、修改文件或执行 SVN 写操作；
- `AI11-SAFE-02`：证据引用经过候选、路径、hunk、hash 与时效校验。

### 10.2 内容与证据

- `AI11-DRAFT-01`：受限差异模式生成至少一条“对象 + 变化 + 结果”的具体说明；
- `AI11-DRAFT-02`：每条确定性陈述至少关联一个可打开的 Host 证据；
- `AI11-DRAFT-03`：仅文件信息模式不声称理解具体行为；
- `AI11-DRAFT-04`：证据不足时显示未知项，不编造事实或工单号；
- `AI11-DRAFT-05`：原草稿始终保留，可比较、部分采用、替换、复制和撤销。

### 10.3 状态与可访问性

- `AI11-COVER-01`：截断、二进制、读取失败和预算外集合对用户可见；
- `AI11-RECOVER-01`：失败、超时、取消、结构错误、降级和过期不损害输入；
- `AI11-RECOVER-02`：部分完成可只重试失败项；
- `AI11-A11Y-01`：键盘、读屏、IME、200% 和 High Contrast 可完成回执、证据核对与草稿采用。

人工主路径覆盖仅文件信息、受限差异、范围扩大、敏感内容、截断、二进制、虚构路径、hunk 过期、已有中文草稿、部分采用、撤销、模型离线和项目切换。

## 11. 明确不做

- 不默认发送整个项目、仓库或完整历史；
- 不把回执确认泛化为永久授权；
- 不让模型引用控制可写路径；
- 不自动采用建议、选择文件或执行提交；
- 不在本版本合并 Review、Impact 或 Agent；
- 不修改 `package.json` 版本，不生成发布 evidence。
