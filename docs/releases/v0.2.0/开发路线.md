## 1. 依据与确定性

上一轮检查了 main 分支及 v0.1.7..HEAD（94 个文件，约 +9504/-107），阅读当前文档、代码和测试记录，在 Node.js 26.7.0 / npm 12.0.2 下构建生产 Webview，并通过浏览器检查 1280×800、720×480 与无 AI 样例。生产 Webview 使用 Mock 数据，不能替代 VS Code Host、真实 SVN 写操作、真人访谈、真实读屏或真实 200% 缩放验收。当前截图和布局测量是观察依据，未作为发布 accepted evidence；本计划不把临时截图路径作为唯一长期证据。

关键观察包括提交 textarea 约 156×39px、Changes 列错位，以及 720×480 下 Changes/History 列表起点约 y=699/655；两列表可以滚动到达，不得夸大成永久不可用。500 块连续输入失焦来自既有生命周期测试及 current 记录；大文件毫秒数据来自 v0.1.8 历史实测，需要在实施后的提交重新测量。

- **已观察 / 源码已确认**：修复任务；开发前仍需最小复现，并与真实 Host 交叉核验。
- **待复现风险**：R06 历史窗口化、R16 Shift 锚点、R50 语义拆分输入；R10 冲突定位与 R37 真实错误组合也要补复现。没有复现结果时不得声称已修复；若证据不成立，保留反证和对应保护，不无依据重构。
- **能力完善 / 体验建议**：明确是将现有功能变得更易用，不以缺陷措辞误报已实现功能不存在。
- **P3 候选**：R58 本地补全、R59 暂不提交。所在版本保证完成试验与决策，只有需求/收益/安全门禁成立才实现；可明确 no-go。
- **优先级**：P0 为内容输入可靠性；P1 为下一轮重点的正确性/常用任务问题；P2 为效率与完整流程；P3 为收益待验证候选。编号代表原问题，不代表优先级或执行顺序。

## 4. 必须保留的已有能力与边界

- 已有全选、三态表头、自然排序、Shift 连选、完整路径详情/复制、隐藏选择提示、5000 项窗口化；修接线与一致性，不重新声称要从零新增。
- 已有 Changes→Diff→返回恢复选择/滚动、Changes→Commit 交接、独立 Update 与冲突直达；扩展连续队列时沿用。
- 已有页内 Diff 编辑、原生编辑器出口、块导航、冲突 undo/redo/查找、两种保留双方顺序、保存检查点、核验与 Resolve；不能因为此次发现退化就描述为完全没有。
- 已有一次意向单确认、精确清单、过期复验、Relocate 专项复述；不加回全局双重批准，不拿体验优化降低校验。
- 已有本地规则、AI 回退、草稿不覆盖、受限差异回执、证据检查和外部合并工具；AI 只能建议。
- 历史批量 Resolve、Git staging、历史重写、自动提交、自动执行项目测试等不是本路线默认目标；不新增平行 Review/Impact/Agent 一级页面。
- 虚拟化/Worker/同步多窗格既有 no-go 要作为试验输入；未经新的能力与收益证据不强制启用或扩大 CSP。
- Shelf 是本地 Patch 形式的搁置，不能宣传成 SVN 标准 Shelf；正文草稿跨重启保存属于显式设计范围，默认不把原本只在内存的数据写盘。
