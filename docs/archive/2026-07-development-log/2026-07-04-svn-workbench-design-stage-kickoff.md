## 1. 阶段切换说明

项目研发周期统一为：

```text
调研 -> 规划 -> 设计 -> 技术验证 -> 开发 -> 测试 -> 验收 -> 交付 -> 运营迭代
```

当前正式进入：

```text
设计阶段
```

规划阶段已经确定：

- 产品定位：面向中国团队日常使用的 VS Code SVN 管理器。
- 核心差异：右键范围提交、提交页精细筛选、AI-first、中文友好、TortoiseSVN 习惯迁移。
- MVP 边界：稳定 SVN 基础能力 + 提交闭环 + 生成物排除 + 基础 AI。
- 技术可行性：可实现，但 AI 和内置三方合并器需要分阶段。

设计阶段要解决：

- 每个入口长什么样。
- 每个页面有哪些区域。
- 每个按钮做什么。
- 每个状态如何展示。
- 用户如何从一个流程自然进入下一个流程。
- 哪些页面进入 MVP，哪些延后。

## 2. 设计阶段目标

### 2.1 总目标

把规划文档中的功能转成可开发的页面、组件、状态和交互规则。

### 2.2 具体目标

- 形成完整页面地图。
- 确定 Activity Bar、SCM、Explorer 右键、状态栏、命令面板的入口关系。
- 确定 MVP 页面线框。
- 确定 AI 交互方式。
- 确定提交页详细布局。
- 确定冲突处理的第一版交互。
- 确定模型设置页和隐私确认弹窗。
- 确定设计验收标准。

## 3. 设计原则

### 3.1 VS Code 原生优先

优先使用：

- SCM Provider。
- Tree View。
- QuickPick。
- InputBox。
- Status Bar。
- VS Code diff editor。
- Output Channel。

仅在复杂页面使用 Webview：

- 提交页。
- AI 筛选结果。
- AI 模型设置。
- 冲突决策卡片。
- 认证管理。

### 3.2 高风险操作显式确认

以下操作不能一键静默执行：

- 提交。
- 还原。
- 删除。
- 强制解锁。
- 修改 ignore。
- 应用 AI 合并方案。
- 标记冲突已解决。

### 3.3 AI 作为决策助手

AI 的交互必须让用户清楚：

- AI 分析了什么。
- AI 推荐了什么。
- AI 为什么这么推荐。
- 应用后会影响哪些文件。
- 用户可以撤销或拒绝。

### 3.4 范围始终可见

任何提交、更新、AI 筛选、冲突分析都必须展示当前范围。

示例：

```text
范围：src/pages/order 及其子目录
```

## 4. 产品入口设计

### 4.1 Activity Bar

新增 SVN 图标，名称：

```text

```

包含视图：

- 工作台总览。
- 变更。
- 冲突。
- 锁。
- 历史。
- AI 助手。

### 4.2 Source Control

SVN Provider 显示：

```text

```

资源分组：

- 冲突。
- 已修改。
- 已新增。
- 已删除。
- 缺失。
- 未版本控制。

标题按钮：

- 刷新。
- 更新。
- 提交。
- 日志。
- 更多。

### 4.3 Explorer 右键

文件右键：

```text
SVN
  提交此文件
  更新此文件
  查看差异
  查看历史
  还原
  锁定/解锁
```

文件夹右键：

```text
SVN
  提交此文件夹
  更新此文件夹
  查看此文件夹历史
  扫描此文件夹冲突
  加入忽略规则
```

关键文案：

- 文件夹操作必须使用“此文件夹”，强化范围意识。

### 4.4 状态栏

正常：

```text
SVN r12876 | 8 改动 | 远端 +2
```

有冲突：

```text
SVN r12876 | 3 冲突
```

点击后 QuickPick：

- 打开 SVN 工作台。
- 提交变更。
- 更新工作区。
- 查看远端更新。
- 打开冲突中心。
- 刷新状态。

## 7. 页面一：环境检测页

### 7.1 目标

让用户知道当前能不能使用 SVN。

### 7.2 布局线框

```text
┌────────────────────────────────────────────┐
│ SVN 环境检测                               │
├────────────────────────────────────────────┤
│ 状态：未找到 svn 命令                      │
│ 当前工作区：C:\project                     │
│ 已配置路径：未配置                         │
├────────────────────────────────────────────┤
│ [自动重新检测] [手动选择 svn.exe] [安装说明] │
└────────────────────────────────────────────┘
```

### 7.3 状态

- 找到 SVN。
- 未找到 SVN。
- SVN 路径无效。
- SVN 执行失败。
- 当前工作区不是 SVN 工作副本。

### 7.4 设计要求

- 不要让用户先看错误堆栈。
- 给出下一步按钮。
- 成功后自动进入工作台。

## 10. 页面四：提交页

提交页是第一版最重要的设计页面。

### 10.1 目标

让用户清楚、快速、安全地完成一次 SVN 提交。

### 10.2 布局线框

```text
┌──────────────────────────────────────────────────────────┐
│ 提交此文件夹：src/pages/order                            │
│ 候选 12 | 已选 8 | 已排除 4 | 远端：未检查                │
│ [刷新] [检查远端] [模板] [AI 筛选] [只看已选] [更多]      │
├───────────────────────┬──────────────────────────────────┤
│ 文件列表              │ Diff 预览                         │
│ ┌筛选────────────────┐│ ┌──────────────────────────────┐ │
│ │状态 类型 后缀 路径 ││ │ OrderList.vue                 │ │
│ └────────────────────┘│ │ - old code                    │ │
│ ☑ M OrderList.vue     │ │ + new code                    │ │
│ ☑ M api.ts            │ │                              │ │
│ ☐ ? debug.log 排除    │ │                              │ │
│ ☐ A icon.png 需确认   │ │                              │ │
├───────────────────────┴──────────────────────────────────┤
│ 类型：需求  工单：TASK-123                                │
│ 提交说明：需求: 完成订单筛选                              │
│ [AI 生成] [最近提交] [提交]                                │
└──────────────────────────────────────────────────────────┘
```

### 10.3 顶部信息

必须展示：

- 当前操作来源：提交此文件、提交此文件夹、提交工作区。
- 当前范围。
- 候选文件数量。
- 已勾选数量。
- 已排除数量。
- 远端检查状态。
- 冲突状态。

### 10.4 文件列表状态

每行展示：

- 复选框。
- SVN 状态。
- 文件名。
- 路径。
- 文件类型。
- AI 标记。
- 风险标记。

AI 标记：

- 推荐提交。
- 建议排除。
- 需要确认。
- 阻止提交。

### 10.5 筛选器

第一版必须有：

- 状态。
- 文件类型。
- 后缀。
- 路径。
- 搜索。
- 仅显示已选。
- 显示被排除。

### 10.6 批量按钮

- 全选可提交。
- 全选当前筛选。
- 清空选择。
- 排除生成物。
- 只选源码。
- 排除二进制。

### 10.7 提交区

字段：

- 类型。
- 工单号。
- 摘要。
- 详细说明。
- 提交后保留锁。

按钮：

- AI 生成。
- 模板。
- 最近提交。
- 提交。

### 10.8 提交按钮状态

| 状态 | 按钮 |
| --- | --- |
| 无文件 | 禁用 |
| 无提交说明 | 禁用或点击后提示 |
| 有冲突 | 禁用 |
| 有阻止项 | 禁用 |
| 有警告 | 可点击，提交前确认 |
| 正常 | 可点击 |

### 11.1 目标

```text

├──────────┬──────────┬──────────┬──────────┤

│ 8        │ 4        │ 2        │ 0        │
├────────────────────────────────────────────┤
│ 推荐提交                                   │

│                                            │
│ 建议排除                                   │
```

### 11.3 交互规则

- 默认不直接修改勾选。
- 用户点击 `应用推荐选择` 后才影响提交页。
- 每个推荐必须有原因。
- AI 输出路径必须二次校验在 OperationScope 内。

## 13. 页面七：AI 冲突决策卡片

### 13.1 目标

用 AI 降低冲突理解成本，但不强迫用户相信 AI。

### 13.2 MVP 布局

```text
┌──────────────────────────────────────────────────────────┐
│ 冲突文件：src/pages/order/OrderList.vue                  │
├────────────────────────────────┬─────────────────────────┤
│ VS Code Diff / 文件内容         │ AI 冲突决策卡片          │
│                                │                         │
│ <<<<<<< mine                   │ 冲突摘要：               │
│ ...                            │ 字段 status/state 冲突   │
│ =======                        │                         │
│ ...                            │ 我的意图：               │
│ >>>>>>> theirs                 │ 增加多选筛选             │
│                                │                         │
│                                │ 远端意图：               │
│                                │ 重命名状态字段           │
│                                │                         │
│                                │ AI 建议：                │
│                                │ 保留多选逻辑，使用 state │
│                                │                         │
│                                │ 风险：确认后端参数       │
│                                │                         │
│                                │ [采用我的] [采用远端]    │
│                                │ [采用 AI 方案] [手动编辑]│
└────────────────────────────────┴─────────────────────────┘
```

### 13.3 交互规则

- AI 方案先进入预览。
- 用户点击采用后才写入工作文件。
- 写入后仍需用户保存。
- 保存后检查冲突标记。
- 无冲突标记后才允许 `标记已解决`。

### 13.4 延后设计

完整三栏合并器延后。

MVP 使用：

- VS Code diff。
- AI 决策卡片。
- 可选 TortoiseMerge 外部打开。

## 20. 设计验收标准

### 20.1 范围清晰

- MVP 不依赖自研三方合并器。
- MVP 不依赖 AI 自动执行。
- MVP 不依赖完整远端事务预览。

## 23. 当前设计决策

### 23.1 MVP 是否自研三方合并器

决策：不自研。

MVP 采用：

- VS Code diff。
- AI 冲突决策卡片。
- TortoiseMerge 外部打开。

### 23.2 AI 是否默认开启

决策：默认关闭。

用户首次使用 AI 时进入模型配置和隐私确认。

### 23.3 提交页是否用 Webview

决策：使用 Webview。

理由：

- 提交页筛选、AI 标记、模板、差异预览、批量操作复杂。
- VS Code 原生 SCM 列表难以承载完整交互。

### 23.4 变更页是否用 Webview

决策：第一版不用。

优先使用 SCM Provider 和 Tree View。

### 23.5 AI 冲突处理是否直接覆盖文件

决策：不直接覆盖。

先预览，用户确认后应用，并且仍需保存和标记已解决。
