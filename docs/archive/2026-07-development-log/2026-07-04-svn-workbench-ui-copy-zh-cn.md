# SVN Workbench 中文文案规范

> 产品暂名：SVN Workbench for VS Code / SVN 工作台  
> 文档类型：设计阶段中文文案规范  
> 编写日期：2026-07-04  
> 当前阶段：设计阶段  
> 适用平台：Windows / macOS 标准统一  
> 文档策略：新增文件，不覆盖旧文档

## 1. 文案目标

统一 SVN Workbench 的中文 UI 表达，保证用户在 Windows 和 macOS 上看到同一套术语、同一套提示、同一套风险确认。

文案目标：

- 清楚。
- 克制。
- 准确。
- 不吓人，但不隐藏风险。
- 兼顾中国团队口语和 SVN 标准术语。

## 2. 基础术语

| 中文 | 英文 | 使用规则 |
| --- | --- | --- |
| 提交 | Commit | 主术语，不使用“上传”作为按钮 |
| 更新 | Update | 从 SVN 仓库拉取变化 |
| 还原 | Revert | 丢弃本地修改 |
| 检出 | Checkout | 从仓库拉取新工作副本 |
| 差异 | Diff | 查看文件变化 |
| 日志 | Log | 查看提交历史 |
| 锁定 | Lock | 锁定文件 |
| 解锁 | Unlock | 解锁文件 |
| 冲突 | Conflict | 合并冲突 |
| 标记已解决 | Resolve | SVN resolve 操作 |
| 工作副本 | Working Copy | 本地 SVN 工作目录 |
| 仓库 | Repository | SVN 仓库 |
| 修订号 | Revision | 如 r12880 |
| 范围 | Scope | 本次操作影响的路径集合 |
| 未版本控制 | Unversioned | `?` 文件 |
| 缺失 | Missing | `!` 文件 |
| 外部引用 | Externals | `svn:externals` |

## 3. 命名规则

### 3.1 菜单命名

菜单使用：

```text
提交 Commit
更新 Update
差异 Diff
日志 Log
还原 Revert
检出 Checkout
```

文件和文件夹上下文菜单使用更明确的范围文案：

```text
提交此文件
提交此文件夹
更新此文件
更新此文件夹
查看此文件历史
查看此文件夹历史
```

### 3.2 不推荐用词

| 不推荐 | 推荐 |
| --- | --- |
| 上传 | 提交 Commit |
| 下载 | 更新 Update / 检出 Checkout |
| 恢复 | 还原 Revert |
| 解决 | 标记已解决 Resolve |
| 全部提交 | 提交工作区变更 |
| 当前目录 | 此文件夹 |

说明：

- “上传”可在说明文字中出现，如“提交会把文件上传到 SVN 仓库”，但按钮不用“上传”。
- “恢复”容易和“恢复文件”混淆，丢弃本地修改统一叫“还原”。

## 27. 错误提示结构

所有错误统一结构：

```text
发生了什么
为什么可能发生
建议下一步
```

示例：

```text
提交失败：远端已有更新

当前文件不是最新版本，可能有人已经提交了相关修改。

建议先更新当前范围，解决可能的冲突后再提交。
```

按钮：

```text
更新并继续
查看远端更新
打开输出
```

## 28. 跨平台统一文案规则

### 28.1 主流程不区分平台

主流程文案不写：

```text
Windows 下...
macOS 下...
```

除非是安装提示或外部工具。

### 28.2 快捷键写法

统一写：

```text
Ctrl/Cmd + Enter
```

### 28.3 路径示例

通用示例用：

```text
src/pages/order
```

需要平台示例时：

```text
Windows: C:\project
macOS: /Users/name/project
```

## 29. 文案验收规则

文案进入开发前检查：

- 是否使用统一术语。
- 是否明确操作范围。
- 是否说明风险。
- 是否有下一步按钮。
- 是否避免平台分裂。
- 是否避免“上传/下载”等模糊说法。
- 是否没有把 AI 描述成自动执行者。
- 是否对危险操作二次确认。

## 30. 当前决策

1. 按钮统一使用“提交 Commit”，不使用“上传”。
2. 文件夹操作统一使用“此文件夹”。
3. AI 文案统一表达为建议、草案、方案，不表达为自动处理。
4. 错误提示必须给出下一步。
5. 危险操作按钮必须明确风险动作。
6. Windows/macOS 使用同一套主流程文案。
