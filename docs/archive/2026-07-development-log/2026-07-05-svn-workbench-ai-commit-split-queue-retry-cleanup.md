# SVN Workbench AI 拆分队列失败重试与完成项清理

日期：2026-07-05

阶段：开发 -> 测试

整体进度：约 63%

## 本轮目标

上一轮已经完成队列提交后的连续处理体验。本轮继续细化失败项和完成项管理：

- 失败项显示独立的 `重新预览`。
- 失败项显示独立的 `重试提交`。
- 队列头部新增 `清理已完成`。
- 重试提交必须满足失败项已重新预览且计划可提交。
- 已完成项可批量清理，保留失败项和未完成项。

## 页面变化

### 失败项按钮

当队列项状态为 `失败待处理` 时，按钮变为：

- `重新预览`
- `重试提交`
- `移除`

不再混用普通队列项的 `预览计划 / 套用 / 提交此项`。

### 完成项清理

队列头部新增：

- `清理已完成`

点击后：

- 移除所有 `已完成` 队列项。
- 保留 `待处理`、`待提交`、`提交中`、`失败待处理`。
- 如果当前 active 队列项不存在，会同步清理 active 状态。

## 重试规则

失败项不能直接盲目重试。

重试提交前必须满足：

1. 队列项状态为 `失败待处理`。
2. 用户点击 `重新预览`。
3. 提交计划状态变为 `计划可提交`。
4. 用户点击 `重试提交`。
5. 后端仍会重新执行提交计划校验、提交说明校验、远端更新检查。
6. VS Code 仍会弹出确认提交。

如果失败项还处于 `未预览`：

- `重试提交` 会被拦截。
- 页面提示先重新预览计划。

如果失败项预览后为 `计划需处理`：

- `重试提交` 会被拦截。
- 页面提示处理阻止项后重新预览。

## 安全边界

重试并不绕过任何提交流。

`重试提交` 仍然走：

- 当前候选文件匹配
- 提交计划校验
- 提交说明校验
- 团队提交规范校验
- 提交前远端更新检查
- VS Code 二次确认
- SVN commit 执行

## 下一步建议

下一步可以推进“队列筛选视图”：

- 只看失败
- 只看待处理
- 只看待提交
- 只看已完成

这样队列项越来越多时，处理效率会更接近专业 SVN 客户端的变更列表体验。
