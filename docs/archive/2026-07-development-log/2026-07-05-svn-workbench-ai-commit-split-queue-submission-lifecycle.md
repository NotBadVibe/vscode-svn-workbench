# SVN Workbench AI 拆分队列逐条提交状态流转

日期：2026-07-05

阶段：开发 -> 测试

整体进度：约 60%

## 本轮目标

上一轮已经完成拆分队列“先预览、再套用”的守护。本轮继续推进“逐条提交执行流”的第一段闭环：

- 队列项套用后进入 `待提交`。
- 用户点击确认提交后，如果当前勾选文件与某个队列项完全一致，则本次提交归属到该队列项。
- 提交开始时队列项进入 `提交中`。
- 提交成功后队列项进入 `已完成`，记录 revision。
- 提交失败后队列项进入 `失败待处理`，记录失败原因。
- 提交成功后的候选刷新不会清空队列，未完成队列项需要重新预览。

## 页面状态

拆分队列项现在包含两条状态线：

### 1. 计划状态

- `未预览`
- `计划可提交`
- `计划需处理`

### 2. 提交状态

- `待处理`
- `待提交`
- `提交中`
- `已完成`
- `失败待处理`

页面展示会同时显示这两类状态，例如：

- `待提交，计划可提交，3 个文件`
- `提交中，计划可提交，3 个文件`
- `已完成，计划可提交，3 个文件`
- `失败待处理，未预览，3 个文件`

## 归属规则

提交按钮不会盲目把所有提交都归属到队列项。

只有满足以下条件时，本次提交才会绑定到某个队列项：

- 队列项状态为 `待提交`、`失败待处理` 或 `提交中`。
- 队列项计划状态为 `计划可提交`。
- 当前勾选文件集合与队列项文件集合完全一致。

如果用户在套用后手动增删勾选文件，本次提交会按普通提交处理，不会误标队列项为完成或失败。

## 提交成功后的刷新策略

提交成功后仍然会刷新 SVN 候选状态，但刷新原因会区分：

- `commit`：提交后的刷新，保留拆分队列。
- `update`：更新当前范围后的刷新，清空拆分队列。

提交刷新时：

- `已完成` 队列项保留。
- 未完成队列项保留，但计划状态重置为 `未预览`。
- 用户需要重新预览未完成队列项，确认 SVN 状态没有因为上一条提交而变化。

## 安全边界

本轮仍然没有做自动连续提交。

用户每次仍需要：

1. 预览队列项计划。
2. 套用队列项。
3. 检查当前勾选和提交说明。
4. 点击确认提交。
5. 在 VS Code 确认弹窗中二次确认。

这样可以先把逐条提交状态闭环做稳，再进入更高级的队列自动推进或半自动推进。

## 下一步建议

下一步可以推进“队列项专用提交按钮”：

- 在每个 `计划可提交` 的队列项上展示 `提交此项`。
- 点击后自动套用该项并触发提交前预览。
- 提交前仍然保留 VS Code 二次确认。
- 提交完成后自动聚焦下一条未完成队列项。
