日期：2026-07-05

阶段：开发 -> 测试

整体进度：约 64%

## 本轮目标

上一轮已经完成失败项重试与已完成项清理。本轮继续让拆分队列更适合大量队列项使用：

- 队列头部新增 `查看` 下拉框。
- 支持只看失败、待处理、待提交、提交中、已完成。
- 状态筛选可以和 `隐藏已完成` 叠加。
- 统计显示当前可见项数量和总数。
- 空状态会根据筛选和隐藏规则给出明确提示。

## 页面变化

队列头部新增：

- `查看：全部`
- `只看失败`
- `只看待处理`
- `只看待提交`
- `只看提交中`
- `只看已完成`

统计文案调整为：

- `当前 N / 总数 M`

同时保留：

- 待处理
- 待提交
- 提交中
- 失败
- 已完成
- 已隐藏

## 交互规则

### 1. 状态筛选

选择不同状态后：

- 队列列表只显示该状态的队列项。
- 队列实际内容不变。
- 提交、重试、移除等动作仍只作用于当前队列项。

### 2. 隐藏已完成叠加

如果同时开启 `隐藏已完成` 并选择 `只看已完成`：

- 列表为空。
- 页面提示已开启隐藏已完成。

如果全部队列项都是已完成并开启隐藏：

- 列表为空。
- 页面提示可取消隐藏查看。

### 3. 更新范围后的重置

执行 `更新当前范围` 后：

- 队列会清空。
- 队列筛选重置为 `全部`。
- `隐藏已完成` 重置为关闭。

提交成功后的刷新仍保留当前队列和筛选状态。

## 安全边界

状态筛选只影响展示，不影响底层 SVN 操作。

所有提交、重试和预览仍然基于队列项自身数据，并继续走已有的：

- 路径范围校验
- 提交计划预览
- 提交说明校验
- 提交前远端更新检查
- VS Code 二次确认

## 下一步建议

下一步可以推进“队列持久化草稿”：

- 关闭提交页后保留拆分队列。
- 重新打开页面时恢复未完成队列。
- 按工作副本范围隔离队列草稿。
- SVN 状态变化后要求重新预览恢复的队列项。
