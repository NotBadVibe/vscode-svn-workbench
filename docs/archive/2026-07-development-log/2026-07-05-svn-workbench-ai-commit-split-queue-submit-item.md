# SVN Workbench AI 拆分队列提交此项

日期：2026-07-05

阶段：开发 -> 测试

整体进度：约 61%

## 本轮目标

上一轮已经完成拆分队列逐条提交状态流转。本轮继续把队列操作压缩为更顺手的入口：

- 每个拆分队列项新增 `提交此项`。
- 用户不需要先手动套用再去页面顶部点 `确认提交`。
- 点击 `提交此项` 会自动套用该队列项的文件和提交说明。
- 然后进入原有提交链路，仍保留 VS Code 二次确认。

## 交互规则

### 1. 计划未预览

如果队列项状态是 `未预览`，点击 `提交此项`：

- 不改变当前勾选。
- 不改变提交说明。
- 不进入 SVN 提交。
- 提示用户先预览计划。

### 2. 计划需处理

如果队列项状态是 `计划需处理`，点击 `提交此项`：

- 不改变当前勾选。
- 不改变提交说明。
- 不进入 SVN 提交。
- 提示用户处理阻止项后重新预览。

### 3. 计划可提交

如果队列项状态是 `计划可提交`，点击 `提交此项`：

- 自动勾选该队列项对应文件。
- 自动填入该队列项的提交说明草稿。
- 队列项进入 `待提交`。
- 调用原有 `executeCommit` 提交流。
- VS Code 弹出确认提交对话框。
- 用户确认后才真正执行 SVN 命令。

### 4. 提交中或已完成

如果队列项是 `提交中`：

- 阻止重复提交。
- 提示等待提交结果。

如果队列项是 `已完成`：

- 阻止再次提交。
- 提示该队列项已经提交完成。

## 提交归属保护

`提交此项` 会显式传递当前队列项 ID。

普通页面顶部的 `确认提交` 仍然可以归属队列项，但必须满足：

- 当前勾选文件集合与队列项文件集合完全一致。
- 队列项状态为 `待提交` 或 `失败待处理`。
- 队列项计划状态为 `计划可提交`。

这样用户临时修改勾选文件时，不会误把普通提交标记为某个队列项完成。

## 安全边界

本轮仍然不做无确认自动提交。

完整链路保持为：

1. AI 生成拆分建议。
2. 用户加入队列。
3. 用户预览计划。
4. 用户点击 `提交此项`。
5. 页面自动套用文件和提交说明。
6. 后端重新执行提交计划校验、提交说明校验、远端更新检查。
7. VS Code 弹出确认提交。
8. 用户确认后才执行 SVN 命令。

## 下一步建议

下一步可以推进“提交完成后聚焦下一条队列项”：

- 提交成功后自动提示下一条 `未预览` 或 `失败待处理` 队列项。
- 支持一键预览下一条。
- 支持隐藏已完成项，保持队列清爽。
- 支持从失败项快速重新预览和重试。
