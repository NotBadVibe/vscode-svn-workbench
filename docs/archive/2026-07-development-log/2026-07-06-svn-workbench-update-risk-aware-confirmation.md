# SVN Workbench 风险感知更新确认

日期：2026-07-06

阶段：开发 -> 测试

## 背景

更新预览已经可以展示本地摘要、远端摘要和风险提示。
但如果用户直接点击 `更新当前范围`，此前确认框仍是固定文案，无法体现当前风险。

本轮新增“风险感知更新确认”，在真正执行 `svn update` 前重新评估风险，并把关键信息放进二次确认框。

## 页面入口

提交页面 -> `更新当前范围`

点击后确认框新增：

- 更新风险：低 / 中 / 高
- 本地未提交数量
- 远端变更数量
- 同路径重叠数量
- 远端检查失败原因
- 风险建议
- 前 5 条重叠路径

## 示例

```text
确认更新当前范围？
更新风险：高
本地未提交：4
远端变更：1
同路径重叠：1
建议：
- 远端与本地未提交存在 1 个同路径重叠，建议先查看差异或提交本地改动。
重叠路径：
- src/order.ts
如果产生冲突，将保留为待处理状态。
```

## 执行流程

点击 `更新当前范围` 后：

1. 生成当前范围更新预览。
2. 执行远端更新状态检查。
3. 重新计算更新风险。
4. 生成风险感知确认文案。
5. 用户确认后才执行 `svn update --accept postpone`。

如果远端检查失败：

- 确认框会展示失败原因。
- 风险等级为中。
- 用户仍可自行决定是否继续更新。

## 安全边界

该能力只增强确认：

- 不自动更新。
- 不自动提交。
- 不自动解决冲突。
- 不修改工作区文件。
- 不改变 `svn update --accept postpone` 行为。

## 核心实现

新增核心能力：

- `buildUpdateScopeRiskConfirmationMessage`

扩展：

- `executeUpdateScope` 执行前复用远端检查和风险评估。

## 跨平台一致性

确认文案由 TypeScript 核心逻辑生成，Windows 和 macOS 一致。
SVN 更新命令仍使用标准 CLI 参数。
