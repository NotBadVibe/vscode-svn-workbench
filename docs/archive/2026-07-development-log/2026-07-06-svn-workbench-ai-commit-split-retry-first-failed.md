# SVN Workbench AI 拆分队列重试首个失败项

日期：2026-07-06

阶段：开发 -> 测试

## 背景

拆分队列已经支持单条失败项的“重试提交”，但用户需要先在列表里找到失败项，再手动点击单条按钮。
当队列里同时存在可提交项、未预览项和失败项时，失败项恢复路径不够显眼。

本轮新增队列级“重试首个失败”能力，让失败恢复进入下一步建议和头部操作区，减少日常提交中的查找成本。

## 页面入口

提交页面 -> 拆分待提交队列：

- 队列头部新增 `重试首个失败`。
- 下一步建议卡片在存在可重试失败项时显示 `优先重试失败项`。
- 建议卡片主按钮为 `重试首个失败`。

## 可重试判定

队列项必须同时满足：

1. `status = failed`。
2. 已完成提交计划预览。
3. `planStatus = ready`。
4. 未处于 `submitting`。
5. 未处于 `completed`。

失败但尚未预览、失败且计划被阻止、提交中或已完成的队列项不会进入该入口。

## 交互流程

点击 `重试首个失败` 后：

1. 查找队列中第一个可重试失败项。
2. 自动切换筛选条件为 `只看失败`。
3. 自动切换计划筛选为 `只看可提交`。
4. 清空阻止原因筛选。
5. 取消隐藏已完成项，保证用户看到当前上下文。
6. 聚焦到第一个可重试失败项。
7. 复用原有单条 `重试提交` 流程。

## 下一步建议优先级

当前队列的下一步建议优先级调整为：

1. 空队列：提示生成 AI 拆分建议。
2. 批量预览中：等待批量预览完成。
3. 存在阻止项：优先处理阻止项。
4. 存在可重试失败项：优先重试失败项。
5. 存在可提交项：提交首个可提交项。
6. 存在未预览项：预览未预览项。
7. 存在提交中项：等待提交结果。
8. 全部完成：清理已完成项。

保留“阻止项优先于重试”的原因是：阻止项通常代表冲突、范围外文件、生成物过滤或 SVN 状态异常，应先避免错误提交面继续扩大。

## 安全边界

该能力不做自动提交：

- 点击后仍会走提交计划守卫。
- 仍会走提交前确认。
- 仍会走远端更新检查。
- 仍由用户确认是否真正提交。
- 不会绕过生成物、范围、冲突、SVN 状态等既有规则。

## 跨平台一致性

本轮能力位于 TypeScript 核心逻辑和 VS Code Webview 交互层，不依赖 Windows 或 macOS 专有命令。
实际提交仍复用已有 SVN 提交流程，因此两个平台的按钮、筛选、优先级和安全确认标准保持一致。

## 核心实现

新增核心函数：

- `getFirstRetryableCommitSplitQueueItem`

扩展下一步建议：

- 新增 `retryFailed` 状态。
- 新增 `retryFirstFailed` 主动作。

扩展 Webview：

- `getFirstRetryableSplitQueueItem`
- 队列头部 `retryFirstFailed`
- 下一步建议 `retryFailed`
- 点击后自动切换到失败且可提交视图，并调用原有重试提交流程。
