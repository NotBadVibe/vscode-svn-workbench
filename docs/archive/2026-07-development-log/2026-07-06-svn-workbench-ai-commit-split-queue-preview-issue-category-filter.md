# SVN Workbench AI 拆分队列阻止原因筛选

日期：2026-07-06

阶段：开发 -> 测试

## 背景

上一版已经把拆分待提交队列的预览阻止项按原因分组，例如范围不匹配、候选列表缺失、规则排除、阻止状态、SVN 状态不支持、空选择和其他原因。

本轮继续把“分组统计”升级为“可操作筛选”，让用户能直接点击某个阻止原因，只查看对应的拆分队列项。

## 页面功能

入口位置：提交页面 -> 拆分待提交队列 -> 需处理阻止项汇总。

交互细节：

1. 阻止项汇总展示每个原因按钮，按钮文案为“原因 + 阻止条数/涉及队列项数”。
2. 点击原因按钮后，队列自动切到“计划：只看需处理”。
3. 点击原因按钮后，队列只显示匹配该阻止原因的拆分项。
4. 点击原因按钮后，页面自动聚焦第一条匹配的队列项。
5. 激活原因筛选后，汇总区显示“当前原因”。
6. 激活原因筛选后，汇总区提供“全部原因”按钮，用于恢复所有需处理原因。
7. 当用户手动切到“只看可提交”或“只看未预览”等非需处理计划筛选时，原因筛选自动清空。
8. 当批量预览结束并自动跳转到第一条需处理项时，原因筛选自动清空，避免旧筛选遮住新结果。
9. 清空队列、丢弃草稿、清理后队列为空时，原因筛选同步清空。

空状态：

- 如果原因筛选后没有匹配项，页面提示当前没有匹配该阻止原因的拆分队列项。
- 如果阻止项详情在当前原因下为空，汇总区提示可点击“全部原因”恢复。

## 核心能力

新增核心函数：

- `doesCommitSplitQueueItemMatchPreviewIssueCategory`
- `getVisibleCommitSplitQueueItems` 支持第五个参数 `previewIssueCategoryFilter`

分类规则沿用上一版：

- `scope`：范围不匹配
- `candidate`：候选列表缺失
- `excluded`：规则排除
- `blocked`：阻止状态
- `svnStatus`：SVN 状态不支持
- `emptySelection`：空选择
- `unknown`：其他原因

兜底规则：

- 队列项必须是 `planStatus = blocked` 才能命中具体原因筛选。
- 如果阻止队列项缺少 `lastPreviewIssues`，会归入 `unknown`，提示用户重新预览查看详情。

## 价值

这个功能服务于真实日常提交场景：

- 候选列表缺失：通常需要刷新 SVN 状态、重新选择范围或重新生成拆分建议。
- 范围不匹配：通常出现在右键某个文件夹提交时，AI 拆分建议包含了范围外文件。
- 规则排除：通常与 bin、obj、dist、target 等生成文件策略有关。
- SVN 状态不支持：通常需要先处理冲突、缺失、阻止状态或异常状态。

用户可以按原因批量定位问题，不需要在长队列中逐条展开看阻止项。

## 跨平台标准

该能力只依赖 VS Code Webview、TypeScript 状态管理和字符串分类，不依赖 Windows/macOS 专有能力。

按钮样式使用已有 VS Code 主题变量，布局使用 flex wrap，保证 Windows 与 macOS 的窄侧栏或宽页面下表现一致。
