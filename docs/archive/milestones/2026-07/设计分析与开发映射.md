# SVN Workbench v3 · 右键模块设计与开发映射

> 2026-07-30 架构更新：所有可见业务 UI 已统一为 Svelte 5。本文保留产品优先级、AI、范围和领域映射价值；涉及原生 SCM、Diff、Merge Editor、Quick Pick 或多个独立 Webview 的旧建议，由 [`Svelte统一UI开发改造与验收方案.md`](./Svelte统一UI开发改造与验收方案.md) 覆盖。

## 一、产品判断

SVN Workbench 的高频入口应该是“当前文件/文件夹的上下文命令”，而不是独立产品首页。VS Code Explorer、编辑器和命令面板提供入口；命令解析当前范围后，直接打开统一 Svelte Workbench Shell 中的目标模块。提交、Diff、历史、冲突、设置、进度和 AI 使用同一套 Svelte 业务 UI。

这会带来三个直接收益：

1. 用户不需要离开正在编辑的文件，也不用重新选择仓库和范围。
2. 每个模块独立声明状态与协议，避免重新生成一个数千行的全能面板。
3. 右键入口保持 VS Code 使用习惯，同时业务界面、组件和视觉完全统一。

## 二、最常用功能优先级

### P0 · 每天都会用

1. **更新当前范围**：开发开始、提交前、切换任务后都会用。
2. **提交当前范围**：核心闭环，必须支持文件选择、说明和提交前检查。
3. **查看本地修改**：应直接打开 VS Code Diff，不应新做差异页面。
4. **查看历史**：排查改动来源和理解旧实现时高频使用。
5. **冲突处理**：频率未必最高，但一旦发生就是阻断任务。

### P1 · 常用辅助

1. 还原本地修改。
2. 添加到忽略列表。
3. 查看某行责任人或文件日志。
4. 复制 SVN URL / 相对路径。
5. 锁定、解锁需要独占编辑的二进制文件。
6. SVN 属性编辑。

### P2 · 低频管理

1. Relocate、Switch、Cleanup。
2. 分支、标签和合并向导。
3. 仓库浏览器。
4. 团队规则、AI 模型和环境诊断。

P2 不应进入默认右键首层；可以放在命令面板、设置或“更多 SVN 操作”中。

## 三、AI 应该发挥作用的地方

AI 不应只是“写提交说明”的按钮。它更适合承担 SVN 缺少的语义理解和风险判断，但必须给出依据并保留人工确认。

### 1. 提交前语义审查

- 检查潜在缺陷、空值、精度、异常路径和安全问题。
- 识别敏感信息、生成物、大文件和无意混入的调试代码。
- 每条结论必须关联文件、行号、证据和置信度。
- 允许忽略结论，并在本次草稿中记录理由。

对应现有模块：`commitDiffSummary.ts`、候选文件和 AI provider。需要新增 `changeReview` 场景及结构化结果校验器。

### 2. 按业务意图拆分提交

- 结合引用关系、文件状态、差异语义和历史提交风格聚类。
- 保证每批范围合法、说明完整、可独立回滚。
- 发现“日志整理”“格式化”“生成物”等旁支变更并建议另批。

对应现有模块：`commitSplitAi.ts`、`commitSplitQueue.ts`、`commitPlanBuilder.ts`。现有能力可以保留，但 UI 应从全能提交页移到独立模块。

### 3. 影响范围与测试建议

- 分析调用方、复用模块、配置和文档影响。
- 根据差异生成边界测试、回归测试和上线观察项。
- 允许复制为任务清单或发送到 VS Code Chat 继续处理。

需要新增基于引用关系与历史的上下文收集器；默认只读取当前工作区和 SVN 历史，外发前遵循 AI 配置与隐私规则。

### 4. 冲突合并候选

- 解释两侧修改意图。
- 生成合并候选、风险和建议验证步骤。
- 不直接执行 `svn resolve`；应用候选后仍由用户在 Merge Editor 检查并标记解决。

对应现有模块：`conflictAiAdvisor.ts`、`conflictResolver.ts`。建议保留冲突采集、候选生成和范围保护，把编辑、候选比较、AI 理由与验证建议统一迁移到 Svelte 冲突模块。

### 5. 团队记忆

- 从最近 SVN 历史学习提交说明风格、常见模块和评审规则。
- 为当前仓库建立可解释的本地摘要，不把完整历史默认发给外部模型。
- 明确显示使用了哪些规则和多少条历史，而不是声称“自动理解团队”。

这需要新增本地可清理缓存、上下文预算和隐私开关。

### 6. 受控 AI 任务代理

- 接受“整理成可提交状态”这类目标，先产出计划，不直接执行。
- 每一步显示仓库、范围、命令预览、风险、可撤销性、隐私范围和重新采集状态的时机。
- 只读步骤可快速批准；Update、生成代码、Revert、Switch、Merge、Commit 等写操作必须单独确认。
- scope、文件内容或 revision 变化后，旧计划和旧审查结论标记过期，不能继续沿用。
- AI 不可用时退化为本地规则扫描和人工 SVN 流程，核心能力不被锁死。

原型证据见 `功能全景与状态矩阵.html#agent`。

## 四、统一工作副本视图、Changelist 与多仓库

SVN 插件不应只依赖 Explorer 右键。Svelte Changes 模块应作为持续状态面：

- 按冲突、修改、新增、删除、缺失和未版本化分组。
- Changes 与智能提交模块共用同一份 Host 草稿。
- AI 拆分结果可以一键转成 SVN changelist，且允许人工移动文件。
- 每个工作副本创建独立 repository model；嵌套工作副本和 externals 显示所属仓库。
- 混合仓库多选必须阻止一次提交，并建议按仓库拆成多个任务。

完整蓝图见 `功能全景与状态矩阵.html#scm`。

## 五、右键菜单建议

推荐在 `package.json` 中新增 `contributes.submenus`，Explorer 右键只出现一个 `SVN Workbench` 入口，二级菜单如下：

```text
SVN Workbench
├── 智能提交此范围
├── 更新此范围
├── 查看本地修改
├── 查看历史
├── ─────────────
├── AI 助手
│   ├── 审查此范围
│   ├── 智能拆分提交
│   ├── 生成提交说明
│   ├── 分析影响与测试
│   ├── 解释当前文件修改
│   └── AI 任务代理…
├── 冲突与恢复
│   ├── 打开冲突处理
│   ├── 在合并编辑器中打开
│   └── 还原本地修改…
└── 更多 SVN 操作
    ├── 刷新 / Add / Delete
    ├── 添加到忽略列表
    ├── 复制 URL / 在仓库中显示
    ├── 锁定 / 解锁所选文件…
    ├── SVN 属性…
    ├── Cleanup 与恢复…
    ├── 分支、标签、切换与合并…
    ├── 仓库浏览器…
    ├── Patch、本地搁置与发布说明…
    └── 环境检查与设置
```

`when` 条件应按上下文收紧：

- Explorer 模块入口不能依赖扩展激活后才设置的 context key；精确 SVN 状态菜单放在原生 SCM/Svelte 文件树，非 SVN 路径由 Host 拒绝。
- “锁定”只对文件或多选文件显示。
- “冲突处理”只在状态为 conflicted 时提升到可见位置。
- “智能提交/更新”对文件夹、多选和工作区根显示。
- “解释当前文件修改”只对存在本地差异的单文件显示。

## 六、可靠性与异常状态

认证、证书、代理、离线、工作副本锁、未完成操作、长任务、取消、重试、CLI 缺失和 AI 未配置都属于产品主流程，不是统一错误提示。正式实现至少需要：

- 密码使用 `PasswordInput` 或系统凭据存储，禁止写入 settings 和日志。
- 证书确认展示主机、指纹、有效期及“仅本次/永久信任”的差别。
- 长任务展示阶段、耗时、当前范围、输出入口和取消动作；取消后先重新采集状态再允许重试。
- Cleanup 默认不删除未版本化或忽略文件，并展示将运行的命令。
- Revert、Delete、Switch、Merge、从修订恢复等操作展示精确清单、可恢复性和二次确认。

交互状态见 `功能全景与状态矩阵.html#states`。

## 七、代码结构建议

### 命令路由

```text
src/commands/
├── registerContextCommands.ts
├── commitScopeCommand.ts
├── updateScopeCommand.ts
├── reviewScopeCommand.ts
├── splitScopeCommand.ts
├── historyCommand.ts
├── conflictCommand.ts
└── utilitiesCommand.ts
```

所有命令先通过统一的 `resolveCommandContext(uri, selectedUris)` 得到：

- repositoryRoot
- operationScope
- selectedFiles
- SVN 状态快照
- capability flags

避免每个命令自行推断仓库根和右键范围。

### UI 表面

```text
src/
├── extension/workbench/
│   ├── WorkbenchPanelHost.ts
│   └── WorkbenchController.ts
├── protocol/
└── webview/
    ├── App.svelte
    ├── bridge/
    ├── components/
    └── features/
        ├── changes/
        ├── commit/
        ├── diff/
        ├── history/
        ├── conflicts/
        └── ai-agent/
```

所有模块共享一个 WorkbenchPanelHost、设计令牌和消息协议，但每个 feature 保持独立状态；详细目录以统一 Svelte 改造方案为准。

### AI 场景扩展

建议在 `AiUsageScenario` 中增加：

- `changeReview`
- `impactAnalysis`
- `testSuggestion`
- `historySummary`
- `changeExplanation`

所有结构化 AI 结果必须经过 schema 校验、范围校验和字符预算裁剪；模型返回的路径不得扩大当前右键范围。

## 八、迁移顺序

1. 建立 `resolveCommandContext`、Explorer 子菜单和统一 WorkbenchPanelHost。
2. 建立 Svelte Shell、Bridge、设计令牌、组件测试和 Mock 数据。
3. 先迁移“查看修改”形成右键到 Svelte Diff 的垂直链路。
4. 从 `commitPanel.ts` 提取领域逻辑并迁移智能提交、说明、preflight 和拆分队列。
5. 迁移冲突、历史、设置、诊断和可靠性状态。
6. 新增 AI 变更审查、影响分析、任务代理和过期结果协议。
7. 删除旧业务 HTML/CSS/JS Panel 和重复入口，执行统一 Svelte 发布验收。

## 九、验收条件

- 用户从 Explorer 右键最多两级即可到达高频功能。
- 右键范围在模块内始终可见，且 AI 不能扩大范围。
- 查看差异和冲突合并使用统一 Svelte 模块并按需加载编辑能力。
- AI 未配置时，所有基础 SVN 命令仍可使用。
- AI 结论均展示证据、来源、置信度或降级来源。
- 破坏性命令展示精确文件清单并二次确认。
- 不再出现一个同时承载提交、同步、拆分、冲突、配置和诊断的巨型页面。
- Svelte Changes 中可看到 changelist、externals 和多个工作副本的明确归属。
- 认证、证书、离线、锁定、取消、重试和过期 AI 结果都有独立恢复路径。
- 每个功能都能在 `完整功能清单与验收矩阵.md` 中定位到入口和原型证据。
