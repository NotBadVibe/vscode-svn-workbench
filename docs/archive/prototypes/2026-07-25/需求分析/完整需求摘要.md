## 一、项目背景与设计边界

### 1.1 一句话定位
SVN Workbench 是 VS Code 扩展的「SVN 工作台」，**以编辑器内嵌 webview 面板（Chromium）呈现、由命令触发**；本次目标是在既有 6 个功能页 + 新补全的 5 个页面原型基础上，整合成覆盖**全部 11 页**、可被下游直接消费的单一需求输入，并以**中文命名的新文件夹**（`SVN工作台原型/`）组织产物。

### 1.2 运行环境
- **宿主**：VS Code 编辑器内嵌 webview（Chromium 内核，支持 `var()` 嵌套、`color-mix()` 回退）。
- **触发方式**：全部由命令触发（Explorer 右键文件夹 / 命令面板），**不是** Activity Bar / Tree View / SCM Provider（这些在 v1 中明确归后期，见 `v1-spec-converged.md §1`）。
- **主题继承**：UI 必须继承宿主 VS Code 的深色/浅色主题，并随主题切换实时变化；**深色优先 + 自动浅色**。
- **技术栈（已拍板）**：Svelte 重写现有 webview，受控渲染，编译产物纳入 `tsc` 检查（决策 #1，`svn-workbench-redesign-plan.md §3.5`）。

### 1.3 品牌上下文（铁律来源）
- 自有品牌 = **VS Code 设计语言**。所有颜色一律引用 `var(--vscode-*)` 主题变量，**禁用硬编码 hex、禁第三方品牌色**。
- 字体继承 `var(--vscode-font-family)` / 编辑器字体；控件对齐 VS Code 原生组件；图标用 **codicon**（原型阶段以单色 inline SVG 占位并旁注 codicon 名）。
- 视觉模式借鉴基底：**Linear（主）+ Vercel / Raycast（辅）**，仅借其「节奏与秩序」（间距密度、层级表达、状态色克制用法），**不借任何品牌色**（`v1-design-tokens.md §0`）。

### 1.4 本次目标
1. 补全并统一全部 **11 页**需求（6 既有 + 5 未设计）。
2. 以中文命名的新文件夹 `SVN工作台原型/` 组织产物（下设 `需求分析/`、`设计系统/`、`高保真原型/`）。
3. 作为下游设计系统专家与原型构建师的**单一消费输入**，消除"命令孤岛"与降级语义不一致。

## 二、全局设计约束（铁律）

> 以下约束对 11 个页面**全部强制**，违反任一条即不通过验收。提炼自 `v1-design-tokens.md §1/§5/§8`、`design-tokens-addendum-undesigned.md §9.7`、`v1-spec-converged.md §3`、需求摘要第三节。

**① 颜色全部引用 `var(--vscode-*)`，禁 hex、禁浅色覆盖**
- 任何 `color` / `background` / `border-color` 必须走第 1 节令牌（即 `var(--vscode-*)` 或其 `color-mix` / `var` 嵌套回退）。
- 组件样式中不得出现 `#` 开头的 hex（**唯一例外**：`transparent`）。
- **禁止** `@media (prefers-color-scheme: light)` 等按主题硬编码覆盖，禁止按主题写条件分支——信任 `var(--vscode-*)` 自动适配（深浅同源）。
- 退回语义色用嵌套变量兜底，如 `var(--vscode-warningForeground, var(--vscode-charts-yellow))`，回退目标仍是 vscode 变量。

**② 字体首值必须是 VS Code 变量**
- `font-family` 首值 = `--font-family`（即 `var(--vscode-font-family)`）；路径 / diff / 提交信息 / 命令名用 `--font-family-mono`（首值 `var(--vscode-editor-font-family)`）。
- 字号阶梯按 VS Code 原生节奏（11/12/13/15/18）定义，属几何值非颜色，不违反"禁 hex"。

**③ 组件严格按 v1 设计令牌**
- 按钮（Primary / Secondary / Icon-btn / Disabled / Focus）、输入 / 文本域 / 下拉、列表 / 树、徽标 Badge、状态摘要条 / 批量操作条、卡片（左条 + 内容 Raycast 骨架）、左右 Split、codicon 图标——全部按 `v1-design-tokens.md §4` 实现。
- 间距只走 `--space-1..8`、圆角只走 `--radius-*`、高度只走 `--control-height*` / `--row-height*`、字号只走 `--font-size-*`（不得出现裸 `32px`/`6px`/`18px`/`1.45` 等）。

**④ 降级语义（关键，不得抛错 / 不得静默）**
- **AI 未配置 → 手动模式**：相关功能显式降级为"手动模式"info 卡（`icon-info` + 左条 `--color-info-fg`），提示运行 `SVN：AI 配置模型`，**不抛错阻断**整条链路（落实 `v1-spec-converged.md §3.5 / A2`）。
- **svn 缺失 → 引导卡**：渲染 warning/error 引导卡（指向 `svnWorkbench.svn.path`，"去安装/去配置"动作），顶部/整页说明"无法计算差异"，**不静默退出**（直接对应 `redesign-plan §1.2` 头号"跑不通"根因）。
- 二降级均需在原型中存在明确分支（含演示开关），不得静默、不得抛异常。

**⑤ 禁 `innerHTML` 拼接**
- 一律改 Svelte / 受控渲染（操作 `textContent` / `classList` / `createElement` / `setAttribute`），消除"运行期错误不可见"（落实 `§4.1`）。
- 源文件 `aiConfigurationPanel.ts`（`providerPreset.innerHTML` / `renderScenarioModels` / `showModelList`）、`teamConfigPanel.ts`（`renderPreview`）的 innerHTML 必须消除（冲突修正 #3）。

**⑥ 深浅同源**
- 同一份令牌在深色/浅色主题下自动切换，无第二套定义。验证：深浅主题各开一次，核对列表 hover/选中、状态卡左条、diff 增删底色对比度 ≥ WCAG AA。

### 页面 01 · 提交面板（提交当前范围）

**五要素**
- **场景**：命令 `SVN：提交当前范围`（Explorer 右键"提交此文件夹"）/ 命令面板触发，打开单页 webview。合并原"提交页"与"提交篮"为同一面板（决策：否定 `product-spec §5.4` 独立面板）。
- **受众**：执行提交的中国 SVN 开发者，需快速勾选、分组、写中文提交信息。
- **调性**：VS Code 原生、高密度列表、克制。
- **规模**：单页 webview（1 份文档）。

**功能范围（in-scope）**
- 仓库条 + 当前操作范围（右键文件夹路径）+ 刷新状态。
- 变更 / 新增 / 删除 / 冲突 计数徽标（StatusSummary）。
- 批量操作条：全选 / 全不选 / 反选 / 展开折叠分组。
- 筛选·分组·预设：以 **template group 为唯一驱动源**，preset 只引用分组；字段单一 schema；默认排除生成物（`.svnignore` / `svn:ignore`）。
- 文件列表：分组展示、行内可勾选、支持筛选/搜索；**不可自动吸收范围外新变更**。
- AI 建议勾选区：提供"建议勾选"按钮 → 仅生成建议，**用户确认后生效**；建议默认可配置且**默认关闭**；未配置时降级手动模式。
- 提交信息框（多行、支持模板/预设）+ 动作按钮（提交/取消/刷新/打开差异对比）。

**关键 UI 区域 / 内容块**（可直接被原型消费）
1. 仓库条（repoRoot + 右键范围 + 刷新）
2. 状态摘要条（变更/新增/删除/冲突 徽标组）
3. 批量操作条（全选/全不选/反选/展开折叠）
4. 筛选·分组·预设控制（基于 template group 单一 schema）
5. 文件列表（分组 + 行内勾选 + 搜索；范围外保护）
6. AI 建议勾选区（"建议勾选"按钮 + 降级手动模式卡）
7. 提交信息框（textarea，mono 观感）
8. 动作按钮区（提交 Primary / 取消·刷新·打开差异对比 Secondary）

**必要状态**
- 常态：已加载范围文件、分组与勾选就绪。
- 加载中：刷新/筛选计算进度（`--color-progress`）。
- **AI 未配置降级**：AI 区域渲染 info 卡（手动模式），提示运行 `SVN：AI 配置模型`，不抛错。
- 范围外保护态：范围外新变更不进入列表（硬约束，无独立视觉，靠"不出现"体现）。
- 错误态：webview 全局错误边界回传 extension host（不阻断式错误展示）。

**硬验收项**
- 所有颜色/字体/间距引用令牌，grep 无 `#` hex（除 transparent）。
- 合并"提交页+提交篮"为单页（非两面板）。
- template group 为唯一驱动源、单一 schema（消除 `page-function §10.13` 与 `ai-filter §3.8` 两套）。
- **AI 不自动勾选，仅"建议勾选"按钮、用户确认生效**；建议默认关闭（决策 #2）。
- **"右键文件夹提交只显示该文件夹范围"** + **"提交篮不能自动吸收范围外新变更"** 为硬验收项（§3.6）。
- Svelte 受控渲染，禁 innerHTML。

### 页面 02 · 冲突中心

**五要素**
- **场景**：命令 `SVN：打开冲突中心`（右键文件夹 / 命令面板）触发 webview，呈现冲突文件与逐文件解决。
- **受众**：遇合并冲突的开发者，需直观比较 working/ours/theirs 并选择。
- **调性**：VS Code 原生、对比视图密度高、专业。
- **规模**：单页 webview；MVP **不含**三方合并器。

**功能范围（in-scope）**
- 冲突文件列表（未解决 / 已解决状态标记）。
- 默认布局 **左右 + 结果**（一侧 working/ours/theirs 之一，另一侧 working，底部/右侧结果预览），明确二选一。
- 逐处冲突 `working` / `ours` / `theirs` 三选一（扩展 `conflictResolver` 当前仅 working）。
- AI 解决建议区（未配置降级手动模式）。
- 动作：标记为已解决 / 应用 / 刷新 / 打开外部对比。

**关键 UI 区域 / 内容块**
1. ScopeBar（对齐既有顶栏规范）
2. StatusSummary（冲突计数徽标）
3. ConflictFileList（冲突文件列表）
4. WorkArea：SplitCompare（左右双 pane 对比，ours/theirs/working 增删语义底色）+ ThreeWaySelector（三选一）+ ResultPreview（结果预览）+ AiSuggestion（AI 建议·降级手动模式）

**必要状态**
- 常态：文件列表 + 选中文件的双 pane 对比 + 三选一选中态。
- 加载中：刷新/AI 建议进度。
- **AI 未配置降级**：AiSuggestion 区显 info 卡手动模式，不抛错。
- 已解决态：文件标记"已解决"（success 语义）。
- 错误态：webview 全局错误边界回传。

**硬验收项**
- 默认布局 **左右 + 结果**（明确二选一，否定 `ai-filter §5.3` 悬而未决）。
- MVP 支持 `working/ours/theirs` 三选一（决策 #4）；**三方合并器放后期**。
- Split 对比用 `--color-diff-add-bg` / `--color-diff-del-bg` 增删语义，左侧 gutter 用对应 gutter 令牌。
- AI 未配置降级手动模式不抛错。
- Svelte 受控渲染。

- 更新建议列表（待更新项 + 简要说明）。
- 动作：更新当前范围 / 刷新 /（可选）打开差异对比。

**关键 UI 区域 / 内容块**

**必要状态**

- 加载中：更新/刷新进度。
- 空态：无待更新项 → info 提示。

**硬验收项**

- v1 **不做**"远端变更精确预览 / 更新前冲突预测"（归后期）。
- 凭据优先 SVN auth cache，不默认传 `--password`；AI key 存 SecretStorage。
- 全部令牌化、Svelte 受控渲染。

### 页面 04 · 环境检查 / 诊断

**五要素**
- **场景**：首次激活自动 `checkEnvironment`；命令 `SVN：检查环境`（命令面板）也可手动触发；结果以 webview 呈现。
- **受众**：安装/配置扩展的开发者，需明确知道 svn / AI 是否就绪。
- **调性**：VS Code 原生、状态卡清晰、引导性强、不恐吓。
- **规模**：单页 webview。

**功能范围（in-scope）**
- 体检总览（整体就绪 / 需配置）。
- svn 状态卡（已安装 / 缺失 → 指向 `svnWorkbench.svn.path` 配置引导 + "去安装/去配置"动作；不静默退出）。
- AI 状态卡（已配置 / 未配置 → 降级"手动模式"提示运行 `SVN：AI 配置模型`；不抛错）。
- 凭据状态（依赖 SVN auth cache，不默认 `--password`）。

- **svn 缺失降级**：提交/预览均依赖 svn；svn 缺失时相关动作禁用并显 warning/error 引导卡（指向 `svnWorkbench.svn.path`），**不静默退出**。
- blocked 态：阻止项以 warning/error 清晰标注，详情可展开看原因与快捷动作。
- failed 态：`lastSubmissionError` 以 error 文本呈现，仅 failed 提供"重试"。
- 空态：队列空 → 引导横幅"等待拆分建议"。
- 全完成态：allDone → "清理已完成"主操作。

**硬验收项**
- 全部令牌化；徽标/列表/状态卡/操作条严格按 §4.3/§4.4/§4.5/§4.7。
- 队列项 status × planStatus 二维状态以语义色徽标零歧义呈现（状态色只用于徽标/左条/关键计数，遵循 §7 Anti-Slop，不"花花绿绿"）。
- **七类阻止项**（scope/candidate/excluded/blocked/svnStatus/emptySelection/unknown）中文 label 与快捷动作齐全（§9.4）。
- **NextAction 十态**引导横幅与对应主操作命令映射正确，单一明确主操作（§9.2）。
- **AI 未配置 → 手动批次降级；svn 缺失 → 引导卡；二者均不抛错、不静默**（§3.3/§3.5）。
- 草稿按 scope 持久化、恢复时 completed 丢弃 / submitting 退 failed 的语义在原型中可见。
- Svelte 受控渲染，无 innerHTML；深浅主题可读；Windows+macOS 路径 mono 不断版。

### 页面 11 · 提交差异摘要（单页 · greenfield）

**五要素**
- **场景**：命令 `SVN：打开差异对比` 或提交前"查看本次提交差异总览"触发；对当前选中/范围文件跑 `svn diff --internal-diff`，给出逐文件差异概览，并逐文件提供"打开差异对比"入口。
- **受众**：提交前想快速掌握"本次改了哪些文件、各增减多少行"的开发者。
- **调性**：VS Code 原生列表 + 差异语义色（增/删），概览型。
- **规模**：单页 webview。

**功能范围（in-scope，来自 `commitDiffSummary.ts`）**
- 逐文件摘要 `CommitDiffSummary`：`relativePath`、`addedLines`、`deletedLines`、`hunks`、`binary`、`truncated`、`error`。
- 约束：单文件 diff 文本上限 160000 字符（`MAX_DIFF_CHARS_PER_PATH`）、最多 80 个文件（`MAX_DIFF_PATHS`）。
- 仅统计范围内文件（`isPathInScope`），超出范围不纳入。
- 每文件"打开差异对比"动作（触发 `svnWorkbench.openDiff` 命令占位）。
- 顶部总量汇总（文件数、总增/总删、总 hunk）。

**关键 UI 区域 / 内容块**
1. ScopeBar（仓库根 + 右键范围，mono，对齐既有面板）
2. StatusSummary（徽标组：文件数 / 总新增行 green / 总删除行 red / 总 hunk；超 80 文件显"仅显示前 80 个文件"提示）
3. DiffFileList（每行：文件相对路径 mono、`+added` 徽标 `--color-diff-add-fg`、`-deleted` 徽标 `--color-diff-del-fg`、hunk 计数徽标；`binary` 标"二进制"、truncated 标"已截断"；右侧"打开差异对比"图标按钮 `icon-git-compare`）
4. 逐文件错误行（`error` 非空时该行以 error 语义色 + `icon-error` 呈现）
5. 动作按钮：刷新 / 打开全部差异对比（占位）/ 关闭（Secondary）

**必要状态**
- 常态：已统计范围内文件，逐文件增删/hunk 徽标准确，总量汇总正确。
- 加载中：逐文件跑 `svn diff` 进度（可逐行出现，`--color-progress`）。
- **svn 缺失降级（关键）**：核心依赖 `svn diff`；svn 缺失时**不能静默空列表**，须整页/顶部显 warning/error 引导卡（§4.7，指向 `svnWorkbench.svn.path`，"去安装/去配置"动作），说明"无法计算差异"；逐文件 error 行可附同一原因。**不静默退出**（直接对应 `redesign-plan §1.2` 头号根因）。
- 部分失败态：个别文件 `svn diff` 非零退出 → 该行 error 标记，其余正常，不阻断整页。
- 截断态：超 80 文件或单文件超 160000 字符 → 显"已截断/仅显示前 N 个"提示（info 语义）。
- 空态：范围内无选中文件 → info 卡"当前范围没有可统计的差异文件"。

**硬验收项**
- 全部令牌化；差异增/删色严格用 `--color-diff-add-fg` / `--color-diff-del-fg`（§1.3），不引入其它红绿；hunk/binary/truncated 用中性色（§9.5）。
- 仅统计范围内文件（范围不扩大原则，§3.6）；超 80 文件 / 16 万字符截断提示明确。
- **svn 缺失时必须显示引导卡，不静默空列表、不抛错阻断**（§3.3 环境门禁一致）。
- 逐文件"打开差异对比"入口清晰，命令占位不绑定实现。
- 列表/徽标/状态卡严格按 §4.3/§4.4/§4.7；深浅主题可读；路径 mono 不断版（含中文/空格路径样例）。
- Svelte 受控渲染，无 innerHTML。
