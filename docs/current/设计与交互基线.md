# SVN Workbench 设计与交互基线

> 状态：CURRENT，作为当前产品与交互规范。
> 基线版本：v0.0.3 发布线
> 适用范围：Svelte Workbench Shell、全部业务模块、右键深链接、中文文案与 Webview 验收。  
> 关系说明：本文不改变 [`产品与功能基线.md`](./产品与功能基线.md) 的功能边界；涉及中文体验、页面结构、局部滚动和真实视口验收时，以本文为准。

## 1. 结论

下一轮页面改造不应继续增加“大而全”的工作台内容，而应优先解决四个直接影响日常使用的问题：

1. **中文优先但不是简单翻译**：主界面、状态、时间、数量、错误、确认和恢复说明遵循中文用户习惯；SVN、AI、URL、Patch 等必要技术名词可以保留，但不能让英文成为主要信息层级。
2. **右键直达具体任务**：从 Explorer、编辑器、SCM 或 Svelte 文件树发起命令后，直接打开当前功能模块或模块内的具体子任务，不先展示整个仓库工具长页面。
3. **所有内容始终可达**：主页面和小区域都必须有明确滚动归属。列表、历史、冲突、属性、诊断、命令预览等内容超过区域高度时，必须能够通过鼠标、触控板和键盘滚动到最后一项。
4. **测试真实视口，不用完整截图代替可用性**：全页截图继续用于视觉评审，但不得通过临时取消 `overflow` 来证明页面可用；必须新增真实高度、真实局部滚动和底部操作可达性测试。

中文一致性、局部滚动和真实视口测试属于持续门禁；任一门禁失败时，不得把“页面完整可用”判定为通过。

## 2. 当前审查结论

### 2.1 已经具备的基础

- `src/webview/index.html` 已声明 `lang="zh-CN"`。
- Workbench 已采用单一 Svelte 5 Shell，功能模块按需加载。
- 根内容区 `.workbench-content` 已允许滚动。
- 文件列表、修订列表、属性列表、仓库浏览器等部分区域已使用 `overflow:auto`。
- 已有 720、1024、1440 三档宽度，Light、Dark、High Contrast 三主题和 axe 自动化检查。
- 5000 文件列表已经窗口化，并有滚动到末尾的性能测试。

这些能力证明架构方向正确，但还不足以覆盖中文产品体验和局部内容可达性。

### 2.3 测试结论应如何修正

现有自动化仍有价值，但要区分三类证据：

- **完整内容截图**：验证信息结构、视觉密度和主题，不证明真实滚动。
- **真实视口截图**：不注入布局覆盖样式，验证用户首次看到的内容和滚动提示。
- **交互可达性测试**：实际滚动局部容器，证明最后一项和底部主操作能够到达。

axe 能发现语义和对比度等问题，但不会自动判断“某个按钮被 `overflow:hidden` 永久裁掉”，因此不能单独作为页面可达性结论。

## 3. 中文用户体验规范

### 3.1 中文优先原则

1. 页面标题、模块名、状态、按钮、说明、错误、空状态、恢复建议和确认文字以简体中文为主。
2. 英文缩写仅在中国开发者普遍使用且翻译会降低辨识度时保留，例如 `SVN`、`AI`、`URL`、`API`、`SHA-256`、`Patch`。
3. Branch、Tag、Switch、Merge、Relocate 第一次出现时采用“中文名称（SVN 命令）”，同一任务后续可只显示中文或命令名。
4. 路径、仓库 URL、命令、属性名、revision 和代码内容必须保持原文，不做中文化转换。
5. 英文不能作为比中文更醒目的眉题。眉题应改成中文任务类别，必要技术词作为次级说明。

### 3.3 中文文案风格

- 按钮使用“动词 + 对象”，例如“查看修改”“生成更新预览”“重新检查”“确认还原 3 个文件”。
- 危险按钮必须写出动作和数量，不使用含义模糊的“确定”“继续”。
- 成功提示先说结果，再给下一步，例如“已更新到 r128；检测到 2 个冲突，请前往冲突处理”。
- 错误提示采用“发生了什么 → 可能原因 → 可以怎么做”，不要直接暴露原始异常作为唯一内容。
- 中文正文使用全角标点；路径、命令和代码内部保持半角符号。
- 数量使用“已选择 2/5 个文件”，避免空格分隔的 `2 / 5` 形成英文排版感。
- 技术说明尽量避免被动句和长复合句；单个帮助文本建议不超过两行，详细说明放入可展开区域。
- 不用全大写英文和过大的字间距制造层级。高级感来自信息层级、留白、对齐和克制的颜色，而不是英文装饰词。

### 3.4 时间、数字和排序

- 集中使用 `Intl.DateTimeFormat('zh-CN', { hour12: false, ... })`，禁止业务组件各自调用无参数 `toLocaleString()`。
- 当天显示“今天 17:05”，昨天显示“昨天 17:05”，更早显示“2026-07-31 17:05”；悬停或详情提供完整时间和时区。
- 相对时间用于辅助，不替代精确时间，例如“3 分钟前（17:05）”。
- 文件大小按中文常用方式显示，如 `12.4 MB`；数量与中文量词相连，如“12 个文件”“3 条修订”。
- 历史列表默认按修订版本倒序；同版本文件路径按中文用户可预期的自然排序，同时保留大小写和原路径显示。

### 3.5 中文输入法和文本输入

- 提交说明、AI 目标、搜索、属性值和仓库提交说明必须正确处理 IME composition。
- 中文输入法候选状态下按 Enter 不得触发提交、搜索执行或确认操作。
- 快捷提交只能使用显式组合键，并在界面中提示；单独 Enter 仅换行或确认输入法候选。
- 搜索应支持中文文件名、空格、括号、`#` 和大小写混合路径。
- 文本截断后必须可以通过 Tooltip、复制或详情查看完整内容。

### 3.6 文案工程化

即使当前只发布中文版本，也应建立轻量中文资源层，避免同一状态在不同 Svelte 模块重复硬编码：

```text
src/webview/i18n/
├── zh-CN.ts
├── terminology.ts
└── formatters.ts
```

建议集中管理：

- SVN 状态、选择状态、风险等级和操作名称映射。
- 日期、时间、文件数、修订数和文件大小格式化。
- 公共错误、空状态、加载、取消、过期和降级文案。
- 允许保留英文的技术词白名单。

不要求本轮同时实现多语言切换，但不得继续让每个页面自行决定中文翻译。

## 4. 页面结构优化

### 4.1 保持“右键任务优先”

右键命令必须携带 `moduleId + taskId + operationScope`。Workbench 打开后只展示当前任务需要的信息：

```text
Explorer / SCM / 编辑器右键
          ↓
解析仓库与操作范围
          ↓
打开 Svelte 模块的具体 taskId
          ↓
预览 → 确认 → 执行 → 结果与下一步
```

示例：

| 入口           | 直接打开                  | 不应先展示                        |
| -------------- | ------------------------- | --------------------------------- |
| 更新此范围     | Repository / Update       | 仓库浏览器、Patch、属性、发布说明 |
| Cleanup 与恢复 | Repository / Recovery     | Branch、Tag、Merge 表单           |
| SVN 属性       | Repository / Properties   | 更新和发布说明卡片                |
| 创建分支       | Repository / Branch 向导  | 所有高级操作并排长页面            |
| 查看历史       | History / RevisionList    | Changes 首页                      |
| 解释当前修改   | AI Review / ExplainChange | 完整 AI 能力总览                  |

用户可以通过次级导航切换到相关任务，但默认页面不能因为“功能完整”而同时铺开所有低频功能。

### 4.2 Shell 与左侧导航

- 当前任务标题、仓库和范围保持可见；技术性的仓库 UUID、scope hash 只在诊断或详情中出现。
- 宽度充足时，左侧 Rail 可在悬停或用户主动展开后显示中文模块名；收起状态保留图标和 Tooltip。
- 模块按“日常、智能、仓库与设置”分组，低频入口放入“更多”，避免十多个同权重图标。
- 低高度时 Rail 采用紧凑间距或自身滚动，诊断和设置不能被挤出可见区域。
- 右键深链接进入后，将键盘焦点放到任务标题或第一个可操作控件，并由屏幕阅读器播报当前范围。

### 4.3 ScopeBar

推荐顺序：

1. 当前任务，例如“提交当前文件夹”。
2. 操作范围，例如 `src/order · 12 个文件`。
3. 所属工作副本，例如 `vscode-svn · r128`。
4. 刷新、复制路径和切换仓库等次级操作。

长路径默认中间省略，悬停显示完整值；混合仓库、external、范围变化和结果过期使用明确中文提示，不能只依赖图标或颜色。

### 4.4 信息层级和视觉风格

- 每页只保留一个主标题和一个当前主操作。
- 卡片用于表达独立任务、风险或可折叠信息，不为每组字段机械增加边框。
- 同一屏幕避免三层以上边框嵌套；优先使用 12/16/24px 间距、字体权重和分隔线建立层级。
- 中文正文行高建议 1.5～1.65；帮助文字不能低于 VS Code 可读字号，也不能用过淡颜色表达关键限制。
- 状态色仅作为辅助，必须同时显示状态文字和图标。
- AI 使用与普通 SVN 操作一致的布局，只在入口和结果来源上使用克制的辅助强调，不构建一套紫色“AI 世界”。
- 主按钮保持稳定位置；危险操作使用危险语义色，并与普通主按钮有明显区分。

### 4.5 模块级优化

## 5. 局部滚动与内容可达性规范

### 5.1 滚动归属

每个页面必须在设计和代码中明确谁负责滚动。禁止依赖“内容自然撑开后总能在某处滚动”。

| 层级                   | 规则                                                   |
| ---------------------- | ------------------------------------------------------ |
| Webview 根             | 保持固定为当前编辑器区域，不承担浏览器页面级滚动       |
| Workbench Shell        | `height:100%`、`min-height:0`、`overflow:hidden`       |
| 单栏功能页             | `.workbench-content` 可以作为唯一纵向滚动容器          |
| 双栏/三栏功能页        | 页面容器固定在可用高度，每个需要长内容的 Pane 自己滚动 |
| 列表、代码、日志、预览 | 使用统一 `ScrollArea`；设置语义名称并允许键盘聚焦      |
| Dialog/Sheet           | 内容区滚动，标题与操作栏保持可见；不得让按钮落到视口外 |

同一方向最多保留两层可滚动区域：模块主体和一个明确的局部 Pane。无明确理由不得出现三层嵌套滚动。

### 5.2 布局基础要求

所有位于 flex/grid 滚动链上的祖先必须设置正确的尺寸收缩规则：

```css
.workbench-main,
.feature-frame,
.feature-pane {
  min-width: 0;
  min-height: 0;
}

.workbench-main,
.feature-frame {
  height: 100%;
  overflow: hidden;
}

.scroll-region {
  min-height: 0;
  overflow: auto;
  overscroll-behavior: contain;
  scrollbar-gutter: stable;
  scroll-padding-block: 40px;
}
```

`overflow:hidden` 只允许用于 Shell 边界、圆角裁切或明确的视觉容器，不能直接放在承载不定长业务内容的元素上。若外层卡片需要圆角裁切，应把真正内容放入内部 `.scroll-region`。

### 5.3 滚动条视觉

局部区域不能只依赖操作系统默认覆盖式滚动条。统一 ScrollArea 至少满足：

- 使用 `--vscode-scrollbarSlider-background`、`--vscode-scrollbarSlider-hoverBackground` 和 `--vscode-scrollbarSlider-activeBackground`。
- 垂直滚动条可点击宽度建议 10px 左右；高对比度主题下边界清楚。
- 使用 `scrollbar-gutter:stable`，避免滚动条出现后内容宽度跳动。
- 区域可滚动时，在顶部/底部显示轻微滚动阴影或渐隐提示；滚动到边界后消失。
- 鼠标悬停、触控板滚动、键盘聚焦时滚动条反馈增强。
- 滚动条不能覆盖列表最后一列操作按钮。
- 横向滚动只允许出现在代码、命令、Diff 和无法合理换行的技术内容中。

### 5.4 键盘和可访问性

- 独立滚动区使用 `role="region"`、可理解的 `aria-label`，并能通过 Tab 聚焦。
- 聚焦后支持方向键、PageUp、PageDown、Home、End；焦点项始终滚入可见区域。
- Sticky 标题和操作栏不能覆盖被聚焦内容，应配置 `scroll-padding`。
- 滚动区到达边界后，用户能够继续 Tab 到下一个区域，不形成键盘陷阱。
- 屏幕阅读器应能区分“提交候选文件”“修订列表”“冲突文件”“原始命令输出”等区域。
- `prefers-reduced-motion` 下关闭平滑滚动和不必要的滚动阴影动画。

### 5.5 小高度和缩放

除宽度外，必须覆盖高度与缩放：

- 高度：480、600、720、900px。
- 宽度：720、1024、1440px。
- VS Code/Webview 缩放：100%、125%、150%、200%。
- 分屏、底部 Terminal/Problems 面板展开、禅模式和左侧栏宽度变化。

在 720×480 和 200% 缩放下，允许信息转为单列、折叠或分步骤，但不允许：

- 主操作永久不可达。
- 警告或精确范围被裁掉。
- 只能依赖横向页面滚动。
- 左侧模块入口完全消失且没有替代入口。
- 滚动时丢失当前仓库、范围或危险操作上下文。

### 5.6 Sticky 区域

建议保持可见：

- 列表的筛选/选择摘要。
- Diff/冲突的文件名和比较基线。
- 长表单的当前任务标题。
- Dialog 的标题和底部操作栏。

危险操作按钮只有在同一 Sticky 区域同时显示操作对象和风险摘要时才能固定；不能让“确认删除/还原”脱离其精确影响清单。

## 6. AI 能力的中文体验优化

AI 需要更有用，而不是增加更多孤立按钮：

1. **入口贴近任务**：提交页提供选文件、生成说明和提交前审查；冲突页提供意图解释和合并候选；历史页提供修订摘要；不要求用户先进入 AI 首页。
2. **使用中文解释证据**：结论采用“发现 → 证据 → 影响 → 建议操作”，文件路径、行号和命令保持原文。
3. **默认贴合中国团队习惯**：支持常见 `feat/fix` 规范，也允许“需求/缺陷/优化/重构”等中文模板和工单号格式。
4. **解释外发内容**：用自然中文显示“将发送 8 个文件的路径、状态和最多 20,000 个差异字符；不会发送文件正文以外的仓库内容”。
5. **模型失败可继续工作**：显示失败原因并保留当前选择，提供“应用本地规则”恢复动作，基础 SVN 操作和手动编辑保持可用；不把本地规则结果静默包装成 AI 来源。
6. **结果可继续处理**：审查结论可定位文件、加入待办、忽略并记录理由；测试建议可复制命令或形成清单；拆分建议可转为 Changelist 后继续人工调整。
7. **避免中文输入误触发**：AI 目标输入框必须正确处理中文输入法候选状态。

可补充但不应阻塞 P0 的 AI 能力：

- 根据当前差异生成中文变更摘要和评审重点。
- 根据 SVN 历史总结某个模块的演进和可能责任人。
- 结合改动范围给出测试优先级、失败模式和上线观察项。
- 为冲突双方生成“保留我的/保留对方/组合方案”的中文差异解释。
- 对即将执行的 Switch、Merge、Revert 给出风险解释，但不代替人工批准。

## 10. 人工验收脚本

1. 将 VS Code 编辑器区域调整为约 720×480，底部打开 Terminal。
2. 在 Explorer 右键中文文件夹，分别进入提交、更新、历史和属性；确认直接到对应任务。
3. 在每个小列表中滚到最后一项，再使用键盘 Home/End 和 PageUp/PageDown。
4. 将 VS Code 缩放调整到 150% 和 200%，检查范围、警告和主操作是否可达。
5. 使用中文输入法在提交说明和 AI 目标中输入多段文字；候选状态按 Enter 不得误执行。
6. 检查 Commit 中的文件状态、Repository 中的操作标题、Settings 中的字段名和所有时间格式是否一致中文化。
7. 模拟长路径、20 条修订、50 个冲突、多个属性、长诊断输出和长 AI 结论。
8. 使用鼠标滚轮、触控板和键盘分别滚动；确认滚动区域边界和滚动反馈清晰。
9. 切换 Light、Dark、High Contrast，检查滚动条、焦点框、危险提示和禁用状态。
10. 关闭 AI 后重复提交、更新、Diff、历史和冲突手动流程。

人工验收必须在真实 VS Code Webview 和干净安装的 VSIX 中各执行一次，不能只在 Vite 浏览器 Mock 页面完成。
