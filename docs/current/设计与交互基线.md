# SVN Workbench 设计与交互基线

> 文档身份：`current-design-baseline`
>
> 状态：CURRENT。
>
> 负责：中文体验、任务结构、布局、滚动、焦点、IME、主题和可访问性。
>
> 不负责：功能优先级见 [`产品与功能基线.md`](./产品与功能基线.md)；源码位置见 [`实现与代码映射.md`](./实现与代码映射.md)；测试矩阵见 [`测试与验收基线.md`](./测试与验收基线.md)。

## 1. 核心原则

1. **右键任务优先**：入口直接打开 `moduleId + taskId + operationScope` 对应任务，不先展示无关功能总览。
2. **中文优先**：标题、状态、按钮、说明、错误、空态、恢复和确认以简体中文为主；路径、命令、协议字段和必要技术术语保持原文。
3. **范围始终可见**：用户能看见当前任务、仓库和操作范围；筛选、模板、Changelist 和 AI 只能缩小范围。
4. **主操作始终可达**：小高度和 200% 缩放下，范围、警告、恢复动作和主操作不得被永久裁掉。
5. **状态不只靠颜色**：同时使用文字、图标、形状、行号或 `+`/`-` 等信息。
6. **危险操作准确具体**：按钮写明动作、对象和数量，执行前显示范围、影响和恢复方式。
7. **AI 是可选增强**：模型失败时保持本地规则、手动流程和核心 SVN 能力。

## 2. 中文与术语

### 2.1 保留英文的边界

可保留开发者普遍使用且翻译会降低辨识度的词：`SVN`、`AI`、`URL`、`API`、`SHA-256`、`Patch`。Branch、Tag、Switch、Merge、Relocate 首次出现时使用“中文名称（命令名）”。

不得使用全大写英文眉题制造主要层级。产品名称可以是 `SVN Workbench`，页面内优先写“SVN 工作台”。

### 2.2 统一术语

| 原始词                                         | 界面主文案                                     |
| ---------------------------------------------- | ---------------------------------------------- |
| Working Copy                                   | 工作副本                                       |
| Repository                                     | 仓库                                           |
| Revision                                       | 修订版本                                       |
| Commit / Commit Message                        | 提交 / 提交说明                                |
| Changes                                        | 本地修改                                       |
| Changelist                                     | 变更集（Changelist）                           |
| modified / added / deleted                     | 已修改 / 已新增 / 已删除                       |
| missing / unversioned                          | 文件缺失 / 未纳入版本控制                      |
| conflicted                                     | 存在冲突                                       |
| Cleanup                                        | 清理工作副本（Cleanup）                        |
| Switch / Merge / Relocate                      | 切换工作副本 / 合并到工作副本 / 重定位仓库地址 |
| Provider / Base URL / API Key                  | 模型服务商 / 接口地址 / API 密钥               |
| recommended / needsReview / excluded / blocked | 推荐提交 / 需要确认 / 排除 / 阻止提交          |

统一术语优先复用 `src/webview/i18n/`，不要在单个页面创造同义文案。

### 2.3 文案结构

- 按钮使用“动词 + 对象”，例如“生成更新预览”“确认还原 3 个文件”。
- 错误采用“发生了什么 → 可能原因 → 可以怎么做”。
- 成功提示先给结果，再给下一步。
- 中文正文使用全角标点；路径、命令和代码内部保持原文。
- 数量使用“已选择 2/5 个文件”“3 条修订”。
- 长路径和截断文本必须可以通过 Tooltip、复制或详情查看完整内容。

### 2.4 时间与数字

统一使用 `Intl.DateTimeFormat('zh-CN', { hour12: false, ... })`。当天可显示“今天 17:05”，更早显示“2026-07-31 17:05”；详情提供完整时间与时区。文件大小使用 `12.4 MB`，数量配中文量词。

## 3. 输入、键盘与焦点

### 3.1 中文 IME

提交说明、AI 目标、搜索、替换、属性值和仓库提交说明必须处理 composition：

- 候选阶段 Enter 不触发提交、搜索、替换、保存、确认或 AI 执行；
- 快捷执行使用显式组合键；
- Esc 先正确处理输入法或当前浮层，不得误退出整个任务；
- 覆盖中文文件名、空格、括号和 `#`。

### 3.2 焦点

- 用户显式打开任务后，焦点进入任务标题或第一个可操作控件，并播报范围。
- 后台刷新不得抢焦点。
- Dialog 打开时焦点进入 Dialog，关闭后回到触发控件。
- 独立滚动区可通过 Tab 进入和离开，不形成键盘陷阱。
- Sticky 区域不得覆盖当前焦点项。

### 3.3 动效

动效仅用于短暂反馈和状态变化。`prefers-reduced-motion` 下关闭平滑滚动、闪烁、非必要过渡和装饰动画。

## 4. 任务与页面结构

标准任务流：

```text
入口 → 解析仓库与范围 → 打开具体任务 → 预览 → 确认 → 执行 → 结果与恢复
```

- 每页只保留一个主标题和一个当前主操作。
- 当前任务、仓库和范围保持可见；UUID、scope hash 等技术信息进入诊断或详情。
- 模块内可切换相关任务，但默认首屏不铺开所有低频工具。
- 卡片只表达独立任务、风险或可折叠信息；避免三层以上边框嵌套。
- 状态色、危险色和 AI 辅助色必须使用 VS Code 主题变量，并在 High Contrast 下可辨识。
- 自 `v0.0.5` 起每个功能模块使用独立 Webview 窗口：Shell 不再展示模块总览列表（Rail 已移除），入口（右键/命令/模块内动作）直接打开目标模块窗口；模块内任务导航、空态、错误页和设置页保留必要关联入口。窗口内不得出现页面级横向滚动；显式打开会激活目标窗口并把焦点放到标题或第一个可操作控件，后台刷新不得抢焦点。

## 5. 范围与操作反馈

推荐范围栏顺序：

1. 当前任务；
2. 操作范围和文件数；
3. 所属工作副本和修订版本；
4. 刷新、复制路径等次级操作。

范围变化、混合仓库、external、工作副本切换和结果过期必须显示中文提示。旧预览、旧确认令牌和旧 AI 结果不得继续可用。

Commit、Update、Resolve、Revert、Delete、Switch、Relocate、Merge 和历史恢复必须：

- 先显示准确预览；
- 明确动作和影响数量；
- 允许用户检查完整范围；
- 用户确认后在 Host 重新校验；
- 失败后保留恢复或重试入口。

## 6. 滚动与布局

### 6.1 滚动归属

| 层级                   | 规则                                             |
| ---------------------- | ------------------------------------------------ |
| Webview 根             | 固定为编辑器区域，不承担浏览器页面级滚动         |
| Workbench Shell        | `height:100%`、`min-height:0`、`overflow:hidden` |
| 单栏页面               | 模块内容区作为唯一纵向滚动容器                   |
| 双栏/三栏页面          | 页面固定高度，各长内容 Pane 独立滚动             |
| 列表、代码、日志、预览 | 使用明确命名、可聚焦的滚动区域                   |
| Dialog/Sheet           | 标题和操作栏保持可见，内容区滚动                 |

同一方向最多两层滚动。不得用全局 `overflow:auto !important` 掩盖布局问题。

Flex/Grid 滚动链上的祖先必须正确设置 `min-width:0`、`min-height:0`。横向滚动只允许出现在代码、命令、Diff 和无法合理换行的技术内容中。

### 6.2 滚动反馈

- 使用 VS Code scrollbar tokens；High Contrast 下边界清晰。
- 使用稳定 gutter，避免滚动条出现时布局跳动。
- 滚动条不得覆盖末列操作。
- 可滚动区域有可理解的 `aria-label`，支持 PageUp/PageDown/Home/End。
- 代码区滚动不得带走文件头、范围、警告和工具栏。

### 6.3 视口和缩放

设计必须适配：

- 高度：480、600、720、900px；
- 宽度：720、1024、1440px；
- 缩放：100%、125%、150%、200%；
- 分屏和底部 Terminal/Problems 展开。

在 720×480 和 200% 下可以改为单列、折叠或分步骤，但不允许主操作、警告、范围和恢复入口永久不可达，也不允许页面级横向滚动。

## 7. 模块最低交互要求

| 模块                       | 必须保持的上下文与滚动区                            |
| -------------------------- | --------------------------------------------------- |
| Changes                    | 筛选、选择摘要；文件列表独立滚动                    |
| Commit                     | 候选文件与提交说明/检查分区；窄屏按任务顺序排列     |
| Diff                       | 文件名和比较基线固定；长行只在代码区横向滚动        |
| History                    | 修订列表、详情、Changed Paths 和 Blame 各有明确归属 |
| Conflicts                  | 冲突文件、编辑器、证据和解决确认可达                |
| Changelists                | 宽屏多栏独立滚动，窄屏使用步骤或 Tabs               |
| AI Review / Impact / Agent | 结果、证据、计划、命令输出可独立浏览；来源如实显示  |
| Repository                 | 按 taskId 展示当前子任务，不默认铺开全部高级工具    |
| Settings                   | 配置中文化；高级字段渐进展开；保存反馈靠近表单      |
| Diagnostics                | 结论和修复动作优先，原始输出次级展示                |

### 7.1 Diff 窗口与编辑器出口

- Diff 使用独立只读模块窗口。用户显式打开时激活目标标签；`sameGroup` 默认复用当前编辑组，`beside` 用于需要并排查看的场景。
- 同一仓库、范围、文件或修订目标重复打开时只 reveal 现有 Diff，不重新初始化或破坏当前阅读位置；后台刷新不得主动抢焦点。
- Working Copy ↔ BASE 提供“在编辑器中对比”：VS Code 原生 Diff 左侧为只读 BASE，右侧为当前工作副本；Webview 本身仍保持只读。
- 修订比较保持双侧只读，不显示原生编辑器对比入口；二进制或超过 5 MB 的内容禁用该入口，并显示具体原因与可恢复动作。

### 7.3 高密度列表交互（v0.0.8；v0.0.10 推广到全部适用模块）

- 路径单元格两行展示：第一行文件名（保留扩展名），第二行项目内父目录，
  中部省略保留文件名与辨识目录；文本可选择；完整路径经路径详情查看，
  不把 `title` 当唯一出口。
- 语义列头使用 `role=columnheader` + `aria-sort`，方向同时有图标与中文
  文字；小屏用排序菜单保留同等能力；提供“恢复默认顺序”。
- 表头三态只作用于当前筛选可操作项；批量动作收拢在列表内 Sticky 底栏，
  按钮写明动作与数量（如“检查并提交所选（7）”）。
- 选中、焦点、悬停与阻止行分别用背景、轮廓与文字区分，不只靠颜色；
  读屏行名称包含项目名、完整项目内路径、状态与选择状态。
- 列表内 `Ctrl/⌘+A` 幂等选择当前筛选可操作项（连按不反向清空，不劫持
  搜索框、文本域与 IME 候选）；`PageUp/PageDown` 是活动行分页导航（按一页
  可见行数移动活动行并滚动到该行），不是仅原生滚动；`Shift+F10` 或
  Menu 键打开活动行的操作菜单（无活动行时放行原生行为）；
  `Escape` 关闭打开的路径详情并恢复触发点焦点（滚动位置不变），该处理
  先于空列表早退，详情响应到达后候选刷新为空时仍可关闭。
- v0.0.10 跨模块一致：上述手势与“搜索清除、结果数量（`N 个结果`）”
  由共享层（`SearchInput`/`ResultCount`/`useFileList`/`PathCell`/
  `FilePathDetail`/`PreviewPathList`）提供，Changelists、History、
  Conflicts、Repository Browser、Properties、写操作预览清单、Settings
  规则预览、Diagnostics 与只读的 Review/Impact/Diff 复用同一语义；
  相同图标或快捷键在不同页面不得有不同含义。
- 模块可按数据形态减少不适用能力：修订比较固定 2 条（无全选）、
  Conflict 不提供批量 Resolve、Agent 步骤与 AI 建议保持有意顺序不排序、
  写操作确认页清单不可勾选（改范围必须返回上一步重新预览）、只读页面
  不为形式增加复选框。筛选选项从当前数据推导，不虚构不存在的取值。

### 7.2 保存后权威快照刷新与编辑会话保持（v0.0.6）

- 初始进入模块且尚无快照时显示全屏加载；已有快照的刷新（如保存后 Host 重新读取磁盘）保持模块挂载，仅显示轻量“正在刷新当前范围…”提示条，不卸载编辑器、不打断正在进行的输入，后台刷新不抢焦点。
- 编辑态保存成功后：Host 重新加载模块并以磁盘内容刷新权威快照（modified/draft/message 以磁盘为准）；DiffView 编辑态同目标、同容器刷新保持 FileDiff/Editor 实例（快速二次输入不丢失）；只读态刷新重建以采用权威内容；目标切换、退出编辑或视图切换才重建。
- `diff/save-result` 按消息对象只消费一次：随后的快照刷新/重渲染不得重放同一成功结果、清掉第二轮脏状态。

## 8. AI 交互

- AI 入口贴近提交、冲突、历史和影响分析任务。
- 外发前显示模型、数据类型、文件范围、字符/文件预算和是否包含历史。
- 结果使用“发现 → 证据 → 影响 → 建议操作”，并标明来源和置信度。
- AI 结果必须经过路径、范围、候选集合和时效复验。
- 模型未配置、超时或结果无效时，保留当前选择、本地规则和手动操作。
- 冲突建议按钮随配置如实命名：配置外部模型时显示“AI 分析”，未配置时显示“本地建议”
  且隐私说明改为“不会外发”，不把纯本地动作标成 AI（v0.0.9 终审缺陷修复）。
- AI 只能生成建议、草稿或候选，不能执行 SVN 写操作。

### 8.1 提交说明建议草稿（v0.0.9 §4）

- “生成提交说明”改为“生成建议草稿”：无论模型结果还是本地回退都不得直接覆盖
  用户已填写的提交说明；生成、失败、超时、取消、降级、过期均保持原草稿不变。
- 建议区旁侧展示：保留当前草稿、选择区与光标；标明来源（本地检查/模型建议/模型不可用，已保留本地结果）、
  模型与“生成输入仅包含文件信息与差异统计，不能证明具体行为”；本地回退占位草稿标记“基于文件信息”。
- 展示与当前草稿的行级差异（新增/将移除行）。
- 提供“插入空白字段 / 替换草稿 / 复制建议 / 放弃”：插入只补充“标签:”为空的空白字段，
  不删除、不改写用户已填内容；替换前写明字符数并二次确认，替换后提供“撤销替换”恢复原草稿。
- 范围或候选变化后建议只读（过期标记），只能查看、复制或放弃，不能采用；用户草稿继续保留。
- 替换被拒（与草稿相同、超过字符上限等）时界面回滚到原草稿，不保留建议文本；
  Host 在拒绝后补发权威快照供 Webview 收敛本地输入（缺陷修复，v0.0.9 终审）。
- 用户手动编辑、套用模板或再次采用后，替换前备份失效（撤销只对“替换后未编辑”承诺）。

### 8.2 受限差异外发回执与有证据的提交说明（v0.0.11）

- 生成输入模式默认“仅文件信息”；选择“含差异（需确认）”后点击生成先展示
  外发回执（`commit/preview-receipt` 只采集/脱敏/裁剪并下发 `commit/receipt`，
  不调用模型）。
- 回执面板展示：任务、模型、数据类型、文件数、单文件/总字符预算、是否
  包含历史、差异覆盖率（已分析/截断/二进制/读取失败/预算外）、可展开的
  包含 / 排除文件清单、明确不会发送的数据、无法由插件证明的服务商保留
  策略提示。
- 回执提供三动作：“开始模型生成”（携带一次性回执 token 确认，Host 校验
  后调用模型）、“继续仅文件信息”（放弃回执并按仅文件信息生成）、“放弃”
  （放弃回执，不外发）。取消后说明是否已经完成外发。
- 受限差异生成的建议展示差异覆盖率与证据引用：每条具体陈述关联可打开
  的 Host 证据（有效证据提供“打开差异”入口，Host 复验 token/时效/候选/范围
  后路由到该文件 Diff），无效/过期引用如实标注原因；仅文件信息模式明确声明
  “基于文件信息生成，未读取差异正文”，不声称理解具体行为。
- §5 逐条声明：受限差异建议可展示逐条说明及状态（已证实 / 推断 / 待确认）；
  模型标为“已证实”但缺少可核对 Host 证据的声明由 Host 强制降级为“待确认”
  并标注“已降级”，每条声明证据同样可“打开差异”；仅文件信息模式不生成
  逐条声明，只保留整体级提示。
- 工单号：v0.0.11 不新增专用工单号输入框；团队规范要求真实工单号时在正文
  填写、沿用现有格式校验，AI 不编造工单号。

### 8.3 变更解读（v0.0.12 批次 A）

- 变更解读页首屏说明用途、项目范围、来源与下一步；“查看并开始分析 N 个文件”
  与“只运行本地检查”始终可达（过期/运行中禁用），并声明 AI 不会修改文件或执行提交。
- 受限差异外发回执复用 v0.0.11 交互（任务/模型/数据类型/预算/覆盖率/包含排除
  清单/不会发送项/保留策略），提供“开始模型分析”“继续仅本地检查”“放弃”三动作；
  独立 `understanding/receipt` 消息，不改动已发布 commit/receipt。
- 结果按四段展示：这次改了什么（状态：已证实/推断/待确认，来源逐条标记）、
  需要你确认（本地阻止项/模型发现/证据不足/业务未知分开）、影响与验证（每条
  说明验证哪项风险，命令仅展示不执行）、准备提交（基于会话内确认的只读建议）。
- 每条有效证据提供“打开差异”（Host 复验 token/时效/候选/范围后路由到 Diff）；
  无效/过期证据如实标注原因。
- 会话内确认：输入带 IME 保护（候选阶段 Enter 不触发）；确认绑定候选 hash，
  范围/候选/revision 变化标“待复核”且绝不静默沿用；切换项目前由切换守卫提示
  会话内确认将失效。
- 过期结果只读（禁止打开证据/采用），重新分析恢复；空/部分/失败/离线状态均
  有明确恢复动作与中文说明。

### 8.4 提交说明接入确认与按改动意图拆分（v0.0.12 批次 B）

- 提交说明建议如实标注“已使用 N 条变更解读中的会话内确认事实”；过期/待复核确认
  不会进入模型，建议仍不覆盖草稿、可插入/替换/撤销（v0.0.11 契约不变）。
- 按改动意图拆分：入口在变更集页“按改动意图拆分（含差异需确认）”，先展示独立回执
  （任务/模型/数据类型/预算/覆盖率/包含排除清单/不会发送项），提供“开始语义拆分”
  “继续仅目录分组”“放弃”三动作；无差异时明确降级为目录/文件类型分组并如实说明。
- 语义拆分建议展示目的、依赖与风险；模型永不加入范围外文件；同文件不得进入两个
  实际 Changelist（Host 预览与执行均复验）；实际套用保留既有预览→确认→写入链路。
- 变更解读“准备提交”区提供“按改动意图拆分（进入变更集）”入口。
- 冲突意图解释（§7 六段）：冲突页“解释冲突意图”先展示独立回执（任务/模型/
  数据类型/逐文件字符预算/截断与读取失败），提供“开始解释”“继续仅本地建议”
  “放弃”；结果按六段展示，验证命令仅以代码样式展示不执行；冲突集或修订变化后
  解释标过期只读；保存与 Resolve 仍走既有确认契约。

- 部分完成可“只重试失败项”：建议的逐文件覆盖情况展示读取失败/预算外的
  文件；提供“重试失败项（N）”入口，仅对失败项重新采集并重新展示外发回执，
  确认后生成的新建议替换旧建议（用户草稿始终不变）。建议过期时不显示重试
  入口、禁用打开证据。
- 回执是等待确认的一次性状态：任何快照或错误到达后清除，不残留面板；
  范围或候选变化后回执失效（fail-closed），再次生成需重新确认。

## 9. 设计完成条件

一个新增或修改的页面只有同时满足以下条件才完成：

- 入口直达正确 `moduleId + taskId + operationScope`；
- 中文术语和时间格式一致；
- 正常、加载、空、失败、取消、过期和恢复状态明确；
- 危险操作展示动作、对象、数量和恢复方式；
- 键盘、读屏和 IME 可用；
- Light、Dark、High Contrast 均不只依赖颜色；
- 720×480 和 200% 下主操作、范围、警告与恢复可达；
- 没有页面级横向滚动和无归属的嵌套滚动；
- 对应测试按 [`测试与验收基线.md`](./测试与验收基线.md) 补齐。
