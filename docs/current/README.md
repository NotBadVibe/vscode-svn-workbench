## 权威顺序

发生冲突时依次采用：

1. 实际源码、协议类型和自动化测试；
2. 当前基线中负责该领域的主权威；
3. 开发中版本计划；
4. 已发布版本记录；
5. 历史归档。

若代码与 current 不一致，应先判断是实现缺陷还是文档滞后，并在同一改动中修复；不得选择较方便的一方作为结论。

## 维护约束

- 一个规则只在负责它的主权威中完整描述，其他文档使用链接引用。
- current 不记录临时 PASS 数、候选 VSIX 指纹、已完成迭代日志或旧方案比较。
- 功能 ID、源码路径、协议 action、测试文件或完成条件变化时同步更新相关基线。
- 所有修改执行 `npm run docs:verify`。
