# SVN Workbench 产品与功能基线

> 文档身份：`current-product-baseline`
>
> 负责：功能 ID、优先级、入口、用户结果和产品完成条件。本文是规范目标清单，不表示每项都已实现；当前实现状态必须由实际代码、测试和 [`实现与代码映射.md`](./实现与代码映射.md) 证明。
>
> 不负责：具体源码位置见 [`实现与代码映射.md`](./实现与代码映射.md)；测试门禁见 [`测试与验收基线.md`](./测试与验收基线.md)；历史原型不作为当前证据。

## 1. 日常核心能力

| ID      | 功能                        | 推荐入口                   | 用户结果                                                                                                                                                              | 优先级 |
| ------- | --------------------------- | -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| CORE-01 | 更新当前范围                | Explorer/Svelte 文件树右键 | 先显示准确预览，再展示进度、结果和冲突恢复入口                                                                                                                        | P0     |
| CORE-02 | 智能提交当前范围            | Explorer/Svelte 文件树右键 | 选择文件、编辑共享草稿、执行提交前检查并确认提交                                                                                                                      | P0     |
| CORE-03 | 查看本地修改                | 文件/文件夹右键            | 在独立只读 Diff 中查看 Working Copy ↔ BASE 或修订比较；默认在当前编辑组激活，也可配置为旁侧打开；单文件 Working Copy ↔ BASE 可继续进入 VS Code 原生 Diff 编辑工作副本 | P0     |
| CORE-04 | 查看文件与目录历史          | 右键/命令面板              | 查看修订列表、详情并进入修订比较                                                                                                                                      | P0     |
| CORE-05 | 冲突处理                    | 冲突资源右键/Svelte 冲突组 | 审阅冲突、编辑候选结果并经预览确认 Resolve                                                                                                                            | P0     |
| CORE-06 | 刷新状态                    | Changes 标题栏/右键        | 重新采集当前范围并使过期结果失效                                                                                                                                      | P0     |
| CORE-07 | Add/Delete/Revert           | 资源右键                   | 显示精确范围、影响数量、恢复方式和确认                                                                                                                                | P1     |
| CORE-08 | Ignore                      | 未版本化资源右键           | 选择目录级或全局忽略规则                                                                                                                                              | P1     |
| CORE-09 | Lock/Unlock                 | 单文件或多选文件右键       | 显示锁状态、目标与执行结果                                                                                                                                            | P1     |
| CORE-10 | SVN Properties              | 文件/目录右键              | 查看、编辑并校验 SVN 属性                                                                                                                                             | P1     |
| CORE-11 | Copy URL/Show in Repository | 文件/目录右键              | 复制仓库 URL 或在仓库浏览器定位                                                                                                                                       | P1     |
| CORE-12 | 提交选择规则                | `settings/selection`       | 编辑作用域、状态策略与路径规则，并预览决策、原因和来源                                                                                                                | P0     |

## 2. Changes 与 Changelist

| ID     | 功能                     | 产品要求                                                | 优先级 |
| ------ | ------------------------ | ------------------------------------------------------- | ------ |
| SCM-01 | 状态分组                 | 区分冲突、修改、新增、删除、缺失、未版本化和 Changelist | P0     |
| SCM-02 | 统一提交草稿             | Changes 与提交模块共享 Host 草稿，不产生两份提交说明    | P0     |
| SCM-03 | 多选资源命令             | 支持提交、AI 审查、拆分、还原和锁定                     | P0     |
| SCM-04 | SVN Changelist           | AI 计划可转为原生 Changelist，并支持跨会话恢复          | P0     |
| SCM-05 | Changelist 调整          | 文件可在 Changelist 之间移动或移出                      | P1     |
| SCM-06 | 多仓库                   | 每个工作副本独立建模，禁止混合仓库提交为一个 revision   | P0     |
| SCM-07 | 嵌套工作副本与 externals | 标明归属仓库，跨仓库选择形成阻止项                      | P0     |

## 5. AI 能力与约束

| ID    | 能力                   | 必须满足的约束                                                   | 优先级 |

| AI-01 | 智能选择               | 只生成建议，不扩大右键范围                                       | P0     |
| AI-02 | 提交说明               | 结合差异、团队规则和历史；只写草稿，不自动提交                   | P0     |
| AI-03 | 变更审查               | 结论关联文件、行号、证据和置信度                                 | P0     |
| AI-04 | 智能拆分               | 可转为 Changelist，且支持人工调整和独立回滚                      | P0     |
| AI-05 | 冲突建议               | 生成候选，不直接执行 `svn resolve`                               | P0     |
| AI-06 | 影响分析               | 覆盖调用方、配置、文档和上线观察项                               | P1     |
| AI-07 | 测试建议               | 包含边界、回归和失败模式                                         | P1     |
| AI-08 | 敏感信息扫描           | 识别凭据、令牌、私钥和个人信息                                   | P0     |
| AI-09 | 生成物/大文件/调试代码 | 与 ignore、文件大小和本地规则结合                                | P0     |
| AI-10 | 团队记忆               | 显示来源、历史数量、缓存和清理入口                               | P1     |
| AI-11 | 任务代理               | 展示计划、命令、风险与可撤销性，写步骤逐次确认                   | P1     |
| AI-12 | 结果过期               | scope、文件或 revision 变化后阻止采用                            | P0     |
| AI-13 | 隐私与预算             | 外发前显示模型、数据类型、范围、预算和历史使用情况               | P0     |
| AI-14 | 本地降级               | AI 失败时保留规则扫描和人工流程                                  | P0     |
| AI-15 | 选择来源拆分           | 本地规则始终可用；模型建议可选；失败不覆盖当前选择；来源如实展示 | P0     |

## 6. 右键上下文

| ID     | 上下文         | 菜单与行为                                                 |
| ------ | -------------- | ---------------------------------------------------------- |
| CTX-01 | SVN 文件夹     | 提交、更新、历史和范围内 AI 操作                           |
| CTX-02 | 单个已修改文件 | Diff、历史、Blame、解释修改和 Revert                       |
| CTX-03 | 多文件选择     | 提交、Changelist、审查、锁定和还原                         |
| CTX-04 | 冲突文件       | 冲突处理提升到首层                                         |
| CTX-05 | 未版本化文件   | Add、Ignore 提升到首层                                     |
| CTX-06 | 仓库根         | Update、Commit、Cleanup、Branch/Tag 和仓库浏览             |
| CTX-07 | 非 SVN 路径    | Explorer 入口可见；Host 检测后拒绝无效写操作并提供环境检查 |
| CTX-08 | 混合仓库多选   | 阻止合并提交，并按仓库拆分操作                             |

VS Code Explorer 菜单不能为任意 URI 异步执行 `svn info` 后再决定单项显隐，也不能依赖扩展激活后才设置的 context key。精确状态菜单以原生 SCM 和 Svelte 文件树为验收表面；Explorer 模块入口稳定可见，执行时由 Host 复验工作副本、仓库和范围。不得使用未公开 API 绕过平台边界。

## 7. 产品完成条件

- 每个功能 ID 必须在实际代码、测试或当前说明中有可定位证据；产品表是规范目标，不是实现清单。没有代码/测试/实现映射证据时，必须表述为“目标”或“计划”，不得表述为已实现。
- P0 能力必须覆盖正常、加载、空、失败、取消、过期和恢复状态。
- 右键确定的操作范围只能被筛选、模板、Changelist 或 AI 缩小，不能扩大。
- 所有 SVN 写操作都必须先准确预览、再明确确认，并在执行前重新校验。
- AI 失败或未配置时，核心 SVN 与人工流程保持可用。
- 正式业务 UI 统一使用 Svelte 5；架构边界见 [`实现与代码映射.md`](./实现与代码映射.md)，交互规则见 [`设计与交互基线.md`](./设计与交互基线.md)，交付门禁见 [`测试与验收基线.md`](./测试与验收基线.md)。
