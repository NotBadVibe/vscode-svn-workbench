## 6. 右键上下文与动态菜单

| ID | 上下文 | 菜单变化 | 原型证据 |
| --- | --- | --- | --- |
| CTX-01 | SVN 文件夹 | 提交、更新、历史、AI 范围操作 | `原型总览.html` 默认菜单 |
| CTX-02 | 单个已修改文件 | Diff、历史、Blame、解释修改、Revert | 功能全景上下文矩阵 |
| CTX-03 | 多文件选择 | 提交、Changelist、审查、锁定、还原 | 同上 |
| CTX-04 | 冲突文件 | 冲突处理提升到首层 | 同上 |
| CTX-05 | 未版本化文件 | Add、Ignore 提升到首层 | 同上 |
| CTX-06 | 仓库根 | Update、Commit、Cleanup、Branch/Tag、仓库浏览 | 同上 |
| CTX-07 | 非 SVN 路径 | SCM/Svelte 不产生 SVN 状态操作；Explorer 保留模块入口，Host 检测后拒绝写操作并提供“检查环境” | 同上 |
| CTX-08 | 混合仓库多选 | 阻止提交并按仓库拆分操作 | 状态矩阵 `mixedRepo` |

说明：VS Code Explorer 的公开菜单贡献不能对当前任意 URI 异步执行 `svn info` 后再决定单项显隐，也不能让菜单依赖扩展激活后才设置的 context key，否则冷启动时入口永远不会出现。因此精确到 conflicted/versioned/unversioned 的动态菜单以原生 SCM 和 Svelte 文件树为验收表面；Explorer 的模块入口对文件资源稳定可见，执行时由 Host 复验工作副本、仓库和范围。不得使用未公开 API 绕过该平台边界。

## 7. 完成门槛

- 本矩阵中的每个 ID 都必须在原型或说明中有可定位证据。
- P0 状态必须具备正常、加载、失败、取消和恢复表达。
- 原型仅用于交互设计，不应被复制成新的单文件生产 Webview。
- 正式实现需把命令协议、状态机和视觉组件分别测试。
- 正式业务 UI 统一使用 Svelte 5；技术与发布门槛见 `Svelte统一UI开发改造与验收方案.md`。
