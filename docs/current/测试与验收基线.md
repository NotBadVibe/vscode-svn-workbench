# SVN Workbench 测试与验收基线

> 文档身份：`current-test-acceptance-baseline`
>
> 状态：CURRENT。
>
> 负责：测试层级、场景矩阵、人工验收、候选与发布门禁。
>
> 不负责：产品优先级见 [`产品与功能基线.md`](./产品与功能基线.md)；交互规则见 [`设计与交互基线.md`](./设计与交互基线.md)。实际结果以当前提交的命令、CI 或 accepted evidence 为准。

## 1. 当前事实基线

- 本地开发使用 `.nvmrc` 声明的 Node.js 26 与 npm 12；`package.json` 同步声明可接受的 Node、npm、VS Code 版本和仓库元数据。
- `package.json` 提供 ESLint、Prettier、TypeScript/Svelte 静态检查、依赖审计、覆盖率、Webview、性能、Extension Host、文档校验、VSIX 打包和干净安装验证脚本。
- CI 使用最小 `contents: read` 权限和固定 SHA 的 GitHub Actions；开发分支
  由 `pull_request` 验证，`push` 只覆盖 `main` 与 `v*` 标签，避免同一 PR
  提交重复运行三平台矩阵；CodeQL、Dependabot 与高危依赖审计持续覆盖
  供应链风险。
- 测试数量随代码变化，不作为版本身份；交付结论必须来自对应提交的实际运行和版本 manifest。
- 归档中的旧 PASS 数、VSIX 大小和 SHA256 只代表当时产物。

## 2. 验证层级

### L1 · 静态与编译

```bash
npm run check
npm run audit:dependencies
```

要求：

- ESLint、Prettier、TypeScript 和 Svelte 均无错误或未处理警告。
- `npm audit --audit-level=high` 无高危或严重依赖漏洞。
- Svelte、TypeScript 和 Vite 构建无错误。
- Svelte 组件无危险 `{@html}`、散落消息监听和外部不受控资源。
- Host 中无业务 HTML/CSS/JS 字符串，只允许静态 Webview Shell。
- 命令、菜单、配置和 activation event 能互相对应。

### L2 · 领域单元、组件与 Extension Host

```bash
npm run test:unit
npm run test:platform-contracts
npm run test:coverage
npm run test:extension
```

至少覆盖：

- OperationScope、父子范围合并和范围外路径拒绝；范围守卫
  （`src/scope/pathBoundaryGuard.ts`）的路径 resolve 必须与注入的
  `PathSemantics.platform` 一致（禁止宿主 node:path 先解析再比较），
  valid/out-of-scope 返回路径也按注入语义规范化；`scopeGuards.test.ts`
  覆盖 POSIX 与 win32 对称契约（文件、目录自身、子项、同前缀兄弟、
  父目录、`..cache`、盘符与大小写折叠），合成路径期望值不得使用宿主
  `path.resolve` 构造。
- 跨平台路径身份（`src/scope/pathIdentity.ts`）必须覆盖 Windows 盘符、混合
  分隔符、大小写、UNC、同前缀兄弟与 `..cache` 合法子目录；测试通过显式
  注入 `platform + cwd`，不得要求开发者在本机运行 Windows 才能发现问题。
- 双平台路径契约（v0.0.8，`tests/unit/dualPlatformPathContracts.test.ts`）：
  大小写保留与 identity 等价、盘符、UNC、斜杠、中文、同前缀兄弟目录、
  项目相对路径（展示保留大小写、identity 归一）与 SCM 同名标题/切片，全部
  显式注入 posix/win32 在任意平台执行；`tests/unit/pathIdentityBoundary.test.ts`
  静态契约保证协议展示字段为 `DisplayPath`、identity 键（`PathIdentityKey`）
  不得进入协议/展示边界、Webview 运行时不得产生或转换身份键。纯路径 API
  的 `PathSemantics`（platform + cwd）为编译期必填参数，领域代码不读
  process；真实路径夹具（Extension Host / 真实临时目录）显式构造与宿主
  一致的语义对象，合成路径夹具显式 posix/win32。
- 项目边界与活动项目解析（v0.0.7）：项目/工作副本组合 identity 与 Host
  文件 key（不得只使用 `projectRelativePath`）；活动项目解析固定顺序（命
  令 URI → 活动编辑器最具体 folder → 容器保存项目根 → 单根 → 多根选择器
  候选且最近项目突出但不自动进入）；保存项目根越界或失效时回退工作副本
  根；范围哈希纳入项目根使旧确认令牌失效；Diagnostics 归属分类覆盖独立
  工作副本根、上层工作副本、嵌套工作副本、external、非 SVN 与路径不存在。
- SCM 项目切片（v0.0.7）：每个显式 workspace folder 一个项目级 provider
  （同名补充父路径）；同一工作副本共享一次状态采集并按项目根切片；未加
  载兄弟目录不进入项目 provider；嵌套/额外工作副本保留独立 provider；单
  工作副本采集失败不影响其他工作副本刷新恢复。
- 项目切换草稿守卫（v0.0.7）：项目 A→B 加载前识别提交草稿、手动选择、
  AI 结果与各类待确认预览；三选一（保留/放弃/留在当前项目）；草稿按项
  目 + 模块隔离存储，切回一次性恢复且旧预览与确认 token 永不恢复。
- 团队规则项目层（v0.0.7）：项目根配置优先、工作副本根继承并显示来源；
  新建/保存默认写项目根且不改动工作副本根既有配置；迁移必须预览（源/目
  标/键清单/影响）并经确认令牌执行，执行前复验源哈希、目标存在性与项
  目边界；只迁移白名单键（commitConvention、commitSelection）。
- SVN executable、状态 XML、info、revision 和远端状态解析。
- 提交候选、生成物、筛选预设、提交说明、团队规则和提交选择规则（状态策略与仅属性变化决策、Glob 路径规则与遮蔽检测、用户/工作区/仓库合并、安全边界、运行时缓存失效及 v0.0.2 行为金样兼容）。
- 提交前远端检查、提交计划和成功后刷新。
- AI 选择、说明、拆分、团队规则和冲突建议的结构校验。
- Workbench 协议 action 字面量联合与 `webviewActions` 运行时清单一致；v2 action 必须包含 `sessionId + repositoryUuid + scopeHash`，Host 还须复验 `taskId`，新会话接管后拒绝旧会话消息与动作。
- Diff 窗口覆盖默认 `sameGroup`、可选 `beside`、非法配置回退、同目标复用和目标变化失效；原生对比覆盖不透明 BASE URI、范围复验和会话释放。
- 0.0.5 统一模块窗口：按模块惰性创建与单例复用、不同模块互不顶替、关闭后重建、跨模块路由（命令/右键/`open-module`/`open-diff`/`history/compare`）与非法 module/task/scope 拒绝、扩展停用统一释放；多窗口共享安全上下文按 repository identity 引用计数（最后一个窗口关闭才清除、合并同步不清除其他窗口凭据、显式清除认证广播失效事件），一控制器仅持有一个当前仓库引用（同仓库重开不泄漏、关闭/dispose 恰好释放一次、重复 release 安全），异步凭据刷新在写回前复验会话为当前会话。
- 拆分队列生命周期、草稿恢复、失败重试和批量预览。
- 真实 SVN 覆盖率桥接（`domainAcceptanceCoverage.test.ts`）：Extension Host 真实 SVN 子进程用例经 Vitest 桥接跑覆盖率；仅两个慢用例（guarded Windows Unicode-path commit、advanced repository operations）设 15s per-test 超时（Windows 负载 flake），其余保持默认 5s，不跳过 Windows、不减少断言。
- Windows 文件系统专项契约（`windowsPlatformContracts.test.ts`）：写入临时
  文件必须以写句柄执行 `write -> fsync -> close`，`EACCES` 不得被吞掉；
  真实 SVN 临时目录清理仅对 Windows 的 `EPERM | EBUSY | ENOTEMPTY` 在
  有限重试后延迟回收，非 Windows 或其他错误码继续失败。
- 快速双平台契约门禁 `npm run test:platform-contracts`（v0.0.8）：合成
  posix/win32 路径与平台契约用例在任意开发平台等价执行，Verify 工作流在
  Linux 上先于完整覆盖率运行使平台边界尽早失败；同一套用例不在 Windows
  Runner 重复执行（Windows 保留完整覆盖率与真实 SVN 验收作为最终确认）。
  本地 `npm run verify` 同样先跑该门禁；`npm run test:windows-contracts`
  保留为同集合别名。不得通过 `continue-on-error`、跳过 Windows 或
  全局放宽测试超时取得通过。
- 0.0.6 页内编辑保存后快照刷新回归：App 已有快照刷新保持模块挂载（`AppLifecycle.test.ts`）；DiffView 重建决策纯函数（`diffViewLifecycle.test.ts`：编辑态同键同容器保持、只读态内容变化重建、挂载键/容器身份切换重建、old/new/patch 逐字段比较无拼接碰撞）；DiffModule 保存结果按消息对象只消费一次、快照刷新不重建编辑器（`DiffModuleHarness.svelte` 原地更新 props 回归 harness）；连续保存 e2e（repeat-each≥15）携带轮换后 token/hash 全部通过。
- 更新风险、冲突、取消后刷新和下一步动作。
- 环境诊断和验收清单。

新增能力时，测试数量可以变化；不得为了维持历史数量而限制新增测试。

### L3 · Webview 交互

```bash
npm run test:webview
npm run test:performance
```

- Working Copy ↔ BASE 显示“在编辑器中对比”；修订比较不显示，二进制和截断状态禁用入口并解释原因。

- 正常、加载、空、失败、取消、恢复和过期状态可到达。
- 右键范围在所有模块持续可见。
- 720px 与常规桌面宽度无横向溢出和不可达操作。
- 真实视口测试不得通过覆盖 `overflow` 代替滚动验收；局部列表必须实际滚动到末项，覆盖 480/600px 小高度和 200% 缩放。
- 深链接、模块切换、Svelte Context Menu/Dialog、逐步批准和状态切换无控制台错误。
- 键盘焦点、可访问名称和 Escape 关闭行为可用。
- Light、Dark、High Contrast 以及视觉回归基线通过。
- 构建体积和首屏性能满足本文的性能预算与发布门禁。
- 中文术语、IME、局部滚动和内容可达性满足 [`设计与交互基线.md`](./设计与交互基线.md)。

### L4 · 真实 SVN 工作副本

使用隔离测试仓库验证：

- modified/add/delete/missing/conflicted/unversioned/ignored/external 状态。
- 中文、空格、特殊字符和长路径。
- 文件与文件夹范围提交。
- update、out-of-date、文本冲突、tree conflict 和 Cleanup。
- lock/unlock、属性、历史、Blame、Switch、Branch/Tag 和 Merge。
- 多工作副本、嵌套工作副本和 externals。

测试不能污染用户真实工作副本。

- 使用的 Node/npm 版本、依赖审计结果和静态检查结果。

- 干净 profile 安装结果。
- 人工 UI 验收结果和已知问题。

## 5. 人工验收主路径

- 候选环境：`npm run prepare:manual-test-env` 生成两个仓库/工作副本、多根
  工作区、externals、第一列文本状态 M 恰好 7 个的批量选择与真实刷新失效
  （stale.ts 本地 M + 远端删除，update 后 tree-conflict）等 fixture，并输出
  一页式 `README-manual-acceptance.md`（17 项真人步骤与通过/失败记录位）；
  生成后脚本自检 M 集合/externals URL 语义精确目标/stale 状态，不满足即抛错。清单纯
  逻辑契约见 `tests/unit/manualAcceptanceEnv.test.ts`（含安全根 exact
  match 与 svn status --xml 解析；Windows XML 反斜杠路径须规范为 `/`，
  POSIX 合法反斜杠文件名不得被改写）。人工执行结果必须逐项填写记录位，
  不得用模拟或 axe 代替。

1. 打开包含多个工作副本和 external 的 VS Code 工作区。
2. 在 Explorer、编辑器和 Svelte 文件树分别触发上下文菜单。
3. 分别以默认 `sameGroup` 和配置后的 `beside` 打开 Working Copy ↔ BASE 与修订比较，确认 Diff 不顶替主工作台模块、显式打开会激活目标标签、同目标重复打开不破坏阅读位置。
4. 从 Working Copy ↔ BASE 执行“在编辑器中对比”，确认原生 Diff 左侧为只读 BASE、右侧为范围内工作副本；再验证修订比较、二进制、超过 5 MB、无 BASE、无文本差异、目标移动/删除、取消和旧会话均不会错误打开原生 Diff。
5. 查看历史和冲突是否直接进入对应 Svelte 模块。
6. 在 Svelte Changes 建立 Changelist，使用共享提交草稿并完成提交前检查。
7. 模拟远端领先、冲突、认证失败、证书异常、工作副本锁和取消操作。
8. 关闭 AI 后重复基础流程。
9. 启用 AI，验证变更解读的证据往返、按改动意图拆分、冲突意图解释与过期阻止。
10. 检查 Output Channel 不包含密码、token、完整认证参数或不必要的文件内容。

## 6. 里程碑记录规则

- 日常测试结果进入 CI 或任务记录，不新增 `xxx-pass-results.md`。
- 只有版本候选、正式发布或重大架构迁移才新增不可变交付记录。
- 失败应记录原因、影响范围和修复链接，而不仅是 PASS 数量。
- 发布记录固定进入 `releases/vX.Y.Z/`，日期只作为 manifest 元数据或证据运行编号。
- 普通运行写入 `.validation/evidence/vX.Y.Z/<运行编号>`；发布运行使用 `npm run evidence:release`，不得覆盖已有目录。
- `released` 目录不可修改；如需更正，创建新版本或在历史说明中显式追加勘误。
- 已固定的发布证据若发现元数据笔误，必须在当前版本变更映射中说明勘误范围、验证方式和“证据内容未改动”的结论。
