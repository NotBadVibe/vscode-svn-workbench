# SVN Workbench 测试与交付基线

> 状态：CURRENT
> 原则：文档描述测试结构和门槛；实际结果以当前命令或 CI 产物为准。

## 1. 当前事实基线

- 本地开发使用 `.nvmrc` 声明的 Node.js 22 与 npm 10；`package.json` 同步声明可接受的 Node、npm、VS Code 版本和仓库元数据。
- `package.json` 提供 ESLint、Prettier、TypeScript/Svelte 静态检查、依赖审计、覆盖率、Webview、性能、Extension Host、文档校验、VSIX 打包和干净安装验证脚本。
- CI 使用最小 `contents: read` 权限和固定 SHA 的 GitHub Actions；CodeQL、Dependabot 与高危依赖审计持续覆盖供应链风险。
- 测试数量随代码变化，不作为版本身份；交付结论必须来自对应提交的实际运行和版本 manifest。
- 归档中的旧 PASS 数、VSIX 大小和 SHA256 只代表当时产物。

## 2. 验证层级

### L1 · 静态与编译

```bash
npm run check
npm run audit:dependencies
```

要求：

- ESLint、Prettier、TypeScript 和 Svelte 均无错误或未处理警告。
- `npm audit --audit-level=high` 无高危或严重依赖漏洞。
- Svelte、TypeScript 和 Vite 构建无错误。
- Svelte 组件无危险 `{@html}`、散落消息监听和外部不受控资源。
- Host 中无业务 HTML/CSS/JS 字符串，只允许静态 Webview Shell。
- 命令、菜单、配置和 activation event 能互相对应。

### L2 · 领域单元与 Extension Host

```bash
npm run test:extension
```

至少覆盖：

- OperationScope、父子范围合并和范围外路径拒绝。
- SVN executable、状态 XML、info、revision 和远端状态解析。
- 提交候选、生成物、筛选预设、提交说明和团队规则。
- 提交前远端检查、提交计划和成功后刷新。
- AI 选择、说明、拆分、团队规则和冲突建议的结构校验。
- 拆分队列生命周期、草稿恢复、失败重试和批量预览。
- 更新风险、冲突、取消后刷新和下一步动作。
- 环境诊断和验收清单。

新增能力时，测试数量可以变化；不得为了维持历史数量而限制新增测试。

### L3 · 原型与 Webview 交互

- 正常、加载、空、失败、取消、恢复和过期状态可到达。
- 右键范围在所有模块持续可见。
- 720px 与常规桌面宽度无横向溢出和不可达操作。
- 真实视口测试不得通过覆盖 `overflow` 代替滚动验收；局部列表必须实际滚动到末项，覆盖 480/600px 小高度和 200% 缩放。
- 深链接、模块切换、Svelte Context Menu/Dialog、逐步批准和状态切换无控制台错误。
- 键盘焦点、可访问名称和 Escape 关闭行为可用。
- Light、Dark、High Contrast 以及视觉回归基线通过。
- 构建体积和首屏性能满足本文的性能预算与发布门禁。
- 中文术语、IME、局部滚动和内容可达性满足 [`设计与交互基线.md`](./设计与交互基线.md)。

### L4 · 真实 SVN 工作副本

使用隔离测试仓库验证：

- modified/add/delete/missing/conflicted/unversioned/ignored/external 状态。
- 中文、空格、特殊字符和长路径。
- 文件与文件夹范围提交。
- update、out-of-date、文本冲突、tree conflict 和 Cleanup。
- lock/unlock、属性、历史、Blame、Switch、Branch/Tag 和 Merge。
- 多工作副本、嵌套工作副本和 externals。

测试不能污染用户真实工作副本。

### L5 · VSIX 与干净安装

```bash
npm run package:vsix
npm run validate:vsix-install
```

每次候选发布记录：

- 版本号、构建时间和提交标识。
- VS Code 与操作系统版本。
- VSIX 文件名、大小、SHA256 和文件清单。
- 使用的 Node/npm 版本、依赖审计结果和静态检查结果。
- Extension Host 测试结果。
- 干净 profile 安装结果。
- 人工 UI 验收结果和已知问题。

不得从历史文档复制旧指纹作为新产物依据。

## 3. 当前新增能力必测契约

| 领域         | 最低验收                                                                                                  |
| ------------ | --------------------------------------------------------------------------------------------------------- |
| 动态右键菜单 | Explorer 冷启动入口可见；SCM/Svelte 按冲突、未版本化、多选和仓库根显示正确命令；非 SVN 写操作被 Host 拒绝 |
| 多仓库       | 每个工作副本独立 SCM；混合仓库提交被阻止                                                                  |
| Changelist   | 创建、移动、移出、恢复、过期路径处理                                                                      |
| AI 审查      | path/line/evidence/confidence 校验；范围外结果拒绝                                                        |
| AI 任务代理  | 每个写步骤独立确认；scope/revision 变化阻止继续                                                           |
| 认证与证书   | 密码不落日志；证书指纹与信任范围准确                                                                      |
| 长任务       | 进度、取消、重新采集状态和安全重试                                                                        |
| 破坏性操作   | 精确清单、恢复方式、命令预览和二次确认                                                                    |
| AI 降级      | 未配置、超时或结构错误时核心 SVN 功能可用                                                                 |

## 4. 人工验收主路径

1. 打开包含多个工作副本和 external 的 VS Code 工作区。
2. 在 Explorer、编辑器和 Svelte 文件树分别触发上下文菜单。
3. 查看修改、历史和冲突是否直接进入对应 Svelte 模块。
4. 在 Svelte Changes 建立 Changelist，使用共享提交草稿并完成提交前检查。
5. 模拟远端领先、冲突、认证失败、证书异常、工作副本锁和取消操作。
6. 关闭 AI 后重复基础流程。
7. 启用 AI，验证审查证据、拆分建议、过期阻止和任务代理逐步确认。
8. 检查 Output Channel 不包含密码、token、完整认证参数或不必要的文件内容。

## 5. 里程碑记录规则

- 日常测试结果进入 CI 或任务记录，不新增 `xxx-pass-results.md`。
- 只有版本候选、正式发布或重大架构迁移才新增不可变交付记录。
- 失败应记录原因、影响范围和修复链接，而不仅是 PASS 数量。
- 发布记录固定进入 `releases/vX.Y.Z/`，日期只作为 manifest 元数据或证据运行编号。
- 普通运行写入 `.validation/evidence/vX.Y.Z/<运行编号>`；发布运行使用 `npm run evidence:release`，不得覆盖已有目录。
- `released` 目录不可修改；如需更正，创建新版本或在历史说明中显式追加勘误。
- 已固定的发布证据若发现元数据笔误，必须在当前版本变更映射中说明勘误范围、验证方式和“证据内容未改动”的结论。
