## 2. 不可破坏的领域契约

### 2.1 操作范围

所有命令先解析统一上下文：

```ts
interface ResolvedCommandContext {
  repositoryRoot: string;
  repositoryUuid: string;
  operationScope: OperationScope;
  selectedFiles: string[];
  statusSnapshot: SvnStatusSnapshot;
  capabilities: CommandCapabilities;
}
```

必须遵守：

- 文件入口只允许影响该文件。
- 文件夹入口只允许影响该目录及其子目录。
- 多选范围是所选路径的去重并集，父目录已选时合并其子路径。
- 筛选、搜索、模板、Changelist 和 AI 只能缩小范围。
- 嵌套工作副本与 `svn:externals` 默认形成独立仓库边界。
- 混合仓库选择不能提交为一个 revision，必须按仓库拆分。
- 写操作执行前再次校验绝对路径、仓库 UUID 和范围哈希。

### 2.2 状态模型

内部状态至少区分：

- `modified`
- `added`
- `deleted`
- `missing`
- `replaced`
- `conflicted`
- `unversioned`
- `ignored`
- `external`
- `obstructed`
- `lockedBySelf`
- `lockedByOther`
- `outOfDate`

文本状态、属性状态、远端状态、锁状态和仓库归属应分别保存，不能压成一个显示字符。UI 可以按优先级显示装饰，但领域层不能丢失原始维度。

提交选择决策以 `(status, propStatus)` 二元组为输入：仅 SVN 属性变化（`status=normal`、`propStatus=modified`）独立于普通 `normal` 判断，自 v0.0.3 起按 `propertyModified` 状态策略默认推荐提交，不再作为普通 `normal` 排除（`src/commit/commitSelectionRuleEvaluator.ts`；金样期望已随该有意行为修正更新）。`conflicted`、`obstructed`、`incomplete` 出现在任一维度（文本状态或属性状态）即进入不可覆盖的阻止结果；提交计划构建器（`src/commit/commitPlanBuilder.ts`）按同一二元组判断可提交性，仅属性变化只进入 `commitPaths`。

### 2.3 多仓库与 Changelist

- 每个工作副本创建独立 repository model。
- Svelte Changes 按冲突、Changelist、修改、新增、删除、缺失和未版本化分组。
- Changes 和智能提交模块共享同一份 Host 草稿来源。
- AI 拆分结果只能生成 Changelist 建议，用户可以移动或移出文件。
- Changelist 草稿跨会话恢复时必须重新采集状态并检查过期路径。

## 3. SVN 命令契约

### 3.1 通用规则

- 所有命令通过一个 `SvnCommandRunner` 执行，禁止 UI 层直接启动进程。
- 优先解析 `--xml`，不要依赖本地化终端文案。
- 参数使用数组传递，不拼接 shell 命令字符串。
- 命令记录需要脱敏密码、token、认证缓存路径和用户隐私数据。
- 长任务必须支持阶段、耗时、输出入口和取消信号。
- 取消、失败或工作副本状态变化后，必须重新执行状态采集才能重试。

### 3.2 主要能力与命令

| 能力              | 推荐命令/机制                                                    | 关键约束                                                                                                                       |
| ----------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 本地状态          | `svn status --xml`                                               | 限定工作副本和操作范围                                                                                                         |
| 远端检查          | `svn status --show-updates --xml`                                | 失败不能伪装成“无更新”                                                                                                         |
| 信息与归属        | `svn info --xml`                                                 | 读取 root、URL、UUID、revision                                                                                                 |
| 更新              | `svn update <paths>`                                             | 执行前展示范围和冲突风险                                                                                                       |
| 提交              | `svn commit <paths> -F <file>`                                   | 消息使用临时文件；执行最终远端检查                                                                                             |
| Diff              | `svn diff`、`svn cat -r BASE`、Svelte 只读 Diff 与 `vscode.diff` | Webview 只读审阅；原生对比左侧为 Host 管理的只读 BASE 虚拟文档，右侧为范围内工作副本；二进制、截断、无 BASE 和过期目标安全拒绝 |

| Merge             | `svn merge`                                                      | 先预检，冲突转入 Svelte 冲突与合并模块                                                                                         |

## 4. UI 表面契约

| 任务                                     | 首选表面                                       |
| ---------------------------------------- | ---------------------------------------------- |
| 持续查看状态、分组、Changelist、提交草稿 | Svelte Changes 模块                            |
| 文件与修订差异                           | Svelte Diff 模块                               |
| 文本冲突编辑                             | Svelte 冲突与合并模块                          |
| 简单选择与轻量确认                       | Svelte Dialog / Command / Context Menu         |
| 密码输入                                 | Svelte 安全输入；Secret 只传给 Host，不回显    |
| 长任务                                   | Svelte Progress/Task 状态；Host 管理取消和日志 |
| 配置项                                   | Svelte Settings 模块                           |
| 智能提交、AI 审查、拆分计划、冲突理由    | 对应 Svelte feature module                     |
| 仓库浏览                                 | Svelte Repository 模块                         |

所有可见业务 UI 统一使用 Svelte 5。自 v0.0.5 起，每个功能模块拥有独立 Webview 窗口，一个 Workbench Shell 根据命令直接进入目标模块；不得恢复一个同时挂载所有能力和全部状态的巨型页面，窗口内不再提供模块总览列表（Rail 已移除）。模块内任务导航、空态/错误/设置页的关联入口保留。

自 v0.0.5 起，模块窗口由统一窗口管理器（`src/extension/workbench/workbenchWindowManager.ts`）按 `WorkbenchModuleId` 惰性创建、单例复用的 `WorkbenchController` 承载；同模块重复打开复用窗口并加载新目标，不同模块互不顶替，关闭后按需重建，扩展停用时统一释放。跨模块打开请求（命令/右键入口、Webview 的 `open-module`、`open-diff`、`history/compare`）由控制器回传窗口管理器，经 `src/extension/workbench/workbenchRouting.ts` 纯路由逻辑路由到目标模块窗口，源窗口保持原快照与操作范围。`svnWorkbench.diff.openMode` 支持 `sameGroup | beside`：默认 `sameGroup` 在当前编辑组激活目标标签，`beside` 在旁侧编辑组激活；缺失或非法配置安全回退到 `sameGroup`。同一 Diff 目标重复打开只 reveal，不重新初始化；目标文件、范围或修订变化时建立新会话。控制器收到非本模块会话请求且未接线时明确拒绝（`src/extension/workbench/WorkbenchController.ts`、`src/extension/workbench/workbenchRouting.ts`）。

Working Copy ↔ BASE 页面可发送 `diff/open-in-editor`。Host 重新校验当前范围，读取工作副本和 `svn cat -r BASE`，通过 `NativeDiffContentProvider` 以不透明随机 URI 提供只读 BASE，并调用 `vscode.diff`；右侧使用实际工作副本 URI。BASE 内容与 URI 在会话替换、面板关闭或控制器释放时失效。修订比较、二进制、超过 5 MB、无文本差异、无 BASE 或过期目标不打开原生 Diff，并返回中文原因与恢复动作。

### 4.1 Workbench 协议与会话隔离

`WORKBENCH_PROTOCOL_VERSION` 当前为 `2`。Host 为每次安全上下文或 Diff 目标变化生成新的 `sessionId`；所有 `workbench/action` 必须携带并通过 `sessionId + repositoryUuid + scopeHash + taskId` 校验，任一不一致均作为过期上下文拒绝。Webview 在新的 `app/initialize` 接管后忽略旧 `sessionId` 的延迟快照、进度和结果。`diff/open-in-editor` 同时登记在 `WebviewAction` 字面量联合与 `webviewActions` 运行时清单中；协议 action 变化必须同步检查 Host、Webview、Mock、消息守卫和测试。

多窗口共享 SVN 安全上下文（`src/security/svnSecurityContextRegistry.ts`）：按 repository identity 引用计数管理认证与证书信任；窗口会话创建时 `acquire`、替换或关闭时 `release`，仅最后一个引用消失才清除共享上下文；`sync` 采用合并语义避免空会话覆盖其他窗口凭据；显式清除认证时向相关窗口广播失效事件（`WorkbenchController.handleSecurityInvalidated` 重新读取 SecretStorage 并刷新设置页快照，不重载其他模块以保留未提交输入）。`moduleId + taskId + operationScope` 在每个窗口独立保存，跨模块路由只保持（不扩大）源窗口范围。

## 5. 安全与恢复契约

### 5.1 认证与证书

- 密码不得写入 settings、工作区配置或日志。
- 可使用 VS Code SecretStorage 保存扩展管理的 secret，但要兼容 SVN 自身认证缓存。
- 证书确认必须显示主机、SHA-256 指纹、错误原因和有效期。
- “仅本次信任”与“永久信任”必须明确区分。
- 认证失败、证书失败、代理失败、DNS 失败和离线状态不能合并成一个错误。

### 5.2 破坏性操作

Revert、Delete、Switch、Relocate、Merge 和从历史恢复文件必须展示：

- 精确路径清单。
- 本地未保存或未提交内容。
- 是否可以撤销以及如何恢复。
- 将执行的 SVN 命令或动作。
- 明确的二次确认。

必要时先提供恢复 Patch。不要把“本地搁置”描述为 SVN 标准 shelf；它是插件管理的可恢复 Patch。

### 5.3 工作副本恢复

- 识别锁定、未完成 update/merge、tree conflict 和 obstructed 状态。
- Cleanup 页面展示安全默认参数，不默认删除 ignored/unversioned 文件。
- 恢复后刷新 SCM、候选文件、revision、冲突和 AI 结果有效性。

## 6. AI 契约

### 6.1 处理顺序

```text
OperationScope
  -> SVN 状态与仓库边界
  -> 本地确定性规则
  -> 敏感信息 / 生成物 / 大文件 / 调试代码扫描
  -> 裁剪后的 AI 上下文
  -> 结构化结果校验
  -> 用户确认
```

### 6.2 结果要求

- 文件级判断包含 `path`、分类、理由和置信度。
- 审查结论包含文件、行号、证据、严重度和置信度。
- 拆分建议包含文件集合、提交意图、建议说明和依赖关系。
- 冲突建议包含两侧意图、候选结果、风险和验证步骤。
- 模型返回路径必须经过仓库与范围校验；虚构路径和范围外路径直接丢弃。
- 提交文件选择请求只发送当前范围候选的相对路径、SVN 状态、文件类型和本地规则结论（`localDecision`、`safetyLocked`），不发送本地绝对路径（`src/ai/commitSelectionAi.ts`）。
- AI 选择建议必须经本地边界校验：本地阻止项、强制排除项和用户明确配置的排除结果不得被 AI 改为推荐（`src/ai/aiResultValidator.ts` 的 `enforceAiSelectionLocalBoundary`）。
- AI 不得直接执行 commit、update、resolve、revert、delete、switch 或 merge。

### 6.3 上下文与过期

每个 AI 结果至少绑定：

- repository UUID
- operation scope hash
- 文件内容或 diff hash
- working copy revision
- 生成时间与模型

任一关键值变化后结果标记为过期，只能查看或重新生成，不能直接采用。

### 6.4 隐私与降级

- 外发前显示文件数、字符预算、模型和数据类型。
- 默认不发送范围外文件、完整仓库历史、认证信息和本地绝对路径。
- 团队记忆优先保存本地摘要，并提供查看来源、清除缓存和关闭入口。
- AI 未配置或调用失败时，保留范围保护、敏感规则、生成物检测和全部手动 SVN 流程。
- 提交文件选择场景中，AI 调用失败时保留用户当前选择，展示失败原因与“应用本地规则”恢复动作，不静默替换为另一来源的结果。

## 7. 受控 AI 任务代理

任务代理的执行单元不是“自由操作”，而是带审批的领域步骤：

```ts
interface AgentStep {
  id: string;
  title: string;
  repositoryUuid: string;
  scopeHash: string;
  preview: string;
  risk: "read" | "write" | "destructive" | "remoteRevision";
  undo: string;
  privacy: string;
  requiresApproval: boolean;
}
```

- 代理先生成计划，再逐步执行。
- 每个写步骤执行前重新校验仓库、scope 和工作副本状态。
- 提交前必须再次显示最终文件、说明、远端状态和风险。
- 停止代理不静默回滚已经完成的 SVN 步骤，而是说明当前状态和恢复路径。

### 8.1 跨平台路径与测试文件系统边界

- 绝对路径的 Map/Set 键、相等判断和父子范围判断统一使用
  `src/scope/pathIdentity.ts`。所有纯路径 API 要求显式 `PathSemantics`
  （`platform + cwd` 均必填，无默认回退）：领域函数不得自行读取
  `process.platform/process.cwd()`，生产 Host 从唯一边界
  `src/scope/nativePathSemantics.ts` 注入；合成 posix/win32 路径的测试在
  任意开发平台（包括 Windows）得到确定语义，平台问题不会拖到 CI 才暴露。
- `normalizePathIdentity` 只生成内部身份键；界面展示和真实文件操作必须继续
  使用原始绝对路径，不得把 Windows 小写身份键显示给用户。
- 身份/展示类型边界（v0.0.8）：`src/scope/pathBrands.ts`（零依赖，品牌归属
  身份领域；协议层经 type-only import 引用，scope 不反向依赖 protocol）
  定义互不兼容的 `PathIdentityKey` 与 `DisplayPath` 品牌；
  `normalizePathIdentity`、`workingCopyId`、`projectId`、`scmProjectKey`、
  `createScopedFileKey` 只返回 `PathIdentityKey`（用于 Map/Set、比较、排序、
  缓存键与范围判断）。协议展示字段（`WorkbenchScopeView` 的
  `projectWorkingCopyRelativePath` 与 `roots[].relativePath`、
  `WorkbenchFileView.projectRelativePath`、`file/path-detail-result` 的
  `projectRelativePath/workingCopyRelativePath/repositoryRelativePath/absolutePath`）
  声明为 `DisplayPath`；Host 构建处（`workbenchPresentation.toScopeView`、
  `workbenchFileOperations.withProjectFileView`、
  `WorkbenchController.respondFilePathDetail`）经唯一显式转换
  `toDisplayPath` 进入协议。`toDisplayPath` 参数类型 `DisplayPathSource`
  在类型层面拒绝 `PathIdentityKey`（直接传入 identity 键编译失败，由
  `npm run check` 的 tsc 与 svelte-check 强制，不是源码扫描提醒）。
- 编译期品牌契约（`src/scope/pathBrands.ts`）：`Assert<T extends true>` +
  `PathIdentityNotDisplayPath`/`DisplayPathNotPathIdentity`（品牌互斥，
  任一方向可互相赋值即编译失败）与 `DisplayPathRejectsIdentityKey`
  （`DisplayPathSource<PathIdentityKey>` 必须折叠为 never）；品牌或参数
  约束一旦退化，`npm run check` 必失败。
- 静态边界契约 `tests/unit/pathIdentityBoundary.test.ts` 扫描源码：协议展示
  字段必须是 `DisplayPath`、Webview 运行时目录不得导入 pathIdentity /
  pathBrands / nativePathSemantics（identity 键无法在 Webview 侧产生或转换）、
  领域纯函数无默认语义回退且不读取 process、唯一 native 边界集中读取。
- `isSameOrDescendantPath` 使用平台对应的 `path.relative` 判断边界，禁止用
  字符串前缀判断目录归属；`/repo/a` 不得覆盖 `/repo/ab`，名为 `..cache`
  的合法子目录不得被误拒绝。
- 页内编辑临时文件统一经 `writeAndSyncTempFile` 使用写句柄执行
  `write -> fsync -> close`；可注入的 open 契约用于在非 Windows 环境锁定
  `FlushFileBuffers` 需要写访问的行为。
- Extension Host/真实 SVN 测试目录统一经
  `src/test/suite/testTempDirectory.ts` 清理。仅 Windows 的
  `EPERM | EBUSY | ENOTEMPTY` 在有限重试后可延迟给临时 Runner 回收；其他
  平台或错误码必须继续失败。
- 主要回归位于 `tests/unit/windowsPlatformContracts.test.ts`、
  `tests/unit/dualPlatformPathContracts.test.ts`（v0.0.8：大小写保留与
  identity 等价、盘符、UNC、斜杠、中文、同前缀兄弟目录、项目相对路径、
  SCM 同名标题与切片，全部显式注入 posix/win32）、
  `tests/unit/pathIdentityBoundary.test.ts`、
  `tests/unit/extensionHostTempCleanup.test.ts` 与
  `tests/unit/githubWorkflow.test.ts`。
- 快速双平台契约门禁 `npm run test:platform-contracts`（v0.0.8）：上述可注入
  用例组成一套合成契约，任意开发平台均可运行；已纳入本地 `npm run verify`

### 8.4 选择内核（v0.0.8 批次 1，纯逻辑）

- 无 DOM/VS Code/Svelte 依赖的 TypeScript 领域模块 `src/selection/`，
  契约见 [`v0.0.8`](../releases/v0.0.8/) §4/§5 与 UX08-SEL-01/02/03/04/06、
  UX08-SORT-02；不修改 Svelte、WorkbenchController 与协议（集成在后续批次）。
- 选择集合与三态 `src/selection/selectionCore.ts`：`SelectionKey` 复用批次 0
  的 `PathIdentityKey` 品牌（普通 string/DisplayPath 编译期不可直接赋值，
  编译期 Assert 强制与 DisplayPath 互不兼容）；模块不把 DisplayPath 当
  identity、不读取 process。actionability 是针对当前动作的调用方权威输入
  （`SelectableItem.actionable` 必填），模块只做 fail-closed 运算：可操作项
  = actionable=true 且非 blocked（blocked 是二次 fail-closed；Commit 调用方
  对 excluded 传 actionable=false，允许的非提交动作可传 true；needsReview
  可由调用方明确 actionable=true 且保持标记）。三态 none/partial/all 只基于
  当前筛选可操作项；表头 toggle 只影响传入快照的可操作 key（隐藏选择保留、
  新出现项不因过去全选自动加入）；blocked 永不被批量加入；
  `mergeRecommendedSelection` 只加不减（推荐且可操作、非 excluded/needsReview
  项加入，不覆盖用户手动保留）；隐藏选择计数/集合、clear hidden、
  only-selected 视图过滤。
- 自然稳定排序 `src/selection/selectionSort.ts`：路径/文件名/归属大小写
  不敏感 numeric natural compare（file2 < file10，逐字符扫描、前导零不改变
  数值），相等以原始输入位置稳定兜底；状态与选择建议经显式产品优先级表
  （`RECOMMENDATION_ORDER` = recommended < needsReview < excluded < blocked），
  未知值恒排末尾、降序只反转已定义值；`toDefaultOrder` 恢复调用方原始顺序。
- 刷新合法交集 `src/selection/selectionRefresh.ts`：以调用方复合稳定 key
  保留 selected ∩ 刷新后保留项；消失/越界/blocked 由调用方以 retained +
  removalReason 判定（模块不猜测、不放宽安全边界）；同一 identity 在刷新
  快照中重复出现是数据完整性异常，fail-closed 取消选择并返回确定原因
  （“刷新快照存在重复身份，已安全取消选择”），与顺序/retained 组合无关；
  新文件绝不自动加入；返回新集合（selected + removed 明细，无冗余字段），
  旧集合不变。
- 主要回归位于 `tests/unit/selectionCore.test.ts`、
  `tests/unit/selectionSort.test.ts`、`tests/unit/selectionRefresh.test.ts`
  （含 5,000 项数据集、输入不变异、稳定性与未知值契约）。
- `src/selection/**/*.ts` 已纳入 `vitest.config.mts` 的 coverage include，
  受全局 80% 阈值约束（当前 statements/branches/functions/lines 均 100%）。

## 9. 维护要求

1. 新增功能时同步补充“源码、测试、引入版本、证据”五项。
2. 未发布工作只链接到版本草稿，不得复用上一发布版本的通过结论。
3. 源码路径迁移后必须在同一改动中更新本表并执行 `npm run docs:verify`。
4. Workbench 新增行为应优先放入对应领域模块；Controller 只保留面板生命周期、协议路由和跨领域编排。
5. 新增绝对路径比较不得自行复制 `path.resolve + process.platform`；新增真实
   SVN fixture 不得直接清理临时目录；新增耐久写入必须提供可注入失败契约。
